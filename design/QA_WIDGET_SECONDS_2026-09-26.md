# 위젯 초 표시 구현·검증

2026-09-26. 사용자 ‘해당 구현안을 목표로 설정하고 구현, 검증’ 승인에 따른 결과. 기본 A와 선택형 시간 보드, 일반4×2·기간 요약4×1을 유지한다. 이 기록은 [승인 적용안](WIDGET_SECONDS_STRATEGY_2026-09-26.md)의 구현 전 설명보다 우선한다.

## 제공 범위

| 대상 | 이번 결과 |
| --- | --- |
| 오늘 | 지원 호스트에서 선택형 초 숫자·눈금. 앱과 같은 현지 하루 시각 계산, 자정 순환 |
| 일반/캘린더 시간 일정 | 유효한 시작·종료가 있는 7일 이내 구간, 시작 대기→진행→0초 종료 |
| 반복 시간·자동 다음 일정 | 현재 회차의 초 표시. 시작/종료 및 다른 후보 경계에서 데이터 재선택. 지연 중에는 이전 문서가0과 종료 상태를 유지 |
| 집중 | 제외. 기존 단조 시계/일시정지/재부팅 의미를 벽시계로 바꾸지 않음 |
| 날짜·달·년·주·분기·기간 요약4×1 | 기존 일수 중심/기준 시각 표시 유지 |
| Android 17, Pixel 런처, 문서 버전9 | 실제 설치 위젯 검증 |
| Android 16(API36), 문서 버전8 | 초 옵션을 숨기고 저장된 초 선택도 정적으로 대체하는 설정·프레임워크 검증 |
| 다른 제조사/하위 OS | 전체 검증 아님. API35 미만 또는 문서 버전9 미만은 정적 경로 |

기존 위젯은 기본 꺼짐이다. 각 위젯 설정의 ‘초 단위 표시 · 실험 기능’으로 켠다. 지원하지 않는 항목/환경에는 동작하지 않는 스위치를 표시하지 않는다. 사용자 DB·출시 버전·provider 식별자·기존 형식 키는 변경하지 않았고 `${id}seconds` 키만 추가했다. 집중·정확 알람·알림 권한을 새로 요구하지 않는다.

## 구현과 제한

- `WidgetSecondsPlan`: 원본의 명시적인 시작/종료를 사용한다. percent/번역 문자열로 상태를 추측하지 않는다. 1초 미만 끝점은 다음 틱으로 올려 조기 종료를 피하고, 종료 숫자는0 이상으로 제한한다. 정수 epoch 범위(2038 이전)와 시작·종료가 현재에서7일 이내인 표시 범위만 허용한다. 범위를 벗어나면 기존 표시로 복구한다.
- `WidgetSecondsRenderer`: 위젯 시스템의 정수 epoch 차이를 먼저 계산한 뒤 짧은 길이를 실수로 변환한다. 원시 epoch를 float로 바꾸지 않는다. 현지 초 시계에만 갱신 의존성을 등록한다. 연속 애니메이션 시계를 사용하지 않는다. 숫자와 눈금은 같은 시간값이며 글로우 비트맵은 게시 때만 생성한다.
- `WidgetPalette`, `WidgetTextMeasure`, 위젯 치수, `TimeRulerTokens`, `drawTimeRulerGlow`, `TimeLeftSwitchRow`를 재사용한다. 큰 글자/긴 제목이 맞지 않으면 확대 안내를 표시한다. 미리보기는 같은 렌더러의 고정 시각이다. 숫자 열의 최대 폭을 확보하고 시간 형식을 구간 안에서 유지한다.
- DrawInstructions와 XML을 같은 응답 트리에 섞지 않는다. 크기별 전체 지도는 같은 계획으로 생성한다. 생성/게시에서 앱에 반환된 오류는 모든 크기를 정적 XML로 다시 만든다. 호스트 내부 오류가 항상 앱으로 돌아오는 것은 아니므로 미검증 런처에 무조건적인 성공을 보장하지 않는다.
- 본문과 새로고침을 별도 의미가 있는 레이아웃 구성요소로 제공한다. 현재 시간 설명을 읽을 수 있고 새로고침의48dp 영역과 겹치지 않는다. 매초 접근성 알림은 발송하지 않는다. 단순 ClickArea만으로는 프레임워크 접근성 트리에 현재 값이 나오지 않아 이 구조로 보완했다.
- `WidgetBoundarySchedule`은 여러 위젯 중 가장 빠른 다음 경계 한 개를 비기상 RTC의 **비정확 알람**으로 예약한다. 매초 앱 IPC나 정확 알람 권한을 요구하지 않는다. 날짜 후보는 다음 현지 자정, 시간 후보는 시작/종료를 고려한다. 다음 선택/회차가 즉시 반영되는 것을 보장하지 않으며 수동 새로고침이 남는다.
- 지연·중복 요청에는 오래된 항목 payload를 싣지 않는다. 현재 설정/저장소를 다시 읽고 예약을 갱신한다. 제거된 위젯은 예약에서 제외한다. Focus/Boot/새 경계 Receiver는 실제 위젯 게시까지 `goAsync()`를 유지한다.
- 오래된 시간 문서에서 종료 후 본문을 누르면 유효 기한을 다시 검사해 갱신하고 홈으로 복귀한다. 이전 제목 아래 다음 회차 상세를 열지 않는다. 위젯의0초 표시는 DB 완료/알림 발송을 대신하지 않는다.

## 라이브러리 판단

생성 전용 `androidx.compose.remote:remote-creation-android:1.0.0-alpha20`을 고정했다. 앱의 Compose BOM은 올리지 않고 내장 플레이어도 추가하지 않는다. 실제 표시는 시스템 플레이어다.

현재 필요한 생성/연산 API 일부가 AndroidX 내부용으로 표시돼 있어 **어댑터 한 곳에서 RestrictedApi 예외를 사용**한다. 플랫폼의 DrawInstructions는 공개 API다. Android 숨겨진 API, 리플렉션, 자체 프로토콜 인코딩은 사용하지 않는다. 공개 생성 API만을 선호했던 초기안에 대한 비용을 구현 전에 적용안에 기록했다. 실험 선택형 기능이며 라이브러리를 올릴 때 프로파일·시간·접근성·갱신 빈도를 재검증해야 한다.

API 버전만으로 활성화하지 않고 실제 문서 버전을 검사한다. Android16 시험 환경은8, Android17은9였다. 이번 구현은9 이상만 허용하며8에서도 전체 연산이 안전하다고 가정하지 않는다. 집중에 필요한 부팅 후 경과 시계는 확인한 프로파일에서 확보하지 못했다. `ContinuousSec`는 매시간 순환하므로 대체 시계로 쓰지 않았다.

## 남은 검수와 출시 경계

Samsung 등 실제 제조사 런처, Android15/하위 OS 설치 경로 전수, 강제 중지 후 각 OS의 재활성화 정책, 장시간 Doze·배터리 절약·실기기 발열/배터리, 여러 자동 선택 위젯의 밀집 종료, 실제 시간대/DST 수동 변경, TalkBack 음성 출력, 릴리스 축소 빌드는 별도다. 일반 프로세스 종료와 사용자의 강제 중지는 다르다. 계측 실행 과정의 강제 중지에서는 시스템이 임시 초기 레이아웃을 노출하기도 했으며 초 표시 지속을 약속하지 않는다.

집중·요약4×1의 초 확장은 지원 시계/공간/전력 검증을 통과한 뒤 별도로 한다. 이번 구현을 모든 안드로이드 기기에서 사용할 수 있는 정식 초 표시로 설명하지 않는다. 다음 회차/다른 자동 선택은 앱 데이터 갱신이 필요하며 지연 시 종료 상태에서 새로고침할 수 있다.


## 최종 정리

- 앱 최종 기본 검증42초 성공. 만료 링크 계측 보강 후 같은 검증 명령도5초 성공(앱 코드 변경 없음). 단위100개 실패0, Lint 오류0·경고159·힌트7, Kotlin 컴파일 경고 없음. 새 경고5개는 debug 검증 도구의 API31 셀 힌트2개·검증용 로케일 변경·배경 중복 그리기·toUri 권장이다. 운영 렌더러/예약의 새 오류는 없다. 나머지는 기존 의존성 업데이트·복수형·미사용 리소스 등의 항목이며 일괄 억제하지 않았다.
- 마지막 APK로 API37/36 위젯 계측을 각각 다시 실행해 각4개 중3개 실행 통과/1개 환경 조건 제외를 확인했다. 직전 전체 계측17개 중16개 실행 통과 기록도 보존한다.
