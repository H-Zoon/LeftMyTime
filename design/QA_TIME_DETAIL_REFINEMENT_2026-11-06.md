# 상세 정보 위계 보완 — 구현과 검수 대기

2026-11-09 후속: 새 Debug APK에서 월/년/주/분기, 320dp·글자 2배의 세 자리 일수, 위젯에서 연 실제 일정 상세와 기간 정보, 현재24일/선택15일을 분리한 미리보기·복귀를 확인했다. 이야기 제거는 유지한다. 모든 시작/종료·접근성·복원 조합을 완료한 것은 아니며 [최종 검수 범위](QA_FINAL_2026-11-09.md)를 따른다.

날짜: 2026-11-06.

2026-11-08 후속: 사용자 요청으로 이야기 기능과 기존 저장·읽음 기록을 제거했다. 아래 이야기 관련 구현·검수 항목과 시안의 이야기 행은 과거 상태다. 나머지 상세 변경은 유지하며 [제거 범위와 최신 검수 조건](QA_TIME_STORIES_REMOVAL_2026-11-08.md)을 함께 따른다.

상태: **‘1안 기본 + 3안 미리보기’ 조합의 Android 소스 반영 완료. 새 빌드·실행·시각 검수는 미실행.**

## 사용자 문제와 선택

[실제 화면 분석](TIME_PROGRESS_UX_REVIEW_2026-11-06.md)에서 확인한 문제는 같은 상태의 반복 설명, 오늘을 포함한 날짜 개수의 ‘지나간 시간’ 표기, 같은 55일의 서로 다른 크기, 현재/미리보기 기준의 혼재, 큰 글자의 이름/값 분절이다.

사용자는 기본 숫자·눈금과 접힌 보조 정보를 중심으로 한 1안에, 날짜 탐색 시 별도 미리보기 구역을 보여주는 3안의 동작을 조합하는 제안에 ‘진행’이라고 승인했다. 새 웹 프로토타입이 아니라 기존 Android 앱의 공통 상세에 반영했다.

## 반영 내용

| 영역 | 코드에 반영한 동작 | 사용·재사용한 기반 |
| --- | --- | --- |
| 첫 화면 | 큰 남은 숫자·눈금 뒤에 달력 현재 일차와 접힌 기간 정보·이야기 표시 | `TimeDetailContent`, `TimeDetailSheet`, 기존 80% 높이 상한·스크롤 |
| 날짜 기준 | 오늘 포함 날짜 개수를 ‘오늘 포함 N일째’, 퍼센트를 ‘달력 진행’으로 표현. 현재 날짜는 원래 범위와 실제 일차에서 파생 | `TimeDetailFacts`, `TimeDetailRange`, 한/영 문자열 |
| 중복 숫자 | 진입 연출 동안만 작은 실제값을 제공. 연출 후 같은 값의 상시 반복 제거. 달력에는 ‘오늘 이후 남은 날짜’ 기준 표시 | `InteractiveRemainingTime`, 기존 실제값 접근성·1200ms 연출 |
| 대표 일수 | 달·년·주·분기는 전체 30/92/365 자리 수와 무관하게 `displayLarge`. 이 일수의 최대값 폭 예약을 사용하지 않아 왼쪽 기준을 맞춤 | `RemainingTimeText`, 기존 타이포그래피 |
| 눈금 탐색 | 현재의 큰 숫자·눈금·비율을 유지하면서 날짜/시간 미리보기 제목·선택 기준·보조 남은 값·복귀 행동을 같은 구역으로 표시 | `InteractiveTimeRuler`, 기존 탐색·햅틱·키보드·접근성 동작 |
| 기간 정보 | 시작/종료, 전체 길이, 경과 또는 달력 일차, 비율·기준 설명은 펼쳐 확인. 전체/막대만/숨김의 기존 표시 조건 유지 | 새 `TimeDetailDisclosure`, 기존 사실 데이터 |
| 이야기 | 제목과 기존 이야기 기간 요약만 먼저 표시. 펼치면 기존 본문·전환·저장·보관함·출처를 제공 | `TimeStoriesSection`, 기존 후보·저장소·출처 |
| 읽음 기록 | 접힌 요약만 표시되었을 때는 기록하지 않음. 펼친 본문에서 기존 1.5초 대기 후 읽음 처리 | 기존 `markSeen`, 기존 로컬 기록 형식 |
| 큰 글자 | 정보 행은 가용 폭 300dp 미만 또는 글자 1.2배 초과에서 이름 위·값 아래 배치. 달·년·주·분기 단위는 화면 360dp 미만 또는 글자 1.2배 초과에서 숫자 아래 표시 | `DetailFact`, 기존 간격·서체·반응형 기준 |
| 주·분기 | 정의·시간대 설명을 큰 숫자 앞에서 기간 정보 안으로 이동 | `PeriodsActivity`, 기존 `SettingsDropdownRow` |

공통 접기 행은 같은 바탕·구분선·제목·요약·기존 Material 화살표를 사용한다. 행 전체에 최소 48dp, 버튼 역할·이름·펼침/접힘 상태를 제공한다. 펼침은 임시 `rememberSaveable` 상태이며 앱 설정 키를 추가하지 않았다.

달·년·주·분기의 일수 숫자는 연출 중 자연스럽게 폭이 바뀌되 글자 역할은 유지한다. 시·분·초 묶음의 최대값 폭 예약과 상위 단위 유지, 개인 날짜 일정·홈·목록·설치 위젯의 숫자 크기 규칙은 기존대로다. 조작 전의 간단한 눈금 안내는 발견 가능성을 위해 유지하고, 중복 ‘현재 위치’ 값은 시각 기본 화면에서 제거하되 눈금의 접근성 상태에는 남긴다.

## 적용 범위와 데이터

- 오늘·이번 달·올해의 하단 상세, 주·분기 화면, 개인 일정의 공통 상세, 위젯에서 연 앱 상세가 공통 표현을 재사용한다. 집중 완료 상태의 기록 시간·실행/미실행 비율과 종료 눈금 숨김 분기는 유지했다.
- 남은 숫자, 내부 경과율, 오늘 포함/제외 규칙, 하루 23:59:59 끝, 반복·시작/종료·알림·설치 위젯 초 로직·DB·출시 버전·기존 설정 키를 변경하지 않았다.
- 읽음 기록의 호출 시점만 본문 펼침에 맞게 제한했다. 새로운 분석 이벤트를 추가하지 않았다.
- 빈 홈의 중복 일정 추가 동선은 이 상세 보완에 포함하지 않았으며, 같은 날 후속 사용자 지시로 [메인 보완](QA_HOME_REFINEMENT_2026-11-06.md)에서 별도로 반영했다.

## 코드·문서 검토에서 확인한 범위

- 변경한 한/영 문자열 XML을 파싱했으며 중복 키가 없었다. 새 14개 문자열의 양 언어 키·형식 인자 일치를 확인했다.
- 변경 경로의 `git diff --check`에서 공백 오류가 없었다.
- 기간 정보는 원래 데이터에서 표현만 파생하며, 미리보기의 탐색값을 실제 숫자·비율·저장·이야기 기준으로 전달하지 않는 분기를 소스로 검토했다.
- 초 갱신마다 접기 상태를 초기화하지 않도록 기존 대상/원래 기간의 key 안에 두고, 이야기 펼침은 기존 대상·단위 identity에 연결했다. 회전의 실제 상태 복원은 아직 실행 검증 전이다.
- 기존 `DesignGallery.kt`에 `detail-review-month/year/quarter/week`를 추가했다. 각각 실제 `TimeDetailContent`를 사용하며 2026-11-06의 24/55/55/2일을 debug 데이터로만 제공한다. 기존 `detail-today/time/waiting/expired/same-day/last-second`, `hidden`·`bar-only`, 긴 제목·언어·밝기·글자 배율 경로도 계속 사용할 수 있다.

**컴파일·Lint·단위 테스트·계측 테스트·새 APK 설치·실행·밝게/어둡게·작은 화면·큰 글자·긴 제목·빈/오류 상태의 새 화면 검수는 하지 않았다.** 소스 검토나 이미지 시안은 실행 검증이 아니다.

## 다음 최종 검증에 포함할 항목

사용자가 최종 검증을 명시적으로 요청하면 기본 `./gradlew testDebugUnitTest assembleDebug lintDebug`에 현재 작업 전체를 포함하고 기존 경고와 새 문제를 구분한다. 그 뒤 새 APK에서 다음을 확인한다.

1. 한/영·밝게/어둡게, 320dp/기본 폭, 글자 1.0/1.5/2.0에서 대표 숫자·단위·긴 제목과 접기 행의 읽기·스크롤·48dp.
2. 달·년·분기에 같은 55일을 표시했을 때 글자 역할 일치. 365→55·100→99 진입 연출과 큰 자리 수, 실제값 보조 문구의 종료, 시·분·초 자리·단위 보존.
3. 오늘·주·달·분기·년의 실제 날짜/일차/남은 숫자와 월말·연말·윤년·자정 경계. 내부 계산은 그대로지만 표시 기준의 정확성을 재확인.
4. 기간 정보·이야기 펼침/접힘, 초 갱신·회전·대상 변경·상세 닫기/재진입, 현재/미리보기 구분·복귀, 전체/막대만/숨김.
5. 시작 전·진행·종료, 날짜 당일/지난 날짜, 잘못된 기간·사실 없음·이야기 후보 없음, 집중 완료의 기록 표현.
6. 이야기를 열지 않았을 때 읽음 기록이 없는지, 펼친 뒤 1.5초·빠른 전환·접기 취소 시 기존 읽음·정렬 정책이 유지되는지. 저장/해제·보관함·출처 접근.
7. TalkBack의 행 이름·버튼 역할·펼침 상태·정보 이름/값 묶음·눈금 상태와 조절, 키보드·햅틱·모션 비활성화.
8. 위젯에서 연 앱 상세의 공통 표시와 위젯 추가 동선. 설치 위젯 렌더링/초 로직의 기존 작업은 별도 최신 검수 문서도 함께 따른다.
