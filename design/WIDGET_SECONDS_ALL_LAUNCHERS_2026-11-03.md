# 숫자 초 표시 전체 런처 확대

2026-11-09 후속: Debug 단위/Lint·계측 검증과 API37.2의 실제 런처 설치/설정·초 흐름·미리보기 정지·상세 연결을 확인했다. DrawInstructions production probe는 종료 후0초/종료 안내/중립 눈금으로 전환했다. XML fallback 실제 런처·음수 경계는 이번 호스트 조건에서 실행 검증하지 못했다. [정확한 통과/제외/미검증 범위](QA_FINAL_2026-11-09.md)를 따르며 전체 런처 검증으로 확대하지 않는다.

2026-11-03. 사용자 요청: 전체 런처에서 초를 볼 수 있도록 확대하며, 갱신 지연으로 인한 음수 표시를 허용한다. 기존 `Chronometer`·위젯 XML·눈금·경계 예약을 재사용했다. **코드·문서 정적 검토만 수행했고 빌드·Lint·단위/계측 테스트·설치·시각 검수는 미실행이다.** 이전 QA와 설치 앱은 이 변경의 검증 결과가 아니다.

## 전달 방식

앱의 최소 지원 버전은 Android 8(API 26)이다. 표준 `RemoteViews.setChronometerCountDown`은 [API 24부터 제공](https://developer.android.com/reference/android/widget/RemoteViews#setChronometerCountDown(int,%20boolean))되므로 숫자 초 표시에는 기존 `DrawInstructions`의 API/문서 버전 조건이 필요하지 않다.

| 조건 | 전달 방식 | 표시 |
| --- | --- | --- |
| 원격 `widget_seconds_enabled=false` 또는 위젯별 초 표시 꺼짐 | 기존 XML | 정적 숫자·눈금·기준 시각 |
| 원격/사용자 선택 켜짐 + 지원 문서/API + 검증된 Launcher3/Pixel | `DrawInstructions` | 숫자·눈금·상태를 호스트 시계로 함께 갱신 |
| 그 외 런처·문서/API | XML `Chronometer` | 숫자는 매초, 눈금·기준 시각은 마지막 앱 갱신 기준 |

삼성 One UI의 `DrawInstructions` 수신 충돌 기록 때문에 해당 전달 방식의 런처 제한은 유지한다. 기본 홈 앱을 판별하지 못하는 경우도 표준 XML을 사용한다. 이는 전체 런처에 표준 전달 경로를 여는 변경이며, 모든 제조사·런처에서 실제 동작을 검증했다는 의미는 아니다. 렌더/게시 중 앱에서 잡을 수 있는 오류가 발생하면 기존 정적 XML 재게시를 시도한다.

위젯별 기본값 꺼짐·실험 기능 표기·기존 저장 키를 유지한다. 대상은 오늘과 기존 7일 이내 시간 일정이며, 집중·날짜 일정·달/년/주/분기·기간 요약·이전 복합 요약의 제한은 그대로다. 앱의 매초 작업·서비스·알람을 추가하지 않는다.

## 시작·종료·자정과 음수

- 정확 알람 접근은 필수 조건에서 제거했다. 설정의 허용 요청 버튼과 차단 상태를 제거하고 기존 `TimeLeftSwitchRow`·한/영 안내를 사용한다.
- 접근이 있으면 기존 1초 선행 정확 경계 알람을 함께 사용한다. 접근이 없으면 시작/종료와 15분 스냅샷 갱신 중 빠른 시각으로 기존 비정확 알람을 요청한다. 다음 렌더에서 기존 정확 경계 기록도 제거한다. 등록 중 권한이 회수되면 기존 비정확 예약 대체를 유지한다.
- 오늘은 23:59:59에 정적 종료 상태가 되며, 이 마지막 초에 렌더되더라도 다음 자정 갱신을 요청한다. 자정 전후 렌더가 늦으면 이전 날짜의 숫자·눈금이 남을 수 있다.
- Android `Chronometer`는 [대상 시각 뒤에 음수 시간도 표시](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/core/java/android/widget/Chronometer.java)한다. 시작 대기 상태도 같은 제약이 있다. 정확 알람도 절전·콜드 스타트 등의 지연을 없애지 못하며, Android 구현별 반올림 차이 때문에 기존 기기의 약 2초 여유를 공통 보장으로 사용하지 않는다.
- 숫자 폭 측정에 `-`와 `−` 중 더 넓은 부호를 포함해 같은 시계 형식에서 부호가 추가되는 공간을 확보한다. 임의의 장시간 지연으로 시간 자리 수까지 늘어나는 경우의 전체 폭은 보장하지 않는다. 글자를 축소하거나 시간을 임의로 제한하지 않는다.
- 설정 프리뷰는 기존 실제 렌더러의 고정 시점이며 `Chronometer`도 정지 상태다. 설치 위젯만 호스트에서 매초 흐른다.

## 검토와 최종 검증 대기

독립 코드 검토에서 원격 OFF의 두 경로 차단, 미지원 문서/미검증 런처의 표준 경로, 정확 접근 전환 시 기록 정리, 자정 예약, 고정 프리뷰를 확인했다. 회귀 소스에는 전달 방식 조합·시작/종료 일반 예약·오늘 날짜 전환·표준 XML 초 표시를 반영했다. 소스 추가나 정적 검토를 실행 검증 완료로 간주하지 않는다.

사용자가 최종 검증을 요청하면 `./gradlew testDebugUnitTest assembleDebug lintDebug`를 실행하고 다음을 확인한다.

1. Android 8 및 14 이하의 표준 초 표시, Android 15의 미지원 문서, 최신 Android의 One UI·기타 런처와 기존 Launcher3/Pixel 경로.
2. 정확 알람 허용/미허용/회수/재허용, 시작 전→진행→종료, 오늘 23:59:59→자정과 시간대/시계 변경, 다음 일정 선택·반복 회차.
3. 프로세스 종료·화면 꺼짐·Doze·장기 미갱신 후 복구와 허용한 음수 표시. 정시 전환이나 15분 이내 실제 갱신을 보장하지 않는다.
4. 원격 `true→false→true`, 위젯별 선택과 기존 저장값, 단일/보드·밝게/어둡게·한/영·작은 크기·큰 글자·긴 제목·빈 상태, 음수 부호가 생길 때 숫자와 상태 배치, 프리뷰 정지.

새 APK와 실행 화면·전후 캡처는 아직 없으며 이전 설치 앱과 현재 소스가 다르다. 공개 Console·스토어 게시·출시 버전·배포·커밋은 이 작업에서 변경하지 않았다.
