# LeftMyTime 개인 영상 기록과 전체 흐름 점검

## 확인한 화면

기존 6.9(26) Debug APK를 Android 에뮬레이터에서 실행했다. 현재 작업 시작 시점의 화면을 실제 화면과 Debug 디자인 갤러리에서 캡처했다. 갤러리는 앱 화면에 예시 일정을 전달해 빈 화면, 날짜 일정과 긴 제목 같은 상태를 재현한다.

1. **홈과 첫 일정 추가 — 기본 흐름 양호.** 남은 시간과 숫자 눈금이 먼저 읽히고 빈 홈에는 일정 추가가 한 번만 나온다. 날짜 일정이 모두 지난 경우에는 다음 일정 영역에서 지난 일정을 열도록 개선했다. [홈](qa-local-video-flow/01-home.png) · [빈 홈](qa-local-video-flow/02-empty-home.png)
2. **일정 편집 — 용어 개선.** 날짜 선택과 저장은 아래로 이어지지만 화면 제목은 ‘항목 수정’이고 홈은 ‘일정’이었다. ‘일정 추가’와 ‘일정 수정’으로 통일했다. [일정 편집](qa-local-video-flow/03-add-date.png)
3. **전체 일정과 지난 일정 — 찾기 개선.** 검색 아래 정렬 선택이 다섯 개로 펼쳐져 있고 완료한 날짜가 목록 맨 아래에 있었다. 정렬을 현재값이 보이는 한 행으로 묶고 검색 지우기와 ‘지난 일정만’을 추가했다. 설정에서 지난 일정을 숨겨도 이 필터로 열 수 있고, ‘가까운’ 순서에서는 최근에 끝난 일정이 먼저 온다. 홈과 전체 일정의 스크롤 위치는 각각 기억한다. [전체 일정](qa-local-video-flow/04-all-schedules.png)
4. **펼친 일정과 날짜 상세 — 행동 위계 개선.** 펼친 행에서 상세·수정·위젯·삭제가 나란히 붙어 있었다. 날짜 일정에는 시간 상세와 영상 기록을 먼저 둔다. 편집·삭제는 더보기, 위젯 추가는 시간 상세에서 제공한다. 기존의 큰 숫자와 접힌 기간 정보 구조를 사용한다. [펼친 행](qa-local-video-flow/04a-expanded-date.png) · [날짜 상세](qa-local-video-flow/05a-date-detail-sheet.png)
5. **영상 기록 — 개인 기록으로 축소.** 이전 빈 상태의 주요 행동은 초대 코드 입력이었고, 기록 목록에는 초대와 새로고침이 노출됐다. 이제 날짜 일정에서 들어오면 바로 해당 일정의 기록을 읽는다. 영상 추가에서 촬영하거나 기기 파일을 고르고, 미리보기 후 저장한다. 클립은 날짜별·시간순으로 보고 개별 재생과 이어 보기를 제공한다. [이전 진입 화면](qa-local-video-flow/06-album-entry.png) · [이전 타임라인](qa-local-video-flow/10-album.png)
6. **집중 설정 — 기본 흐름 양호.** 길이 선택, 시작, 집중 기록 순서가 명확하다. 시작 버튼에 공통 주요 행동 모서리를 적용했다. [집중 설정](qa-local-video-flow/07-focus.png)
7. **설정과 일정 백업 — 데이터 범위 명확화.** 지난 일정은 설정의 기본 표시 방식과 전체 일정의 탐색 필터를 구분해 안내한다. 일정 내보내기에는 영상이 포함되지 않는다는 점을 백업 범위에 표시했다. [설정](qa-local-video-flow/08-settings.png) · [일정 백업](qa-local-video-flow/08a-schedule-backup.png)
8. **위젯 — 미리보기 흐름 양호.** 기존의 ‘표시할 내용 → 선택한 일정 → 미리보기 → 위젯 추가’와 기간 표시를 사용한다. 날짜 일정 위젯에서 열리는 앱 상세에 동일한 영상 기록 진입을 추가했다. [위젯 설정](qa-local-video-flow/09-widget.png)

스크린샷으로 초점 순서, TalkBack 발화, 색 대비, 시스템 카메라 앱의 동작까지 확인할 수는 없다. 정렬과 필터, 메뉴와 영상 버튼은 이름 있는 터치 영역과 공통 큰 글자 대응 컴포넌트를 사용했다. 새 화면의 실제 동작 및 접근성은 아래 검수 절차를 따른다.

## 구현

- Android 카메라 앱의 영상 촬영 또는 로컬 파일 선택을 사용한다. 임시 카메라 출력은 별도의 FileProvider 경로에만 허용한다. MP4 영상의 15초·32MB 제한을 기기에서 검사한다.
- 저장이 승인되면 앱 내부의 `noBackupFilesDir/video-records`로 이동한다. 날짜 일정의 기존 `stableId`를 폴더에 연결한다. 제목과 목표일을 수정해도 기록은 같은 일정에 남으며, 일정 복제는 새 식별자를 받는다. Room 스키마와 일정 백업 형식은 기존 버전을 사용한다.
- 임시 파일을 검증하고 나서 저장 위치로 이동한다. 기록 날짜는 이 앱에 영상을 남긴 기기 시각을 기준으로 한다. 타임라인은 당시의 날짜와 현재 목표일을 함께 보여준다. 앱에서 일정 삭제를 확인하면 저장 영상도 삭제한다. 앱 제거·데이터 삭제 후에는 기기의 기록을 복구할 수 없다.
- Media3의 파일 데이터 소스로 로컬 MP4를 재생한다. 로딩, 빈 목록, 입력 취소, 파일 오류, 삭제 확인을 각각 표시한다. 필요한 네트워크 콘텐츠 없이 촬영·파일 선택·재생을 사용할 수 있다.
- 이전 공유 구현의 앱 코드, 빌드 설정, SQL과 초대·계정·업로드 화면은 이 브랜치에서 제거했다. 이전 테스트 프로젝트에 저장한 영상이나 계정은 로컬로 옮기거나 삭제하지 않았다.

## 설치 후 검수

1. 기존 앱 데이터가 있는 설치에서 업데이트하고, 비행기 모드에서 날짜 일정을 만들거나 기존 날짜 일정을 연다. 펼친 행과 상세 화면의 **영상 기록**이 같은 일정을 보여야 한다.
2. **영상 추가 → 영상 촬영**과 **기기에서 선택**을 각각 실행한다. 취소, 길이·파일 크기 초과, 촬영 앱 부재, 저장 공간 오류를 구분한다. 정상 영상은 앱을 재시작한 뒤에도 남아야 한다.
3. 날짜·이름을 바꾸거나 일정 JSON을 같은 일정에 복원한 뒤 연결을 확인한다. 복제한 일정은 개별 기록으로 시작하고, 개별 영상/일정 삭제를 각각 확인한다.
4. 기본 지난 일정 표시의 표시·맨 아래·숨김 각각에서 **지난 일정만**을 확인한다. 검색 지우기와 빈 상태, 두 화면의 스크롤 복귀, 펼친 일정의 편집·삭제와 상세의 위젯 추가를 따라간다.
5. 한/영, 밝게/어둡게, 작은 화면·큰 글자에서 저장 시트·영상 옵션·날짜 그룹을 확인한다. 두 개 이상의 순차 재생, 세로·가로 영상, 화면을 떠날 때 오디오 정지를 확인한다.

Debug 디자인 갤러리에서 `video-record-empty`, `video-record-timeline`, `video-record-draft`, `video-record-error`, `video-record-timeline-large`가 실제 기록 화면을 재사용한다. 위의 화면별 분석에는 기존 앱 캡처를 사용했다. 변경 화면은 아래 실행 기록에 있다.


## 6.9 Debug 실행 확인

- Galaxy A33에 설치돼 있던 APK는 영상 기록 Activity가 빠진 빌드였다. 개인 기록 브랜치에서 Debug APK를 생성해 데이터를 유지하는 업데이트로 설치했다. 기기의 설치 APK가 영상 기록 Activity를 포함한 빌드와 일치하는지 확인했다.
- 에뮬레이터에서 Wi-Fi와 모바일 데이터를 끄고 실제 날짜 일정에서 기기 파일을 골라 저장했다. 앱 프로세스를 다시 시작해 동일 일정의 영상이 남아 있고 Media3로 재생할 수 있는지 확인했다. [날짜 상세](qa-local-video-flow/after-01-date-detail.png) · [저장된 기록](qa-local-video-flow/after-05-record-timeline.png) · [로컬 재생](qa-local-video-flow/after-06-local-playback.png)
- 한국어 디자인 갤러리에서 ‘지난 일정만’ 필터와 펼친 일정의 ‘영상 기록’ 진입을 확인했다. [지난 일정 진입](qa-local-video-flow/after-07-past-date-entry.png)
- 시스템 카메라로 직접 촬영하는 흐름과 실기기에서 재생하는 동작은 이번 실행 확인에 포함하지 않았다.
