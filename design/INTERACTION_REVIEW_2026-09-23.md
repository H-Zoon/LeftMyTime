# 사용자 인터랙션 조사 — 2026-09-23

상태: **조사 후 사용자 승인 · 코드 적용 · 최종 검증 대기**. 숫자 최대값→현재값, 눈금 직접 조작과 추천 반응을 공통 상세에 반영했다. 아래는 당시 조사 근거이며 최종 적용 규칙은 [디자인 시스템](DESIGN_SYSTEM.md#상세-인터랙션-2026-09-23), 확인 범위는 [검수 대기 기록](QA_INTERACTIONS_2026-09-23.md)을 따른다. 대화의 체험 시안은 실제 Android 검수 증거가 아니다.

최종 적용 범위: 1200ms 숫자 진입과 마지막 최대 6단계 감속 보정, 별도 탐색선, 현재 복귀/자석 반응, 주변 눈금 반응, 제한적 햅틱, 이야기의 버튼/스와이프 전환, 총 초 전환. 개인 일정도 대표 구간·펼친 목록에서 같은 상세 시트를 연다. 홈과 목록의 숫자·위젯 비트맵은 자동으로 움직이지 않는다. 관성 테이프·원형 다이얼·일정 편집 제스처는 조사 단계의 대안으로 남긴다.

## 권장 조합

1. 상세를 새로 열 때 대표 숫자 하나가 전체 길이에서 실제 남은 길이로 400–550ms 동안 내려온다.
2. 상세 눈금을 좌우로 움직이면 해당 시각/날짜의 남은 길이를 미리 본다. 실제 현재 남은 시간과 원래 일정은 유지한다.
3. 중요한 눈금에만 가벼운 촉각 피드백, 다른 이야기 전환에 짧은 이동·투명도 효과를 적용한다.

홈의 세 기간과 모든 목록에서 한꺼번에 움직이게 하지 않는다. 첫 적용은 기간 상세·위젯에서 여는 앱 상세이며, 홈 대표 시간으로의 확대는 실제 사용감을 본 뒤 판단한다. 이하 시간·거리 수치는 구현 시작값 제안이지 성능 또는 사용자 검증 결과가 아니다.

## 조사 당시 코드에서 확인한 범위

- `RemainingTimeText.kt`: 숫자·단위 그룹, 첫 baseline, 큰 글자 줄바꿈, 접근성의 실제 남은 시간 설명을 공유한다. 숫자는 현재 `Text`로 즉시 갱신한다.
- `RemainingTimeFormat.kt`: 초 하나를 시·분·초로 분해한다. 숫자 그룹별 독립된 시간값을 저장하지 않는다.
- `TimeRuler.kt`: 높이 28dp의 표시 전용 Canvas다. 폭에 따라 20–60개 눈금을 배치하고 남은 구간에만 빛을 그린다. 각 눈금은 고정 1분/1일이 아니며 현재 터치 동작은 없다.
- `TimeDetailContent.kt`: 기간 상세와 `WidgetDetailsActivity`가 공유한다. 상세 확장은 이 경로에 한 번 구현할 수 있다.
- `TimeDetailFacts.total`에는 전체 초 또는 일수가 있다. `ItemGenerate.kt`는 월/년의 실제 길이를 제공한다. 다만 눈금 탐색에 필요한 원본 시작·종료 시각/날짜는 `AdapterItem`에 표시 문자열로만 전달되므로 탐색용 형식 있는 데이터를 별도로 넘겨야 한다. 표시 문구를 역파싱하지 않는다.
- 오늘은 기존 00:00–23:59:59 기준, 월/년 남은 일수는 오늘 제외, 경과율은 오늘 포함이다. 이 기준을 애니메이션 작업에 묶어 바꾸지 않는다.
- `Motion`은 150/200/720ms를 정의한다. 720ms의 이전 ring sweep 주석을 새 방향의 근거로 사용하지 않는다. 승인 시 새 숫자 진입 역할과 실제 사용처를 함께 정리한다.
- Gradle의 Compose BOM은 `2024.02.00`이다. 최신 문서의 API를 그대로 복사하지 않고 현재 의존성에서 사용 가능한 API를 확인해야 한다. 이번 조사에서 의존성을 갱신하지 않았다.
- 설치 위젯의 눈금은 `WidgetRendering.kt`의 비트맵이며 `AppWidget.kt`에서 탭 동작을 연결한다. 앱의 Canvas 제스처를 그대로 이식할 수 없다.

## 1. 최대값에서 목표 숫자로

### 시작값의 의미

| 대상 | 권장 시작값 | 실제 목표값 |
| --- | --- | --- |
| 이번 달 | 해당 월 전체 일수 28/29/30/31 | 기존의 오늘 제외 남은 일수 |
| 올해 | 해당 연도 전체 일수 365/366 | 기존의 오늘 제외 남은 일수 |
| 오늘 | 기존 오늘 범위와 같은 상한 23:59:59 | 기존 초 단위 남은 시간 |
| 진행 중 시간 일정 | 원래 일정의 전체 초 | 현재 종료까지의 초 |
| 진행 중 날짜 일정 | 기존 일정 계산의 전체 일수 | 기존 남은 일수 |
| 시작 대기·종료·잘못된 기간 | 첫 적용에서 진입 카운트 생략 | 실제 상태와 기존 숫자 유지 |

예: 9월 23일이면 연출은 30→7일이다. 30은 전체 길이이고 오늘 제외 방식에서 실제 첫날의 남은 일수가 30이라는 뜻은 아니다. 연출 중에도 ‘현재 7일 남음’을 보조 정보로 유지해 전체 길이와 현재값을 구분한다.

시·분·초를 각각 최댓값에서 별개로 내리면 24시간 59분 같은 범위를 벗어난 조합이 나타날 수 있다. **하나의 총 초를 보간하고 기존 포맷으로 나눈다.** 현재값은 원본 데이터, 움직이는 숫자는 화면 연출용 값으로 분리한다. 정렬·알림·저장·이야기 선택·실제 눈금 비율에는 연출값을 전달하지 않는다.

후속 사용자 검수에서는 동일 총 초 보간의 분·초 순환 때문에 오늘의 감속이 약하게 읽혔다. 최종 구현은 한 타임라인에서 유효한 시·분·초 시작 조합을 만들고 단위별 마지막 6단계를 보정한 후 총 초 하나로 합친다. 처음 값은 실제 최대값이며 단위를 빌릴 때도 항상 그 이하로 내려온다. 중간값의 범위·단조 감소와 원본 데이터 분리 기준을 유지하고, 위의 단일 보간 제안은 이 후속 표시 보정으로 대체한다.

### 표현 비교

| 방식 | 특징 | 판단 |
| --- | --- | --- |
| 짧은 숫자 카운트 | 큰 숫자가 빠르게 감소하다 현재값에 정착. 단위와 baseline은 고정 | 1차 권장, 변경 범위가 가장 작음 |
| 세로로 굴러가는 숫자 | 숫자 줄이 넘어가는 감각. 폭·높이와 중단 처리를 정교하게 다뤄야 함 | 체험 시안에서 비교 후 선택 |
| 숫자마다 임의 값으로 여러 번 회전 | 효과는 강하지만 정확한 숫자를 읽기까지 지연되고 작은 화면이 복잡해짐 | 기본 경험으로 권하지 않음 |

400–550ms, 감속 곡선, 반동 없이 한 번이 출발점이다. 1초 틱·일반 재구성·리스트 재노출·회전·백그라운드 복귀에서는 최대값으로 다시 시작하지 않는다. 상세 진입 상태를 소유한 곳에서 시작 신호를 주고, 대상/범위 식별자별로 재실행을 제어한다. 재생 중 실제 초가 바뀌어도 다시 시작하지 않으며 끝에서 최신값으로 연결한다.

시스템 애니메이션 배율이 0이면 즉시 실제값을 표시한다. 접근성에는 연출 중간 숫자가 아니라 현재값을 제공하고 매 프레임 읽지 않는다. 단위 경계(1시간→59분, 1분→59초)와 세 자리→두 자리에서도 자리 폭/줄바꿈/기준선을 유지한다. 구현 후보는 `Animatable`과 제한적인 `AnimatedContent`다. [Android 값 기반 애니메이션](https://developer.android.com/develop/ui/compose/animation/value-based), [MotionDurationScale](https://developer.android.com/reference/kotlin/androidx/compose/ui/MotionDurationScale).

## 2. 눈금을 돌리거나 스크롤하기

**권장 의미는 ‘시간 탐색’이다.** 예: 14:00–15:00 일정의 현재가 14:18이면 원래 42분 남음을 유지한다. 눈금을 14:40에 맞추면 별도의 ‘14:40 기준 · 20분 남음’이 나타난다. 끝 시각이나 알림을 바꾸는 조작으로 연결하지 않는다.

| 조작안 | 동작 | 권장 범위 |
| --- | --- | --- |
| 가로 드래그/원하는 위치 탭 | 눈금 위 탐색선이 손가락을 따라 움직이고 미리보기 표시 | 첫 적용 |
| 테이프를 굴리듯 가로 밀기 | 확대된 눈금 띠가 고정된 탐색선 아래로 이동, 약한 관성 후 주요 눈금 정착 | 후속, 첫 적용에서 필요하지 않음 |
| 원형 회전 다이얼 | 회전 각도를 시간으로 환산 | 현재의 얇은 직선 눈금과 구조가 달라 우선순위 낮음 |
| 양 끝을 끌어 일정 수정 | 시작/종료 시각이 변함 | 별도 편집 화면의 작업으로 분리 |

### 조작 규칙

- 보이는 눈금은 현재 28dp를 유지하고 손가락 입력 범위만 최소 48dp로 확보한다.
- 가로 의도가 확정된 뒤 드래그를 소비한다. 세로 이동은 본문 스크롤과 바텀시트에 넘긴다. 터치 취소와 범위 변경도 처리한다. [Compose 드래그·스와이프](https://developer.android.com/develop/ui/compose/touch-input/pointer-input/drag-swipe-fling).
- 실제 경과/남은 색과 글로우는 현재 시각 기준으로 유지한다. 탐색선과 설명을 별도로 표시해 미리보기가 실제 남은 시간처럼 보이지 않게 한다.
- 손을 떼면 고른 시점을 읽을 수 있도록 유지하고 ‘현재로 돌아가기’로 탐색을 종료한다. 실제 시간이 바뀌어도 탐색 지점은 움직이지 않고 현재값만 계속 갱신한다. 닫기/다른 일정 전환 시 탐색은 해제한다.
- 시간 일정은 첫 적용에서 1분 간격, 1분 미만 구간은 초 간격, 날짜 일정은 1일 간격을 후보로 한다. 화면상의 20–60개 눈금 수를 실제 단위 간격으로 착각하지 않게 분리한다.
- ‘좌우로 움직여 시간 살펴보기’ 안내는 조작 영역 가까이에 둔다. 필수 기능을 숨겨진 제스처에만 두지 않는다.
- 접근성에는 범위·현재 선택값·이전/다음 단위·현재 복귀 동작을 제공한다. 기존 Canvas의 읽기용 `clearAndSetSemantics`를 그대로 두면 조절 동작이 전달되지 않으므로 의미 구조를 함께 수정한다. [Compose 접근성 의미](https://developer.android.com/develop/ui/compose/accessibility/semantics).
- 마우스/트랙패드를 지원한다면 가로 스크롤 또는 포커스된 눈금의 명시적인 조절로 한정한다. 페이지의 일반 세로 휠을 가로 탐색으로 가로채지 않는다.

### 설치 위젯과 앱의 구분

Android 홈 화면 위젯은 런처의 페이지 이동과 공존해야 하며, 공식 문서는 지원 제스처를 탭과 세로 스와이프로 제한한다. 현재 비트맵 눈금에 임의의 가로 드래그·회전 제스처를 붙이는 안은 적용 범위에서 제외한다. 위젯은 탭으로 상세를 열고 그 안에서 같은 숫자·탐색 동작을 제공한다. [Android 위젯 제스처 제한](https://developer.android.com/develop/ui/views/appwidgets/overview#gestures).

## 3. 추가할 만한 재미

| 아이디어 | 사용자가 느낄 변화 | 우선순위 |
| --- | --- | --- |
| 주요 눈금의 가벼운 촉각 피드백 | 5/15분, 하루 등 의미 있는 지점을 넘을 때 살짝 걸리는 감각 | 높음. 매 픽셀·매 초 진동하지 않고 설정/기기 지원을 따름 |
| 이야기 넘기기 | ‘다른 이야기 보기’에 약 150–200ms의 짧은 이동과 투명도 전환. 본문 가로 스와이프도 선택적으로 제공 | 높음. 기존 버튼·후보 고정 규칙 유지 |
| 누른 곳의 눈금 반응 | 손가락 주변의 눈금 몇 개가 잠깐 길어졌다 돌아옴 | 중간. 실제 채움 비율과 남은 구간 밖 글로우는 변경하지 않음 |
| 다른 단위로 살펴보기 | 상세에서 ‘초로 보기’를 누르면 같은 남은 시간을 총 초로 확인, 재탭하면 원래 단위 | 중간. 일수→자유시간 환산은 하지 않고 시간 일정부터 검토 |
| 현재 위치에 붙는 촉감 | 탐색선이 현재 시각 근처에서 약하게 정착하고 짧게 반응 | 중간. 미리보기에서 빠져나오는 동작이 명확해야 함 |

반복 진동·상시 호흡·파티클·화면 전체 흔들림은 읽기와 충돌할 가능성이 크다. 사용자 조작에만 짧고 일관되게 반응하는 쪽을 권한다. 적은 빈도의 의미 있는 촉각 피드백은 Android 지침과도 맞는다. [Android 햅틱 원칙](https://developer.android.com/develop/ui/views/haptics/haptics-principles).

## 기준 변경과 구현 순서

조사 당시 디자인 기준에는 진입 시 채워지는 효과와 매초 숫자 이동을 제한하는 규칙이 있었다. 후속 구현 승인에 따라 **‘명시적으로 상세를 열 때 숫자만 1회 연출’**, **‘직접 조작할 때 탐색과 촉각 피드백’**의 예외 범위를 디자인 문서와 공통 코드에 함께 기록한다. 매초 틱과 상시 글로우는 그대로 유지한다.

1. `RemainingTimeText`에 표시용 진입 상태를 추가하고 원본값/접근성/시간 계산과 분리.
2. 원본 시각·날짜 데이터가 있는 탐색 모델을 추가하고 `TimeRuler`를 감싸는 앱 전용 상호작용 구성요소에서 재사용.
3. 공통 상세에 탐색 상태와 현재 복귀를 연결. 시간 일정부터 확인한 뒤 하루·월·년의 포함 기준 확장.
4. `TimeStoriesSection`에 사용자 전환 효과와 선택적 스와이프를 추가하고 후보·순서 유지.

새 DB 스키마·알림·서비스·분석 이벤트·의존성 업그레이드는 이 제안에 필요하지 않다.
