# 위젯의 표시 항목과 크기 분리 검토

작성: 2026-09-18. 기준 커밋: `8986d02`.
상태: **후속 ‘변경 진행’ 승인에 따라 표시 항목 분리·기간 요약·기존 위젯 호환·설정 복원·공유 미리보기 코드 반영. 빌드·실행 검수 보류.** 확정 규칙은 [디자인 기준 v2](DESIGN_SYSTEM.md), 실제 변경 범위는 [구현 및 검증 대기 기록](QA_WIDGET_CONTENT_2026-09-18.md)을 따른다. 아래 조사는 `8986d02` 시점의 발견과 판단 기록이다. 런처의 목적별 개편은 이후 별도 승인에 따라 반영했으며 [선택 UI·런처 개편 기록](QA_WIDGET_SELECTION_2026-09-18.md)에서 관리한다.

사용자 문제: 위젯 크기에 따라 오늘·이번 달·올해가 덧붙거나 사라진다. 원하는 내용을 별도 항목으로 선택하는 방안을 검토한다.

## 판단

**표시 항목을 먼저 선택하고, 크기는 그 항목의 배치만 바꾸도록 분리하는 것을 추천한다.** 기존 오늘·이번 달·올해 개별 선택을 유지하고, 세 기간을 함께 보는 용도는 독립적인 ‘기간 요약’ 항목으로 제공한다. 개인 일정 위젯 아래에 기간 요약을 자동으로 붙이지 않는다.

사용자가 말한 ‘별도 항목’에는 두 수준이 있다. 위젯 설정의 표시 항목 분리는 현재 구조를 활용할 수 있다. 홈 화면의 위젯 추가 목록 자체를 오늘·이번 달·올해로 나누는 변경은 별도 단계로 다룬다. 후자는 이름만 바꿔도 기존에 설치한 위젯의 선택값·초기값·미리보기에 영향을 줄 수 있다.

## 변경 전 코드에서 확인한 사실

| 현재 구조 | 사용자에게 보이는 결과 | 근거 |
| --- | --- | --- |
| `WidgetSource`에 Today / Month / Year / Next / Custom 존재 | 설정에서 오늘·이번 달·올해를 이미 각각 선택할 수 있음 | [AppWidgetConfigure.kt](../app/src/main/java/com/devidea/timeleft/widget/AppWidgetConfigure.kt), `WidgetSource` |
| 위젯 ID별로 `embedTime`, `embedMonth`, `embedYear`, `nextCustom` 또는 일정 ID 저장 | 여러 위젯이 서로 다른 기간·일정을 표시할 기반이 이미 있음 | 같은 파일의 `persistAndFinish`, [AppWidget.kt](../app/src/main/java/com/devidea/timeleft/widget/AppWidget.kt)의 `renderWidget` |
| 대형 레이아웃은 선택한 대표 항목 외에 세 기간 요약을 항상 바인딩 | 오늘을 대표로 선택하면 아래에도 오늘이 반복될 수 있음 | `renderLarge`, [app_widget_large.xml](../app/src/main/res/layout/app_widget_large.xml) |
| 대형은 최소 폭 245dp·최소 높이 185dp 조건으로 판정. 보조 이번 달은 높이 ≥ 210 × 글자 배율, 올해는 ≥ 240 × 글자 배율일 때 표시 | 크기·글자 배율에 따라 보조 기간 개수가 달라짐. 대형의 오늘 보조 행에는 별도 숨김 조건이 없음 | `resolveSizeClass`, `adaptToHeight` |
| 위젯 추가 목록에는 소형·중형·와이드·대형의 네 provider 등록 | 사용자는 먼저 크기 이름을 고르고 이후 표시 항목을 선택함. 설치 후 레이아웃은 실제 크기 조건으로 다시 판정됨 | [AndroidManifest.xml](../app/src/main/AndroidManifest.xml), `app_widget_info*.xml` |
| 설정 미리보기는 별도의 Compose 숫자·눈금 영역 | 실제 대형 위젯의 추가 기간·높이에 따른 숨김을 보여주지 않음 | `WidgetPreviewBand`; 실제 RemoteViews 재사용은 `AppWidget.previewViews`에 있음 |
| 설정 화면 초기값은 항상 오늘·남은 시간 표시 | 재설정 기능을 추가하려면 위젯별 기존 값 복원이 먼저 필요함 | `WidgetConfigureRoute` |
| 개인 일정이 없거나 선택 일정 조회에 실패하면 이번 달로 대체 | 크기와 별개로 표시 대상이 바뀌는 경로가 있음 | `renderNextCountdownWidget`, `renderCustomWidget`, `renderMonthFallback` |

높이 값은 현재 코드의 조건이다. 모든 런처에서 동일한 칸 수나 실제 가시성을 보장한다는 의미가 아니며 이번 조사에서 실행 검증하지 않았다.

## 추천하는 표시 항목

| 선택 항목 | 주요 내용 | 크기를 늘렸을 때 |
| --- | --- | --- |
| 오늘 | 오늘 남은 시간 | 같은 값의 가독성·여백, 하루 눈금과 범위 보강 |
| 이번 달 | 이번 달 남은 일수 | 같은 값과 해당 월의 눈금·범위 보강 |
| 올해 | 올해 남은 일수 | 같은 값과 해당 연도의 눈금·범위 보강 |
| 기간 요약 — 신규 | 오늘·이번 달·올해를 함께 표시 | 가로/세로 재배치와 여백 조정. 세 기간을 유지 |
| 곧 다가오는 일정 | 기존 자동 선택 일정 | 그 일정의 남은 시간·종료 정보·눈금 보강 |
| 내 일정 | 사용자가 지정한 일정 | 그 일정의 남은 시간·종료 정보·눈금 보강 |

‘한 달’은 지금부터 30일을 뜻하지 않도록 앱과 동일하게 **‘이번 달’**로 표기한다. 현재 ‘이번 달 흐름’, ‘올해 흐름’, ‘내 항목’이라는 설정 문구도 선택 대상이 명확한 표현으로 정리하는 후보이다.

개별 기간 위젯은 작은 크기에서도 선택한 이름과 남은 값을 우선한다. 넓어져도 다른 기간을 추가하지 않는다. ‘기간 요약’은 세 정보를 함께 보여주는 별도 용도이므로 모두 읽을 수 있는 최소 크기를 정해야 한다. 공간이 모자란다고 올해부터 숨기거나 글자를 작게 줄이지 않는다. 최소 크기와 큰 글자에서의 대응은 실제 런처 검수 후 확정한다.

예: 사용자가 ‘올해’를 골랐다면 작은 위젯은 ‘올해 / 104일 남음’, 큰 위젯도 같은 값에 연도 범위와 눈금을 더한다. ‘기간 요약’을 골랐을 때만 오늘·이번 달·올해가 함께 표시된다. 숫자는 설명용 예시다.

색·글꼴·눈금은 A안을 유지한다. 종류별로 다른 카드 스타일이나 아이콘 체계를 추가하지 않는다. 기간 요약도 한 표면 안에서 글자·간격·얇은 구분선으로 구성한다.

## 대안 비교

| 방안 | 장점 | 비용·제약 | 판단 |
| --- | --- | --- | --- |
| 기존 개별 선택만 유지하고 자동 보조 기간 제거 | 변경 범위가 가장 작고 한 위젯의 목적이 선명함 | 세 기간을 함께 보려면 위젯을 세 개 놓아야 함 | 최소 개선안 |
| 개별 선택 + 독립 ‘기간 요약’ 추가 | 하나만 보는 용도와 한꺼번에 보는 용도를 사용자가 결정. 크기와 내용의 결합 해소 | 요약 전용 배치·최소 크기·미리보기 필요 | **추천** |
| 런처의 추가 목록부터 오늘·이번 달·올해·내 일정 등으로 구분 | 추가하기 전에 목적을 이해하기 쉬움 | provider별 기본값·이전 설치 호환·미리보기·런처별 노출 검수까지 필요 | 내용 분리 후 후속 단계 |

런처 목록을 목적별로 바꾸더라도 기간 × 크기 조합을 모두 별도 항목으로 만들지는 않는다. 같은 항목의 크기 조절로 해결해야 선택지가 불필요하게 늘지 않는다. 기존 provider 클래스 삭제·비활성화를 통한 목록 정리는 이번 추천에 포함하지 않는다.

## 구현 범위와 재사용

1. **표시 대상과 배치를 분리한다.** 기존 저장된 source 값은 유지한다. 신규 요약용 값만 명시적으로 추가하고 설정·렌더러가 같은 해석을 사용하게 한다. 현재 `WidgetSource`는 설정 파일 내부에 있고 렌더러는 문자열을 별도로 분기하므로, 공유 정의로 옮기는 범위까지는 이 변경과 직접 관련이 있다.
2. **단일 항목 렌더링에서 자동 기간 요약을 분리한다.** `renderBase`, `WidgetPresentation.toWidgetData`, 기존 달력 계산과 눈금·테마 매핑을 재사용한다. `renderLarge`를 단순히 지우면 기존 설치 위젯도 바뀌므로 아래 호환 규칙과 함께 다룬다. DB·일정 계산·반복 로직을 개편할 필요는 없다.
3. **설정 미리보기를 실제 위젯과 맞춘다.** 선택 항목·표시 방식·크기·글자 배율이 반영된 RemoteViews 렌더러를 공유한다. 현재 debug 갤러리의 `previewViews` 경로를 출발점으로 삼되 크기 결정과 표시 정책도 공유해야 한다. 독립 Compose 모형만으로 실제 배치를 검증하지 않는다.
4. **설치 후 표시 항목 변경을 지원한다.** 현재 provider XML에는 `widgetFeatures`가 없다. 재설정을 지원할 때 저장된 source·일정 ID·표시 옵션을 먼저 복원하고, 일정 목록을 읽는 동안 기존 선택을 첫 항목으로 덮어쓰지 않아야 한다. 취소하면 기존 설정을 유지한다.
5. **빈 상태에서도 위젯 목적을 유지한다.** 새 방식의 개인 일정 위젯에 대상이 없으면 ‘표시할 일정이 없어요’ 또는 ‘일정을 다시 선택해 주세요’ 상태를 제안한다. 기존 이번 달 대체 동작의 변경은 사용자 동작 변경이므로 별도 확인 범위로 기록하고, 이 조사에서 바로 수정하지 않는다.

## 기존 설치 위젯의 호환

기존 대형 위젯에서 세 기간을 보고 있는 사용자의 정보를 업데이트 직후 없애지 않는 것이 좋다. 권장 이행안은 다음과 같다.

- 기존 provider 컴포넌트와 위젯 ID, 선택 source, 일정 ID, `${id}option` 값을 유지한다. 삭제·재설치를 전제로 하지 않는다.
- 기존 인스턴스는 현재 자동 요약을 유지하고, 새로 추가하는 인스턴스부터 단일 항목/기간 요약의 명시적 선택을 적용한다.
- 이를 구별하는 위젯 ID별 표시 방식 또는 버전 값을 새로 둘 수 있다. 새 값이 없는 기존 인스턴스는 종전 표시로 해석한다. source 값이나 현재 크기만으로 신규·기존을 추측하지 않는다.
- 기존 위젯을 재설정할 때 현재 표시 방식을 미리 보여주고 사용자가 새 방식을 선택·저장하면 전환한다. 단순 진입·취소로 바뀌지 않는다. 새 키를 추가하면 위젯 삭제 시 정리도 함께 구현한다.
- 런처 목록을 나중에 목적별로 개편하더라도 기존 저장 source가 provider의 새 기본값보다 우선해야 한다. provider 재사용·추가 중 어느 쪽이 적합한지는 업데이트 설치 검수와 목록 중복 정도를 비교한 뒤 확정한다.

이 표시 방식 저장은 신규 기능의 호환을 위한 제안이다. 기존 설정 키의 이름 변경이나 DB 마이그레이션을 의미하지 않는다.

## Android 공식 문서로 확인한 구현 가능성

- Android는 설정 화면과 설치 후 재설정 방식을 제공한다. `reconfigurable` 설정과 현재 선택 복원을 함께 적용할 수 있다. 공식 Views 문서도 공통 설정 메타데이터 안내를 Glance 문서로 연결한다. **문서가 Glance 예시를 쓴다는 이유로 현재 RemoteViews 위젯을 전환할 필요는 없다.** 런처·OS별 재설정 노출은 실제 확인 대상이다. [Views 설정 안내](https://developer.android.com/develop/ui/views/appwidgets/configuration), [재설정 옵션](https://developer.android.com/develop/ui/compose/glance/configuration#enable-users-to-reconfigure-placed-widgets).
- Android 12 이상에는 크기에 맞는 여러 RemoteViews 배치를 제공하는 방법이 있다. 현재 minWidth/minHeight 기반 판정의 보완 후보이며, 공식 문서도 해당 범위 추정이 모든 상황을 다루지는 못한다고 설명한다. 이것은 크기에 맞는 배치 구현 수단이지 표시 항목을 자동으로 추가하라는 요구는 아니다. 요약 전용 배치를 구현할 때 검토하고 전체 위젯 프레임워크 교체로 범위를 확대하지 않는다. [위젯 크기별 배치](https://developer.android.com/develop/ui/views/appwidgets/layouts).

## 구현 시 검증할 조건

- 오늘·이번 달·올해·기간 요약·개인 일정 각각의 추가, 여러 인스턴스의 서로 다른 선택 유지, 크기 변경 후 표시 대상 유지.
- 기존 네 provider 위젯이 설치된 상태에서 업데이트, 기존 선택·표시 옵션 유지, 재설정 저장·취소·회전, 일정 목록을 불러오는 중 선택 보존.
- 기본 밝게/어둡게, 사용자 팔레트, 한국어/영어, 작은 크기·큰 글자·긴 일정 제목, 기간 요약의 세 값 모두 표시.
- 월말·연말·윤년·시간대 변경과 달력 의미. 현재 월·년 일수는 오늘을 제외하는 계산을 재사용한다.
- 선택한 일정 삭제·조회 오류·자동 선택 일정 없음, 위젯 삭제 시 해당 인스턴스의 설정만 정리.
- 미리보기와 실제 런처 배치의 일치, 새로고침·위젯 누르기·TalkBack, OS·런처별 크기 변경과 재설정 접근.
- 현재 provider의 정기 갱신 요청은 30분 간격이다. 내용 분리로 갱신 정확도가 향상되는 것은 아니며, 분 단위 실시간 변화나 자정 즉시 갱신을 이 변경의 효과로 약속하지 않는다. 갱신 정책 개선은 별도 범위로 남긴다.

최초 조사는 코드와 공식 문서 확인으로 진행했다. 이후 사용자가 구현을 승인하여 코드·설정·위젯 메타데이터 변경까지 진행했다. 빌드·Lint·단위 테스트·새 화면 캡처는 실행하지 않았다. 위 조건은 명시적인 최종 검증 요청 이후 확인할 목록이다.
