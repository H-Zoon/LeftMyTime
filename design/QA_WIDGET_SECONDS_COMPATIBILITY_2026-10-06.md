# 위젯 초 표시 하위 호스트 실행 검증

2026-10-05 밤~10-06. 사용자 ‘그럼 시험해 봐’ 요청으로 빌드·단위·Lint·계측과 에뮬레이터의 실제 런처 검증을 수행했다.

## 결과와 지원 범위

**문서 버전 6과 8에서 초 숫자·눈금·상태 전환이 실제로 동작했다.** 제품 지원 조건을 `API >=35`이면서 문서 `6`, `8`, 기존 `9 이상`으로 확대했다. 문서 6은 `WidgetsProfileWriterV6`, 8/9 이상은 기존 V7 생성기를 사용한다. Android 16이라는 OS 이름만으로 켜지 않는다.

일반 위젯 설정의 **‘초 단위 표시 · 실험 기능’**이 이 환경에서도 표시되며 기본값은 꺼짐이다. `WidgetSecondsPlan`, 숫자/눈금/상태 계산, `WidgetPalette`, `WidgetTextMeasure`, `TimeRulerTokens`, 공통 설정 행을 재사용한다. Android 15 시험 환경은 문서 1이어서 정적 표시를 유지한다. 실물 휴대폰은 연결되지 않았고 사용자 설치 앱을 변경하지 않았다.

**남은 결함:** 문서 8 / Pixel Launcher에서 공간 부족 안내의 접근성 노드가 `1×1px`로 보고된다. 문구는 온전히 보이고 표면의 일반 터치로 resize 액션을 실행하지만, 접근성 포커스/터치 영역은 48dp 기준을 충족했다고 볼 수 없다. 정상 숫자 위젯의 본문과 새로고침 영역은 정상 크기로 보고됐다. 전체 접근성 통과로 처리하지 않는다.

모두 별도로 생성한 임시 Pixel 6 구성, arm64, 1080×2400, 420dpi다. 기존 사용자 AVD와 데이터는 사용하지 않았다.

- 최종 명령: `./gradlew testDebugUnitTest assembleDebug lintDebug assembleDebugAndroidTest`.
- 단위 **113개, 실패 0**, debug/계측 APK 빌드 성공. Lint **오류 0, 경고 158, 힌트 7**.

- 초기 6/8: 각각 **6개 실행 통과 / 1개 조건 제외**. 9/1: 각각 **5개 실행 통과 / 2개 조건 제외**.

- 계측 범위: V6/V7 전체 제품 문서 헤더, 시스템 플레이어 최초 그리기, 한/영·글자1/2배·A/시간 보드·밝게/어둡게·250×160/320×200/400×320·오늘/시간 일정의 상태별 문서, 기존 설정 보존, 제품 경로의 오늘 미리보기, 경계 방송 중복/지연, WorkManager 복구 작업 유지/제거.
- 최초 그리기 검사는 보이는 픽셀의 존재를 검사한다. 모든 조합의 글자 배치와 접근성 품질까지 자동으로 증명하지 않는다.

앞선 [갱신 복구 수정](WIDGET_REFRESH_RECOVERY_2026-10-05.md)도 이번 검사에 포함됐다. 실제 15분 WorkManager 실행 지연·Doze·제조사 절전 정책은 미검증이다.

## 실제 홈 화면 동작

6/8 각각 10초 뒤 시작해 90초 동안 진행하는 예시를 제품 렌더러로 한 번 게시했다. 약 20초에 `am kill`로 앱 프로세스를 종료하고 이후 PID가 비어 있는 것을 확인했다. 약 42초에 화면을 끄고 48초에 켰다.

| 항목 | 문서 6 | 문서 8 |
| --- | --- | --- |
| 시작 전 | `00:05` → `00:02 until start` | `00:06` → `00:02 until start` |
| 진행 | `01:24` → `01:04` → `00:46` → `00:22` | `01:23` → `01:04` → `00:46` → `00:21` |
| 프로세스 종료/화면 복귀 | 숫자·눈금·접근성 설명 갱신 지속 | 동일 |
| 종료 후 2회 관찰 | `00:00 Finished · refresh` 유지 | 동일 |
| 눈금 | 남은 강조 영역 감소, 종료 시 중립색 | 동일 |
| 오늘/어두운 시간 보드/한국어 | `23:55:25` → `23:54:17` | `23:55:24` → `23:54:16` |

스크린샷과 접근성 XML은 순서대로 찍어 수 초 차이가 있다. 실제 수집 시각/PID는 `doc6-live-events.json`, `doc8-live-events.json`에 기록했다. 설명 갱신은 확인했으나 TalkBack 음성 출력 전체를 시험하지는 않았다.

문서 6에서는 임시 기기의 자동 시각을 끄고 `2026-10-06 23:59:50`으로 설정했다. 오늘이 `0:00:07`, `0:00:01`을 거쳐 다음 날 `23:59:56`, `23:59:48`로 다시 시작했다. 이후 실제 시각과 자동 시각을 복구했다. 정확히 0초인 한 프레임은 이 수집 간격에서 포착하지 못했으며 자정/0초 계산은 별도 단위·고정 프레임 범위다. 문서 8에서 기기 시각을 바꾸는 자정 시험은 별도로 하지 않았다.

## 시각·접근성·갱신 비용

- 실제 화면으로 밝은 A 진행/종료, 어두운 시간 보드 오늘, 한국어 긴 제목·글자2배를 확인했다. 문서6의 큰 런처 슬롯에서는 줄바꿈한 제목·숫자·눈금·시각 라벨이 함께 보였다. 문서8의 작은 슬롯에서는 숫자를 축소하지 않고 확대 안내가 표시됐다.
- 정상 숫자 위젯의 새로고침 접근성 영역은 **126×126px = 48×48dp**이며 본문은 별도 큰 영역이다.
- 문서8 확대 안내는 재게시와 새 위젯 추가 모두 접근성 **1×1px**였다. 중앙 일반 터치의 `Probe action: resize`는 확인했다. Row 감싸기·표면 의미 결합·초 틱 추가는 개선 효과가 없어 최종 코드에서 제거했다. 불필요한 상시 갱신/미검증 레이아웃 우회를 남기지 않았다. 원인은 확정하지 않았고 이 분기 자체는 변경 전 코드와 동일하다. 문서9의 같은 현상은 추가 확인이 필요하다.
- 오늘 게시 후 약65초간 런처 전체 프레임 수는 문서6 **142**, 문서8 **116**이었다. 연속30/60fps 수준은 아니지만 정확히1fps를 보장하지 않는다. 런처 시계 등 다른 요소·소프트웨어 GPU 비용이 포함된다. 배터리 소모량이나 저사양 기기 CPU 검증으로 해석하지 않는다.
- 모든 런처·회전·TalkBack·빈/오류 화면·팔레트를 시각 통과로 확대하지 않는다. 빈/오류 일정은 초 계획에서 제외하는 기존 규칙을 유지했다.

## 재현과 남은 검수

probe는 Activity가 실제 생성된 뒤 홈으로 보내야 한다. 기존 task만 앞으로 가져오거나 cold start 직후 즉시 HOME을 누르면 새 예시가 게시되지 않을 수 있어 `-W -f 0x10008000`을 사용한다.

```sh
adb shell am start -W -f 0x10008000 -n com.devidea.timeleft/com.devidea.timeleft.design.WidgetSecondsProbeActivity --es mode production --es source custom --ei start_delay 10 --ei seconds 90 --ez pin true
```

최초 추가 후 재시험에는 `--ez pin true`를 뺀다. 나머지 옵션은 [구현 기록](WIDGET_SECONDS_COMPATIBILITY_2026-10-05.md)을 따른다. 초기 로그의 `candidate`/제품 비활성은 승격 전 APK이며 최종 APK에서는 6/8도 `production`이 활성화된다.

남은 우선순위는 확대 안내 접근성 영역, Samsung 등 실물 런처/전력, 하위 호스트 재부팅·시간대/DST, 반복/자동 다음 일정의 장시간 실제 게시다. DB·기존 일정·출시 버전은 바꾸지 않았다. 커밋·스토어 배포·사용자 휴대폰 설치는 하지 않았다.

최종 debug APK: `app/build/outputs/apk/debug/app-debug.apk`, SHA-256 `6e90a565df766684add4223f64d74cbea41c155027a95c0a7707757431eb1c37`. 계측 APK SHA-256 `3a336580aea5bdfe5835c10b76f7043dc8659a059ec60de11579750d5a8abdb9`. 검사 요약/로그는 `design/qa-seconds-2026-10-05/final-results.json`, `final-build.log`에 보존했다. 임시 AVD4개는 종료·삭제했고 기존 사용자 AVD는 보존했다. 추가한 공식 SDK 이미지는 다음 검수에 사용할 수 있도록 남겼다. `git diff --check` 통과.
