# 홈·전체 일정 정렬 / 아이콘 광학 보정 / 6.5(22) 서명 빌드

사용자 요청: 버전을 올려 서명 빌드하되, 먼저 홈·전체 일정에서 어긋난 왼쪽 정렬선과 왼쪽으로 치우쳐 보이는 아이콘을 보완한다.

## 적용

- `TimeLeftUnderlineTextField`의 가로 내부 여백을 제거했다. Material의 라벨·밑줄·포커스 처리를 재사용하고, 전체 일정 검색 아이콘은 오른쪽으로 옮겨 검색 문구·입력값이 목록과 같은 선에서 시작하게 했다. 공통 필드를 사용하는 편집/위젯 검색/문장 입력에도 적용된다.
- `TimeLeftInlineButton`으로 본문 안의 텍스트 행동을 정렬한다. 홈의 진행 중 일정 선택·집중 기록/직접 입력·빈 상태·일정 추가, 전체 일정 펼침의 상세/수정/삭제/더보기, 편집의 구간 조정/추가 설정에 적용했다. 짧은 이름도 48dp 터치 영역 안에서 왼쪽 정렬하며, 펼친 일정의 위젯 추가도 가로 여백을 없앴다. 행동 사이에는 기존 `Spacing.l`을 사용한다.
- 화면 여백·본문 서체·색·48dp 기준, 목록·FlowRow·공통 설정/입력 구성요소를 재사용했다. 대화상자 버튼·테두리/채움 버튼·칩·뒤로가기 옆 제목의 역할은 유지했다.
- 아이콘은 같은 도형을 512 좌표계에서 오른쪽 8·아래 6 이동했다. 적응형/스토어/스플래시 벡터의 `optical_alignment`가 같으며, 안전 영역 배율 안에서 적용한다. 기존 도형·그라데이션·회전축·감김 애니메이션은 유지했다. 생성기가 보정값을 읽어 PNG/WebP를 함께 갱신한다.
- 버전은 6.4(21) → **6.5(22)**. 직전 자동 Firebase 수집 변경도 이번 산출물에 포함한다. DB·일정·위젯 기능 변경은 없다.

- release 빌드의 `lintVitalRelease` 통과. 별도 전체 Lint·단위·계측 테스트는 실행하지 않았다.
- APK 서명 검증, 16KB ZIP 정렬 통과. 서명 인증서 SHA-256은 `65da43af6724aef8c7faae98adfd93be415eb6f26bc5b0a9b630227148c37456`으로 기존 업로드 키와 일치한다.
- AAB는 `jar verified`. 자체 서명/신뢰 체인/타임스탬프와 POSIX 속성에 대한 JDK 경고가 있으며, 무경고로 표현하지 않는다.

## 실제 화면 확인

기존 Pixel9Pro API37 에뮬레이터의 debug6.4(21)에서 비교 화면을 확보하고 debug6.5(22)를 갱신 설치했다. `DesignGalleryActivity`/영어 갤러리가 재사용하는 실제 화면을 확인했다. fixture는 저장하지 않으며 실제 휴대폰에는 설치하거나 데이터를 변경하지 않았다.

- 320dp, 한국어 밝게: 홈의 집중 기록/직접 입력, 전체 일정 검색·펼친 행동, 일정 제목 입력·구간 조정·추가 설정의 정렬 확인.
- 320dp, 글자1.5배: 어두운 홈·긴 제목, 밝은 빈 상태, 어두운 영어 전체 일정의 줄바꿈·검색 필드 확인. 글자 축소나 잘림으로 맞추지 않았다.
- 360dp: 겹친 진행 일정 선택의 시작선, 검색어 입력 → 검색 결과0개 → IME 검색 후 키보드 닫힘 확인.
- 전체 일정의 ‘시간 자세히 보기’와 ‘위젯 추가’는 왼쪽 x84→48px(밀도3, 내부 여백12dp 제거)로 본문 x48px과 일치했다. 화면 폭에 맞춘 행동 줄바꿈을 확인했다.
- 세 벡터의 도형·이동량 일치와 XML 파싱, 생성한 스토어/96/64/48px 아이콘의 정적 전후 비교를 확인했다. 런처별 마스크와 스플래시 중간 프레임 전체를 검수한 것은 아니다.
- 초기 캡처가 첫 화면 준비 전 스플래시를 담아, 첫 프레임·UI 트리 준비 후 다시 촬영했다. 잘못된 초기 캡처를 UI 통과 증거로 사용하지 않는다.

## 남은 범위

- 실제 제조사 기기/런처, release APK 실설치, Android8–16에서 이번 변경의 시각 검수, 전체 팔레트/2배 글자/모든 화면 전수 검수는 미수행이다.
- Firebase의 기존 선택값 조합별 업데이트·실제 서버 수신/오프라인 재전송 검증은 별도로 남는다. 이번 화면 검수는 비행기 모드에서 수행했다.
- 스토어 업로드·심사 제출·공개 정책 수정·커밋은 하지 않았다. 스토어 등록정보는 사용자가 수정한다. 업로드 대기였던 6.4(21)는 이전 파일이므로 새 AAB를 사용해야 한다.
