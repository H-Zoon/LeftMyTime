# 홈 상단의 작은 시간 흐름 영역 검토

작성: 2026-09-18. 기준 커밋: `84b9545`.
상태: **상단 세 기간 요약·하단 상세 승인 및 구현. 실제 검수 결과는 [후속 QA 기록](QA_FLOW_2026-09-18.md)으로 관리.**
사용자 결정: 탭으로 분리하지 않고 최상단의 작은 시간 흐름 요약을 적용한다. 앞서 제안한 홈의 두 탭 분리는 채택하지 않는다.

## 판단

상단의 작은 시간 흐름 영역은 개인 일정과 하루·달·년을 모두 즉시 확인한다는 제품 용도를 유지한다. ‘진행 중 개인 일정 → 달력 기간 → 다음 개인 일정’으로 읽는 기준이 교차하는 현재 구조를 ‘달력 기준 요약 → 개인 일정’의 한 방향으로 정리할 수 있다.

이 방식의 효과는 **정보를 배치하는 순서와 시각적 위계**에 달려 있다. 최상단이라 먼저 보이는 것은 불가피하므로, 크기·색·움직임을 절제하여 개인 일정의 대표 숫자가 주된 시선 대상이 되도록 해야 한다. 산만함 감소는 설계 가설이며 사용성 검증 결과가 아니다.

여기서 위젯은 앱 홈 안의 작은 요약 구성요소다. Android 런처 위젯 추가·변경이나 시스템 상태 표시줄 변경을 의미하지 않는다.

## 우선 제안

순서: **앱 제목·설정 → 시간 흐름 요약 → 진행 중인 개인 일정 → 다음 개인 일정**.

- 오늘·이번 달·올해를 하나의 낮은 영역에 동시에 표시한다.
- 개별 카드 3개로 나누지 않는다. 동일한 중립색 바탕과 글자 위계를 공유한다.
- 요약에는 이름과 남은 수치만 둔다. 세 개의 눈금·퍼센트·아이콘·초 단위 변화는 생략한다.
- ‘남은 시간’이라는 공통 라벨로 숫자의 의미를 명확히 한다. 오늘은 시·분, 달과 해는 일 단위를 사용한다.
- 개인 일정의 큰 숫자와 시간 눈금은 현재 A안의 중심 표현으로 유지한다.
- 기존에 개인 일정 사이에 있던 오늘·달·년 영역은 제거한다. 요약을 추가하고 원래 영역도 남기는 방식은 사용하지 않는다.

## 작은 영역 안의 대안

| 구성 | 장점 | 비용 | 판단 |
| --- | --- | --- | --- |
| 세 기간 동시 표시 | 조작 없이 세 값을 모두 확인. 사용자가 확인한 세 용도에 부합 | 세 숫자가 있어 위계 조정 필요. 큰 글자에서 높이 증가 | 우선 제안 |
| 선택한 기간 하나만 표시 | 가장 조용하고 낮은 높이 | 나머지 기간은 한 번 더 조작해야 확인 가능 | 비교 대안 |
| 자동으로 돌아가는 기간 표시 | 작은 영역에서 여러 값을 노출 | 읽던 값이 바뀌고 원하는 기간을 기다리게 됨 | 제외 |

선택형 대안을 채택할 경우 기존 기간 선택값을 사용한다. 세 기간 동시 표시를 채택하면 요약 자체에는 선택 상태가 없으며, 기존 선택값은 상세 보기의 마지막 기간에만 활용한다. 새 홈 탭 설정은 필요 없다.

## 권장 크기와 형태

아래 치수는 초기 검토의 시작값이다. 실제 구현은 최소 터치 영역과 내용에 맞춘 높이를 사용하며, 높이를 고정하지 않는다. 최종 서체·배치 규칙은 디자인 기준 v2를 따른다.

- 기본 글자 크기에서 총 높이 약 88–104dp를 목표로 한다. 제목 바를 제외한 요약 영역의 높이다.
- 라벨은 12–14sp, 숫자는 약 20sp, 단위는 12–14sp를 시작점으로 비교한다. 현행 `TimeLeftTheme`의 가까운 글자 역할을 우선 사용한다.
- 바탕은 기존 중립색을 사용하고, 낮은 대비의 단일 면 또는 얇은 구분선으로 하나의 영역임을 표시한다. 강한 테두리·그림자·세 개의 유색 카드·강조색 숫자는 추가하지 않는다.
- 각 기간을 누르는 영역은 최소 48dp다. 시와 분은 의미 단위로 묶어 줄바꿈한다.
- 320dp·큰 글자에서 3열이 맞지 않으면 세 기간을 `라벨 — 값` 형태의 세로 행으로 바꾼다. 높이를 고정하거나 글자를 줄이거나 기간을 숨겨서 맞추지 않는다.
- 최상단은 본문 첫 위치를 뜻한다. 목록을 스크롤하면 함께 올라간다. 계속 화면에 고정하면 목록 공간과 주의력을 지속적으로 차지하므로 첫 적용에는 고정하지 않는다.

## 눌렀을 때의 동작

각 기간을 누르면 그 기간의 남은 숫자·눈금·시작과 끝 경계를 하단 상세 패널로 보여준다. 배경의 홈은 그대로 유지하고 패널을 닫으면 같은 위치로 돌아온다.

- 예: 올해 요약을 누르면 올해의 남은 일수와 연간 눈금을 확인한다.
- 홈 안에서 큰 영역으로 펼쳐 개인 일정을 아래로 밀어내는 방식은 피한다.
- 화면 이동 또는 앱 최상위 탭 전환은 추가하지 않는다. 상세의 기간 선택은 필요할 경우에만 기존 오늘·달·년 선택을 재사용한다.
- 큰 글자에서 상세가 한 화면에 맞지 않으면 스크롤 또는 전체 높이 패널로 읽을 수 있게 한다.
- 접근성 이름은 ‘올해, 104일 남음, 자세히 보기’처럼 기간·값·행동을 묶는다. 닫으면 누른 기간 항목으로 초점을 돌린다.
- 초 단위 자동 읽기와 값 변경 애니메이션을 추가하지 않는다. 실제 시간 계산·달력 경계 의미는 유지한다.

## 개인 일정 상태에 따른 규칙

| 상태 | 시간 흐름 영역 | 개인 일정 영역 |
| --- | --- | --- |
| 진행 중 | 동일한 작은 요약 | 기존 대표 숫자·눈금, 다음 일정 |
| 여러 구간 진행 | 동일한 작은 요약 | 기존 진행 중 구간 선택 유지 |
| 진행 중 없음 | 갑자기 커지지 않음 | 다음 개인 일정 또는 진행 없음 안내 |
| 날짜 일정만 | 동일한 작은 요약 | 날짜 일정 목록을 직접 확인 가능하도록 별도 보완 후보 |
| 일정 없음 | 세 기간의 값을 계속 확인 가능 | 간결한 안내와 일정 추가 |

진행 여부에 따라 달력 기간이 큰 대표 영역으로 승격되면 화면의 중심이 계속 바뀐다. 작은 요약의 역할은 상태와 관계없이 유지하고, 달력 정보만 자세히 보려는 사용자는 상세 패널에서 크게 확인하도록 제안한다.

날짜 일정을 홈에서 직접 보이게 하는 개선은 사용자 일정 접근성 문제다. 상단 요약의 효과와 함께 한꺼번에 평가하지 않도록 별도 변경으로 다룰 수 있다.

## 예상 효과와 위험

- 두 정보를 보는 데 최상위 화면 전환이 필요 없다. 위쪽에는 달력의 맥락, 그 아래에는 개인 일정이 연속으로 이어진다.
- 세 기간이 모두 자주 쓰인다는 사용자 설명을 반영한다. 월·년을 설정 또는 더보기 속으로 옮기지 않는다.
- 상단이 너무 화려하거나 높으면 개인 일정의 첫인상이 약해진다. 요약 영역에는 큰 숫자·눈금·진행 링을 반복하지 않는다.
- 큰 글자에서 요약이 길어져 개인 일정이 아래로 내려갈 수 있다. 실제 작은 화면에서 가독성과 첫 화면 정보량을 함께 검수해야 한다.
- 기간 상세를 자주 열어야 한다면 작은 표시가 부족하다는 신호다. 사용자 확인 후 단일 기간 표시나 더 큰 요약을 재검토하며, 숨김 설정을 먼저 늘리지는 않는다.

## 적용과 검증 순서

1. 세 기간 표시와 단일 기간 표시를 같은 개인 일정 데이터로 비교한다. 이번 대화 시안은 구조 설명용이며 앱 화면 검수를 대체하지 않는다.
2. 사용자가 형태를 선택하면 디자인 기준 v2의 홈 순서와 진행 없음·빈 상태 규칙을 함께 갱신한다.
3. 기존 기간 데이터와 시간 포맷을 재사용해 요약 구성요소를 만들고, 홈 가운데의 기존 기간 영역을 대체한다. 상세 패널은 `RemainingTimeText`와 `TimeRuler`를 재사용한다.
4. DB·기존 설정 키·반복·알림·런처 위젯 설정은 변경하지 않는다. 날짜 일정의 홈 표시 보완은 필요하면 별도 변경으로 진행한다.
5. 320dp·기본/큰 글자·한/영·밝게/어둡게, 23시간 59분·세 자리 일수·자정 경계·빈 일정에서 실제 화면 확인. 후속 사용자 지시에 따라 빌드·테스트·Lint는 모든 수정사항 반영 후 명시적인 최종 검증 요청이 있을 때만 수행한다.

완료 판단은 ‘진행 중 일정의 남은 시간과 오늘·달·년을 빠르게 찾는가’, ‘서로 다른 숫자의 의미를 혼동하지 않는가’, ‘상세를 닫으면 원래 일정으로 자연스럽게 돌아오는가’다. 단순히 화면에 들어가는 것만으로 완료로 보지 않는다.

## 큰 배치를 유지한 노출 개선 — 후속 검토

사용자 요청: 상단 시간 흐름 → 개인 일정 → 다음 일정의 큰 배치를 유지하면서 더 나은 노출을 검토한다. 상단 면·라벨·상세 진입은 후속 승인 범위다. 다음 일정의 숫자 축약은 제안으로 남긴다.

### 1. 상단을 별도의 카드보다 조용한 정보 띠로

기존 시안의 회색 면을 걷어내고 같은 화면 바탕에서 얇은 구분선과 간격으로 묶는 구성을 우선 비교한다. 큰 배치·세 기간의 위치·값은 유지한다. 채워진 면의 존재감이 줄어 개인 일정의 대표 숫자가 상대적으로 더 두드러질 것으로 예상한다. 이는 아직 사용자 검증이 필요한 디자인 가설이다.

- 제목은 ‘남은 시간’ 하나로 줄인다. ‘시간 흐름 · 남은 시간’의 이중 설명은 제거한다.
- 세 기간의 숫자는 같은 크기·같은 중립색으로 유지한다. 오늘이 더 많이 쓰인다는 근거 없이 오늘만 크게 하거나 월·년을 흐리게 만들지 않는다.
- 각 값에서 숫자와 단위를 분리하되 ‘9:42’처럼 시각과 남은 길이가 혼동되는 표기는 피한다.
- ‘자세히’ 행동을 요약의 제목 행에 표시해 누를 수 있다는 단서를 제공한다. 각 기간을 눌러도 해당 기간 상세가 열린다. 별도의 화면 이동은 추가하지 않는다.
- 큰 글자·작은 화면에서는 행으로 재배치한다. 촘촘한 한 문장으로 압축하는 안은 읽기와 터치 구분이 약해져 우선안으로 삼지 않는다.

### 2. 큰 숫자가 답하는 질문을 고정

현재 진행 중인 개인 일정의 대표 숫자는 종료까지 남은 시간을 뜻한다. 그 위의 일정 제목·‘진행 중’·종료 시각이 이 숫자의 맥락을 만든다. 기간 요약은 그보다 작은 기준 정보로 남긴다. 일정 종료 시 상단 기간을 갑자기 확대하거나 순서를 바꾸지 않는다.

### 3. 다음 일정의 중복 숫자를 줄임

현재 다음 시간 구간에는 시작–종료 시각과 시작까지 남은 길이가 함께 있다. 최초 요약에서는 ‘저녁 독서 / 5시간 42분 후 시작’처럼 **남은 길이와 다음 행동의 관계 하나**를 우선 제안한다. 시작–종료 시각은 행을 펼쳤을 때 확인한다.

- ‘남음’과 ‘시작까지’가 비슷한 크기로 반복되는 대신 진행 중은 ‘남음’, 예정 구간은 ‘후 시작’으로 읽는 의미를 구별한다.
- 정확한 시작 시각으로 일정을 훑는 사용자에게는 추가 조작이 생긴다. 비교안으로 ‘저녁 독서 / 20:00 시작’을 제시할 수 있으나, 앱의 남은 시간 중심 용도에 맞춰 상대 시간 표기를 먼저 검토한다.
- 날짜 일정은 기존 D-day 표시를 유지한다. 서로 다른 정보인 날짜와 남은 날짜를 무조건 동일한 축약 규칙으로 없애지 않는다.
- 변경은 요약의 표시 수준에 한정하며 시작/종료 데이터, 편집, 상세 접근을 보존한다.

### 4. 한 번에 바꾸지 않고 비교

먼저 상단 면·중복 라벨·상세 진입 단서만 비교하고, 다음 일정의 숫자 축약은 별도 비교한다. 시안에서 회색 면 유지/구분선 구성과 예정 구간의 상대 시간/절대 시각을 선택할 수 있게 한다. 실제 적용 시에는 각각의 변화가 ‘읽을 숫자를 줄였는지’와 ‘필요한 정보를 찾는 탭을 늘렸는지’를 함께 확인한다.

기본 권장 조합은 **구분선으로 묶은 세 기간 요약 + 개인 일정의 큰 남은 숫자 + 예정 구간의 ‘후 시작’ 요약**이다. 숨김·자동 순환·자동 강조·새 최상위 탐색은 추가하지 않는다.


## 후속 보완 — 상세 진입 힌트

최종 사용자 선택은 공통 ‘자세히’ 버튼을 없애고 ‘각 기간을 누르면 자세히 볼 수 있어요’ 안내를 두는 것이다. 오늘·이번 달·올해 항목 전체를 누르면 해당 기간을 연다. 반복되는 화살표가 산만하다는 후속 피드백에 따라 화살표는 제거하고 공통 안내만 남긴다. 마지막 기간의 저장·복원 동작을 제거하며 기존 설정 데이터는 삭제하지 않는다. 위의 공통 상세 버튼·기억 동작은 이전 검토 기록으로 대체되었다.
