## 검증 원칙

- 기존 리뷰의 빌드/캡처를 새 변경의 검증으로 재사용하지 않는다.
- 사용자 승인 범위에서 빌드·에뮬레이터 사용을 진행한다. 단위 테스트·Lint 실행은 별도 명시 요청 전 보류한다. 필요한 테스트 소스와 미실행 조건을 남긴다.
- 알림: 권한 비활성 편집→재허용, 알림 없음 명시 선택, 날짜 반복 앱 미실행, 시각/시간대/부팅, 중복/삭제/수정 후 오래된 수신.
- 입력: 수정 없는 이탈, 수정 후 취소/버리기, 시스템 뒤로, 회전, 저장 중 중복 동작, 한/영 12/24시간.
- 신규 데이터: 기존 DB 이행·기존 일정 보존·중복 복구·잘못된 파일의 원자적 거부. 제외된 기기 동기화의 삭제 전파·충돌 검증은 이번 완료 조건에서 제외한다.
- UI: 밝기, 320dp, 1.5배 이상 글자, 긴 제목, 빈/실패 상태, 실제 4×2/4×1 위젯. 새 캡처는 Git 제외 `design/qa-*/`에만 둔다.

## 결정

- 기본 A안과 기존 저장 키를 보존한다. 새 계절/레이아웃은 명시적 선택으로 추가한다.
- 반복 날짜의 다음 회차를 보여주는 것은 읽기 전용 계산으로 바꾼다. 알림은 원본 일정과 현재 시각으로 다음 발생을 직접 계산하며 화면 진입을 기다리지 않는다.
- 기본 홈 요약 세 항목을 일괄 늘리지 않는다. 신규 기간은 사용자가 선택한다.
- ‘검수 완료’는 실제 수행한 범위에 한해서 기록한다.

## 1차 적용과 실행 근거

- 알림: `ReminderPlanner`가 다음 발생을 순수 계산한다. 화면·위젯의 조회는 읽기 전용 `currentOccurrence`를 사용한다. 앱 프로세스의 데이터 관찰, 각 화면 복귀, 부팅/시간 변경/시간대 변경/업데이트에서 예약을 관리한다. 수신 시 저장된 최신 일정과 예약 서명을 확인하고 중복 수신을 제거한다. 알림 진입은 공통 일정 상세다.
- 편집: 선택한 알림은 권한 거부/설정 취소/제목 수정에서 보존한다. 변경 비교와 이탈 확인, 저장 중 뒤로 차단을 적용했다. 앱·위젯·입력·눈금·설정의 실제 시각 표시가 공통 포매터를 사용한다.
- 백업: Room 8→9는 기존 ID를 보존하며 안정 식별자/수정 시각/삭제 표시만 추가한다. JSON v1은 일정만 포함한다. 파일 크기·형식·날짜·중복 식별자를 검증하고, 복구는 트랜잭션으로 적용한다. 미리보기 이후 DB가 달라지면 재확인한다. 동일 파일 재복구는 중복을 만들지 않는다. 삭제 표시는 후속 동기화의 삭제 전파 기반이며 사용자가 삭제한 일정은 일반 조회에서 제외한다.
- 빌드: 첫 시도에서 테마 견본의 필수 눈금 라벨 누락을 발견·수정. 이후 `assembleDebug` 성공(20초). 기존 경고 5개 유지. 이후 코드 보완은 다음 빌드 대상이다. 단위/Lint/계측 테스트는 미실행.
- 에뮬레이터: 기존 앱을 제거하지 않고 갱신. DB 9 열기, 날짜 테스트 일정 생성, 수정 후 ‘계속 수정’과 ‘버리기’, 원본 제목 보존을 확인했다. 백업 파일 생성, 동일 파일 복구(변경 0개), 충돌 미리보기(1개), 파일 버전 선택 후 복구(변경 1개)를 확인했다. 실제 테마 화면 첫 화면에서 오늘의 숫자·눈금과 선택 도구가 함께 보인다.
- 권한 비활성 상태의 복구 알림 값(0)과 안내 문구를 확인했다. 비활성 상태에서 제목 수정·저장 후 보존 및 권한 복귀 예약은 아직 미확인이다. 일부 에뮬레이터 터치가 반영되지 않아 반복 시도했으며, 이 현상을 원인 규명 없이 앱 또는 기기 문제로 단정하지 않는다.
- 테스트 소스 추가: 반복 날짜의 다음 회차, 조기 알림, 매월 31일, 단발 만료, 자정 이전 알림, 시간대, DST, 잘못된 입력, DB 식별자 이행. 아직 실행하지 않았다.
- 캡처: `design/qa-improvements-2026-09-25/02-discard-confirmation.png`, `03-backup-preview.png`, `04-theme-live-sample.png` (기본 폭/영문/라이트). 첫 `01-editor.png`는 입력 과정이며 완료 근거가 아니다.

남은 검수: 320dp·1.5/2배 글자·다크, 파일 손상/중복/오래된 미리보기/실패 롤백·삭제 항목 복원, 실제 알림 수신/권한 복귀/부팅·시간대·앱 미실행 반복. 에뮬레이터의 임시 `QA_Restored` 일정과 Downloads 내 QA 백업 파일은 후속 검수 완료 후 제거할 것.

## 시간 구간·집중 세션 적용

- Room 9→10은 반복 요일(기존 매일=127)과 명시적 다음 날 종료(기존 false)를 추가한다. 10→11은 일회성 집중 상태·절대 종료 시각·실행 누적/정지/남은 시간을 추가한다. 기존 Time 항목을 세션으로 재해석하지 않는다.
- `ScheduledTimeWindow`는 시작일의 요일을 기준으로 어제~다음 주의 유효 구간을 찾고 실제 시간대의 instant 차이로 계산한다. 앱 숫자·상세·자동 선택 위젯·알림 계획이 이를 공유한다. 이전 역순 시간은 여전히 잘못된 구간이며 자동으로 야간 구간이 되지 않는다.
- 일회성 집중은 15/25/50분 또는 1~1,440분을 한 번 실행한다. 실행/일시정지/완료/중도 종료를 저장한다. 동시에 실행하는 세션은 하나이며 일시정지는 집계에서 제외한다. 백업 시 실행 중인 세션은 일시정지한 복사본으로 내보내 타 기기에서 자동 실행되지 않게 한다.
- 집중 화면은 큰 숫자·공통 눈금, 상태별 행동, 화면 켜짐 선택을 제공한다. 화면 켜짐은 이 화면이 보이고 실행 중일 때만 적용하고 종료/이탈 시 해제한다. 주간 기록은 월요일~일요일에 종료한 세션의 타이머 실행 시간이며 실제 업무 수행을 측정한 값으로 주장하지 않는다.
- 정확한 종료 알람은 시스템 특별 접근을 사용자가 직접 허용할 때 사용한다. 거부 시 일반 알람으로 예약하며 앱이 닫혔을 때 늦게 도착할 수 있음을 설명한다. 알림 권한과 정확한 알람 접근은 구별한다.
- `assembleDebug` 성공(25초). 기존 경고 5종 유지, 단위/Lint 미실행. DB 9에서 새 APK 갱신·앱 열기 성공. 실제 23:56→다음 날 00:11의 15분 세션 시작과 초 감소·일시정지를 확인했다 (`05-focus-running.png`).

추가로 검증/보완할 조건: 수동 시스템 시각 변경 시 집중 타이머의 길이 유지(현재 절대 시각 기반), 재부팅·정확 알람 접근 취소, 여러 회차 종료 알림 중복/누락, 백업의 세션 정합성, 큰 글자 집중 화면. 아직 전체 완료가 아니다.

- 집중 후속 실행: 일시정지 후 프로세스를 종료·재실행해 같은 14분 54초가 보존됨을 확인. 계속하기 후 중도 종료 확인을 거쳐 기록 화면에서 중도 종료 1회·실행 21초를 확인했다 (`06-focus-history.png`). 종료 화면이 0초만 보여주는 점을 발견해 실행 시간을 주 숫자로 보이게 보완했고, 집중 눈금은 실제 벽시계 시각 대신 0분~목표 길이로 표시해 일시정지 제외 계산과 일치시켰다. 이 마지막 표시 보완은 다음 빌드/실행 검수 대상이다.

## 이야기·입력 틀·대표 선택 적용 (2026-09-26)
