# 위젯 표시 항목 분리 — 구현 기록과 검증 대기

작성: 2026-09-18. 사용자 승인: ‘변경 진행’.
상태: **코드 반영 / 빌드·Lint·단위 테스트·실제 화면 및 동작 검수 미실행**.

## 바뀐 동작

- 표시 항목: 오늘 / 이번 달 / 올해 / 기간 요약 / 곧 다가오는 일정 / 내 일정. 개별 항목의 크기를 늘려도 다른 기간이 자동으로 붙지 않는다.
- 기간 요약은 세 기간을 함께 표시한다. 같은 색·글자 위계를 사용하며 실제 문구·글자 배율을 측정해 가로 또는 세로로 배치한다. 숫자와 단위를 붙여 읽을 폭을 확보한다. 모두 표시할 공간이 없으면 ‘크기를 늘려 주세요’ 안내를 사용한다.
- 기존 provider 네 개와 크기 선택 목록을 유지했다. 항목별로 런처의 최소 크기를 바꿀 수 있는 구조가 아니므로, 요약 선택은 모든 크기에서 저장할 수 있고 부족한 공간은 명시적 확대 안내로 처리한다. 사용자는 설정 안내를 읽고 홈 화면에서 크기를 조정할 수 있다. 이번에 고정된 칸 수를 최소 요약 크기로 확정하지 않았다.
- 기존 설치 위젯은 자동 보조 기간 표시를 유지한다. 재설정에서 ‘큰 위젯에 기간 요약 함께 표시’를 끄거나 다른 표시 항목을 선택·저장하면 새 방식으로 전환한다. 단순 설정 진입·취소는 저장하지 않는다.
- 새 방식의 개인 일정 위젯에서 일정이 없거나 조회에 실패하면 안내를 표시한다. 이번 달로 바꾸지 않으며, 조회 실패만으로 저장된 일정 ID를 지우지 않는다. 종전 방식에서는 기존 이번 달 대체 동작을 유지한다.
- 설정 미리보기·debug 갤러리·실제 위젯은 `AppWidget.createViews`를 공유한다. 설정은 런처가 전달한 크기로 미리보기를 배치하며 화면보다 넓으면 가로로 스크롤한다. 실제 갱신 시점과 미리보기 시점의 시간 값은 달라질 수 있다.
- 미리보기는 기존 반복 계산기를 이용해 다음 반복 회차의 사본만 표시한다. 설정 진입이나 취소로 일정 데이터를 저장하지 않는다. 설치 위젯의 기존 반복 갱신·저장은 그대로 유지한다.
- 기존 설정 source·일정 ID·남은 시간 표시 옵션을 복원한다. 목록 로딩 중 또는 저장된 일정 삭제 후 다른 일정으로 자동 교체하지 않는다. 선택한 일정이 없는 상태에서는 저장을 막고 다시 선택하도록 한다.
- 기존 네 provider에 재설정 메타데이터를 추가했다. 실제 재설정 메뉴 제공은 OS·런처에 따라 확인해야 한다.

## 공통 구성요소와 저장 호환

재사용: `ItemGenerate`, `TimeProgressCalculator`, `NextCountdownSelector`, `formatRemainingTime`, `WidgetPresentation`, `ThemePalette`, 기존 숫자·눈금 렌더러와 단일 항목 XML. 설정은 `TimeLeftTheme`, `TimeLeftSection`, `Spacing`, `LayoutTokens`를 사용한다.

`WidgetSource`, `WidgetConfiguration`, `WidgetDimensions`를 설정과 렌더러에서 공유한다. 기존 `${id}` source 키와 `${id}option` 키는 그대로 읽고 쓴다. 신규 요약 source는 `calendarOverview`, 신규 표시 방식 키는 `${id}displayMode`다. 표시 방식이 없는 기존 위젯은 `legacy`, 신규 설정 저장은 `focused`를 사용한다. 기존 표시 유지를 선택하면 `legacy`로 저장한다. 삭제 시 해당 ID의 세 키를 정리한다. DB 스키마·사용자 일정·provider 클래스 이름·앱 버전은 바꾸지 않았다.

요약 전용 `app_widget_overview*.xml`의 치수는 [디자인 기준](DESIGN_SYSTEM.md)에 기록했다. 측정 코드와 XML의 글자·여백·글꼴이 함께 바뀌어야 한다. 보수적인 여유 4dp를 측정에 추가했고, 가로 열은 64dp 이상이면서 숫자·단위 묶음이 들어갈 때 사용한다. 이 수치는 실행 검수로 확정된 최소 칸 수가 아니다.

## 코드·문서 검토 범위

저장·읽기·삭제 사용처, 미리보기와 실 렌더러 호출, 문자열 리소스의 한국어/영어 대응, 레이아웃 XML, 이전 상태와 새 상태의 분기를 코드로 검토했다. XML 파싱·문자열 참조·문서 링크·diff 형식 확인을 수행했으며 오류를 발견하지 않았다. 이 확인은 빌드나 Lint를 대신하지 않는다. 런처가 같은 RemoteViews 레이아웃을 재적용할 수 있어 빈 상태 이후 정상 데이터로 돌아올 때 숫자 서체 크기·줄 수·눈금 표시도 매번 설정하도록 했다.

현재 설치 APK는 이 변경을 포함하지 않는다. 기존 위젯 비교(이전 캡처), 기존 큰 위젯(이전 캡처), 기존 설정(이전 캡처)은 변경 전 참고 자료다. 변경 후 이미지는 명시적인 최종 검증 요청 후 생성해야 하며, 여기서는 시각 검수 완료로 표시하지 않는다.

## 최종 검증 요청 시 확인

- source 여섯 종류의 신규 설치·독립 선택·크기 변경. 오늘/달/년 단일 위젯에 자동 요약이 생기지 않고 요약은 세 기간을 유지하는지 확인.
- 기존 APK에서 만든 네 provider와 모든 source·표시 옵션을 유지한 채 업데이트. 기존 표시 유지 → 설정 취소 → 설정 저장 → 새 방식 전환을 각각 확인.
- 재설정 시 기존 일정 ID·표시 방식·옵션 복원, 로딩 중 저장, 회전, 삭제된 일정, 로딩 오류, 위젯별 설정 격리·삭제 정리. 새 방식 전환 이후 취소로 이전 값이 훼손되지 않는지, 빈 상태가 정상 데이터로 바뀔 때 숫자·눈금이 복구되는지 확인.
- 밝게/어둡게·기존 팔레트·한/영·1/1.5/2배 글자·긴 제목·빈 상태·최소 및 큰 위젯. 큰 글자에서 요약의 확대 안내가 적절한 시점에 나타나고 충분히 키우면 세 기간이 돌아오는지 확인.
- 요약의 문자 측정과 실제 RemoteViews 높이 비교. 단위 분리, 글자 잘림, 접근성 이름, 새로고침·앱 열기와 OS/런처별 재설정 접근.
- 날짜 반복의 오래 지난 회차, 월말·연말·윤년·시간대, 미리보기 사본 계산과 실 렌더러 결과, 설정 취소 후 DB 불변.
- 저장된 source·신규 키 판정·크기 분기·빈 상태·미리보기 반복 사본을 위한 의미 있는 동작 테스트를 최종 검증 범위에 포함한다. 이번에는 테스트를 추가하거나 실행하지 않았다.

실제 렌더러를 사용하는 debug 진입 예: `widget-today-large`, `widget-month-small`, `widget-year-wide`, `widget-overview-large`, `widget-overview-medium`, `widget-overview-small-min`, `widget-legacy-large`, `widget-missing-large`. 기존 갤러리의 테마·언어·글자 배율 옵션과 함께 사용한다. 갤러리 진입을 추가한 사실 자체가 실행 결과는 아니다.

## 남은 범위

- 크기 판정은 기존 런처 minWidth/minHeight 경로를 공유한다. Android 12 이상의 정확한 크기별 RemoteViews 묶음 전환은 이번에 도입하지 않았다. 가로 화면·폴더블·여러 런처의 크기 해석은 미검증이다.
- 이 단계에서는 런처 목록과 PNG를 유지했다. 이후 승인된 [선택 UI·용도별 런처 개편](QA_WIDGET_SELECTION_2026-09-18.md)에서 이름·기본값·미리보기를 변경했으며, 현재 적용 상태와 검수 조건은 후속 기록을 따른다.
- 30분 정기 갱신 요청은 유지한다. 초/분 단위 실시간 표시나 자정 즉시 갱신을 보장하는 변경은 아니다.
