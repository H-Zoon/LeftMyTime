# 상세 인터랙션 적용 · 검수 대기

2026-09-23. 사용자 승인: ‘추가로 추천하는 재미까지 포함하여 전부 코드에 반영 진행’.

상태: **코드·리소스·문서 정적 검토 단계. 빌드·Lint·단위 테스트·새 APK 설치·시각/제스처/햅틱 검수 미실행.** 기존 설치 앱과 과거 캡처는 이번 코드를 확인하는 근거가 아니다. 최종 검증은 사용자가 명시적으로 요청한 뒤 진행한다.

## 사용자 검수 후 곡선 보완

사용자가 기존 인터랙션의 ‘검수 완료’를 알렸다. 검수 기기·조건이나 빌드/Lint/테스트 결과는 공유되지 않아 아래 전체 조건의 통과로 확대하지 않는다. 후속 요청에 따라 숫자 진입 곡선을 `LinearOutSlowInEasing`에서 Android `AccelerateDecelerateInterpolator`를 연결한 `Motion.DetailEntranceEasing`으로 변경했다. 시작/끝을 느리게, 중간을 빠르게 하며 480ms와 기존 한 번 재생 규칙을 유지한다. 이번 곡선 변경은 코드·공백 검토만 했으며 빌드·Lint·단위 테스트·실화면 재검수는 실행하지 않았다. 다음 확인은 날짜의 적은 숫자 차이와 시·분·초 표시에서 목표에 정착하는 감각, 시스템 모션 비활성화 동작이다.

추가 피드백 ‘감속 값이 좀더 커야 될것같아’에 따라 최종 곡선을 `CubicBezierEasing(0.2, 0, 0.1, 1)`로, 시간을 480→800ms로 조정했다. 짧은 가속 뒤 긴 감속을 두어 목표값 근처의 감소를 강조한다. 공통 `Motion`만 조정하며 기존 숫자 계산·1회 진입·모션 비활성화 처리를 재사용한다. 이 후속 조정 역시 코드·공백 검토만 진행했으며 빌드·Lint·단위 테스트·실화면 확인 전이다.

최신 사용자 요청에 따라 숫자 진입 시간을 800→1200ms로 변경했다. 기존 감속 곡선은 유지하며 이 시간 조정의 빌드·Lint·단위 테스트·화면 재검수는 실행하지 않았다.

## 값의 차이와 시간 단위에 따른 감속 보정

사용자 피드백: 이번 달은 감속이 보이지만 오늘·올해는 약하게 느껴짐. 코드상 동일한 곡선/1200ms에 날짜 차이 전체를 넣거나 총 초를 시·분·초로 분해하던 표시를 보정했다. 전체 재생 시간은 1200ms다.

- `RemainingTimeEntrance`: 날짜는 앞 480ms에 목표+6으로 접근하고 뒤 720ms에 마지막 6개 숫자를 하나씩 내린다. 차이가 6 이하면 전체 시간을 사용한다. 종료 직전 반올림으로 목표에 일찍 도달하지 않도록 올림하며, 제곱 감속으로 숫자가 바뀌는 간격이 늘어난다.
- 기대 예시(고정 목표): 이번 달 `30 → 13 → 12 … 7`, 올해 `365 → 105 → 104 … 99`. 뒤 6단계는 같은 시간 배분이다. 차이가 0이면 연출하지 않고, 1이면 중간 정수가 없으므로 한 번의 전환만 있다.
- 오늘은 시·분·초의 유효한 시작/목표에 같은 보정을 적용하고 총 초 하나로 합쳐 기존 숫자 표시를 재사용한다. 기대 예시: `23:59:59 → 15:48:41 → 14:47:40 … 09:42:35`. 빠르게 여러 번 순환하던 분·초가 목표 방향으로 감소한다.
- `1:00:00 → 0:42:35`처럼 하위 단위의 시작 숫자가 목표보다 작으면 첫 15%(180ms)에 `0:59:59`로 빌려 내려온 후 보정한다. 빌린 값이 이미 목표이면 전체 차이를 직접 표시한다. 시작값·중간값은 실제 최대를 넘거나 목표 아래로 내려가지 않는다.
- 진입 계획은 첫 목표로 고정하고 표시 시 최신 실제값과의 차이를 반영한다. 초 틱으로 계획을 다시 시작하지 않으며 완료 후 실제값으로 연결한다. 접근성·보조 현재값·눈금·이야기 선택은 계속 원본값을 사용한다.
- `Motion`에 1200ms, 마지막 최대 6단계, 접근 40%, 단위 빌림 15%를 모았다. 기존 공통 상세·`RemainingTimeText`·시스템 모션 비활성화·1회 재생 처리를 재사용한다.

이번 보정은 코드의 범위/분기·사용처·공백을 정적으로 검토했다. **빌드·Lint·단위 테스트·실화면 검수는 실행하지 않았다.** 위 예시는 코드의 기대 동작이며 실행 검수 결과가 아니다. 최종 요청 시 60/120Hz에서 마지막 숫자의 식별, 차이 0/1/6/7/23/266, 28/29/30/31/365/366, 시/분 빌림 및 하위 단위 일치, 1초/1분/1시간 경계, 진입 중 실시간 감소/종료, 모션 배율 0/0.5/1/2를 확인한다. 밝게/어둡게·320dp·큰 글자·한/영·긴 제목·빈 상태의 기존 검수 범위도 유지한다.

## 사용자에게 달라지는 점

| 위치/행동 | 반영 내용 |
| --- | --- |
| 오늘·이번 달·올해 상세 열기 | 실제 전체 길이에서 현재 남은 길이로 1200ms 숫자 진입. 활성 범위에만 한 번 실행 |
| 개인 일정 | 대표 구간 하단, 펼친 일정 목록에 ‘시간 자세히 보기’. 기간과 동일한 상세 시트 사용 |
| 상세 눈금 탭/가로 드래그/가로 휠 | 별도 탐색선과 시각/날짜별 남은 길이. 큰 현재값·실제 색·글로우는 계속 현재 기준 |
| 현재 복귀 | 선택을 유지하다 ‘현재로 돌아가기’로 해제. 현재 근처 6dp/폭 2% 이내에 약한 자석 반응 |
| 눈금 조작 | 주변 28dp 안의 눈금이 최대 4dp 반응. 주요 간격·현재 위치에 최소 120ms 간격의 시스템 햅틱 |
| 이야기 넘김 | 기존 버튼 및 본문 좌우 스와이프. 180ms, 8dp 이동/페이드. 후보·선택은 읽는 동안 유지 |
| 총 초 보기 | 시간 상세의 ‘초로 보기’ ↔ ‘시·분·초로 보기’. 날짜 일수는 환산하지 않음 |

실제 최대값은 28/29/30/31일·365/366일, 오늘 23:59:59, 일정의 원래 길이에서 얻는다. 시·분·초는 하나의 표시용 총 초에서 파생한다. 상세에서는 전체 구간의 가장 큰 단위를 유지해 1시간→59분 같은 경계에서도 숫자 그룹 수가 바뀌지 않는다. 1시간 구간이 42분 남으면 `0시간 42분 00초`로 표시한다. 날짜의 366→99도 예약한 자리 폭/서체를 유지한다. 실제값은 숫자 연출 중 보조 문구·접근성에도 제공된다.

홈의 상시 숫자와 위젯 비트맵은 이 진입 효과를 쓰지 않는다. 설치 위젯은 기존 탭으로 앱 상세를 연다. 원형 회전·관성 테이프·일정 편집 제스처는 이번 추천안에 포함되지 않은 대안이다.

## 재사용과 상태 소유

- `TimeDetailSheet`는 기존 기간 시트의 배치·스크롤·큰 글자 보존·위젯 추가 버튼을 추출해 개인 일정에서도 재사용한다. `TimeDetailContent`는 위젯에서 연 앱 상세와 계속 공유한다.
- `InteractiveRemainingTime`은 `RemainingTimeText`에 표시용 값/자리 폭/단위 기준만 전달한다. 원본 `AdapterItem` 값과 접근성 설명을 바꾸지 않는다. `rememberSaveable` 진입 상태로 초 틱·회전·복귀에서 재연출하지 않는다.
- `TimeDetailFacts.range`와 `TimeDetailRange`는 원본 날짜/시각/해당 날짜를 전달한다. 실제 기간을 키로 삼아 달/년/반복 구간이 바뀌면 탐색 상태가 넘어가지 않는다. 날짜 문자열 역파싱은 debug 예시 작성에서만 사용한다.
- `InteractiveTimeRuler`가 탐색 상태와 입력을 맡고 `TimeRuler`의 공통 Canvas·색·글로우를 재사용한다. Canvas 도형은 28dp 그대로, 앱 상세 터치 영역만 48dp다. 가로 방향이 확인된 드래그만 처리한다.
- 모션 시간은 `Motion`, 눈금 반응/햅틱 수치는 `TimeRulerTokens`, 간격/터치는 `Spacing`/`LayoutTokens`를 사용한다. 기존 글로우 코드값 10%/20%를 보존했다.
- `TimeStoriesSection`은 기존 후보 고정·출처 열기를 유지하고 선택 변경만 공통 경로로 연결한다. 전환 중 접근성은 현재 선택된 한 이야기만 제공한다.
- 저장/DB/설정 키/알림/서비스/위젯 갱신 주기/의존성/출시 버전은 변경하지 않았다. 시간 계산은 기존 경과율과 남은 값의 뜻을 유지한다.

7. 이야기: 0개/1개/여러 후보, 버튼과 양방향 스와이프, 빠른 연속 넘김, 전환 중 출처 눌렀을 때 선택 사건 대응, 회전·초 틱에서 후보/선택 고정, TalkBack이 두 본문을 중복 읽지 않는지 확인.
8. 접근성/화면: 키보드 좌우·Home/End·Escape, TalkBack 진행 조절과 이전/다음/현재 복귀, 스위치 접근성, 모달 닫은 뒤 포커스. 밝게/어둡게·320dp·글자 1.0/1.3/2.0·한/영·긴 제목/출처·큰 총 초·전체/막대만/숨김·빈 목록에서 baseline, 줄바꿈, 48dp, 잘림 확인.

## 갤러리 진입

- 기본: `detail-time`, `detail-today`, `detail-month`, `detail-year`.
- 감속 보정 예시: `detail-settle-month`, `detail-settle-year`, `detail-settle-today`, `detail-settle-small-gap`, `detail-borrow-hour`, `detail-borrow-minute`, `detail-borrow-equal-minute`, `detail-borrow-terminal`.
- 추가 경계 예시: `detail-february`(28), `detail-leap-month`(29), `detail-31-days`, `detail-leap-year`(366→99), `detail-short-range`(45초), `detail-partial-minute`(5분30초), `detail-same-day`.
- 기존 상태: `detail-waiting`, `detail-expired`, `detail-last-second`, `detail-story-seconds`, `detail-story-music`, `detail-story-literature`.
- `-long`, `-hidden`, `-bar-only` 조합과 테마/글자 배율을 사용한다. 예시는 고정값이므로 실제 초 틱·자정·반복 전환 확인은 실 앱에서 별도로 진행해야 한다.


## 상세 바텀시트 높이 제한

사용자 요청에 따라 공통 `TimeDetailSheet` 전체 표면에 현재 앱 창 높이의 80% 상한을 적용했다. 비율은 `LayoutTokens.DetailSheetMaxHeightFraction`으로 관리한다. 드래그 핸들을 포함한 시트 전체를 제한하며 기존 본문 세로 스크롤과 큰 글자 배율 보존을 재사용한다. 내용이 짧으면 80%까지 강제로 늘리지 않는다. 오늘/달/년·대표 구간·목록의 상세 시트에 함께 적용한다.

로컬 Material3 1.2.0 소스에서 전달한 modifier가 본문뿐 아니라 Surface에 적용되는 경로를 확인하고 코드·공백을 검토했다. 빌드·Lint·단위 테스트·새 APK/실화면 검수는 실행하지 않았다. 최종 요청 시 밝게/어둡게·320dp·큰 글자·긴 제목/이야기·이야기 없음·빈 홈·한/영, 가로 회전·분할 화면에서 80% 상한과 본문 끝의 위젯 추가 버튼 도달을 확인한다. 드래그/뒤로 가기/닫기, 내부 스크롤과 눈금 탐색도 함께 재확인한다. 실제 전후 캡처는 아직 없다.
