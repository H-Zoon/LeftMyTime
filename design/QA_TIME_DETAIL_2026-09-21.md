# 시간 디테일 개선 — 구현 및 검증 대기

날짜: 2026-09-21. 사용자가 [개선안](TIME_DETAIL_REFINEMENT_2026-09-21.md)에 ‘진행’으로 구현을 요청했다. 정밀도는 **1초 단위 시간 + 경과율 소수점 한 자리**다.

## 코드에 반영한 내용

- **글로우:** 앱과 위젯이 같은 `drawTimeRulerGlow` 함수를 사용한다. 기존 28dp 눈금 안에서 남은 구간의 시작부터 끝까지 가로 밝기가 일정한 빛을 채우고, 위아래로만 부드럽게 흐려지도록 한다. 세로 중앙의 농도는 밝게 18%·어둡게 26%다. 시작 전/종료/잘못된 기간/진행 숨김에서는 빛을 표시하지 않는다. Android 12 전용 blur에 의존하지 않는다.
- **정밀도:** 홈 대표 구간, 오늘 요약, 기간/위젯 상세에서 초를 표시한다. 시·분과 함께 있는 초는 보조 크기, 초만 남으면 주 숫자다. 두 자리 초와 tabular 숫자 폭, 단위 묶음 줄바꿈을 사용한다. 접힌 목록·설치 위젯의 기본 분/일 표시는 유지한다.
- **데이터:** `TimeDetailFacts`에 원본 경과 비율, 실제 경과/전체 길이, 상태, 초 표시용 남은 값을 전달한다. 경과 시간을 반올림된 퍼센트에서 역산하지 않는다. 눈금도 위젯의 기존 정수 변환을 거치지 않는다.
- **시작 전 날짜:** 미래의 당일 일정은 기존 계산에서 전체 길이가 0일이어서 100%가 될 수 있다. 새 상세/눈금의 표시 데이터에서는 명시적인 시작 전 상태에 맞춰 0%로 제공한다. 계산기·저장값·기존 목록의 의미는 바꾸지 않는다.
- **마지막 초:** 초 표시용 Duration은 양의 소수 초를 올림한다. 기존 저장값·정렬값·분 단위 표시값은 바꾸지 않는다. 실제 시작/종료 시각으로 상태를 판정하고, 상세의 활성 구간은 완료 직전 99.9%를 표시한다. 눈금의 접근성 설명도 같은 비율 정밀도를 사용한다.
- **상세:** 기간 시트와 `WidgetDetailsActivity`에서 `TimeDetailContent`를 공유한다. 시작/종료 눈금, 경과/남은 비율, 전체·지나간 길이, 달/년의 일수 기준 설명, ‘이만큼의 시간’을 표시한다. 오늘은 기존 23:59:59 종료 기준을 유지하며 전체 길이 행을 생략하고 경과 시간을 보여준다. 진행률 전체/막대만/숨김 설정을 따른다. 편집·위젯 추가 동선을 유지한다.
- **시간 이야기:** 기존 활동 제안을 제거하고 실제 사건 16개의 기간·한/영 문구·출처를 제공한다. ‘이만큼의 시간’에서 남은 길이와 가까운 사건 하나를 보여주며 ‘다른 이야기 보기’로 넘긴다. 선택은 읽는 동안 고정하며 출처 버튼으로 외부 자료를 열 수 있다. [선택·편집·출처 기준](TIME_STORIES.md)을 따른다.
- **위젯 기준 시각:** 단일 오늘·시간 일정은 제목 아래에 날짜·시간 기준을 표시한다. 새로고침과 값의 접근성 설명에도 제공한다. 기존 48dp 헤더 안에서 우선 배치하고 실제 문자열 높이를 전체 높이 계산에 포함한다. 단일 4×2·요약 4×1 배치와 시작/종료 라벨을 유지한다. 요약에는 새 줄을 추가하지 않는다. 생성 미리보기 캐시 버전을 갱신했다.
- **검수 경로:** debug 갤러리는 실제 상세 컴포넌트와 원본 길이가 있는 예시 데이터를 사용한다. `detail-time`, `detail-today`, `detail-month`, `detail-year`, `detail-waiting`, `detail-expired`, `detail-last-second`와 `-long`, `-hidden`, `-bar-only` 조합을 추가했다. 기존 `widget-…` 경로도 실제 공유 눈금 렌더러를 사용한다.

## 이번에 활성화하지 않은 기능

설치 위젯의 초 카운트다운은 미완료다. 시스템 Chronometer의 0초 이후 음수 진행, 시작/종료·자정 전환, 눈금·글로우와의 동기화에 대한 실행 검증을 하지 않았다. 기존 30분/수동/변경 이벤트 갱신을 유지하고 값의 기준 시각을 보강했다. 상시 서비스·정확한 알람 권한·초 단위 백그라운드 작업은 추가하지 않았다. 위젯을 누른 뒤 열리는 **앱의 상세**에서는 초를 표시한다.

## 확인한 범위

- 변경 코드의 데이터 흐름·호출부·리소스 참조를 검토했다.
- 한/영 문자열·복수형의 참조와 중복 이름, 수정 XML의 문법을 정적으로 확인했다.
- Git diff의 공백 오류를 확인했다.

**빌드·Lint·단위 테스트·새 APK 설치·실제 화면 검수는 수행하지 않았다.** 사용자 지시에 따라 최종 검증 요청까지 보류한다. 이전 빌드·46개 테스트 통과 결과를 이번 코드에 적용하지 않는다. Preview와 갤러리 경로 추가는 시각 검수 완료를 뜻하지 않는다. 실행 화면 전후 이미지는 최종 검수 때 `design/qa-time-detail/`에 저장한다.

## 최종 검증 요청 시 확인

1. 코드: `./gradlew testDebugUnitTest assembleDebug lintDebug`. 새 원본 사실 전달, 초 올림, 기존 분/일 표현 유지, 경과율 포맷, 시간 이야기의 거리 순서·선택 범위 경계를 포함하고 기존 경고와 새 문제를 구분한다.
2. 앱: 밝게/어둡게·5개 팔레트·한/영·320dp·글자 1.0/1.3/2.0·긴 제목/숫자·빈 상태. 초·단위가 잘리지 않고 홈 요약의 위계를 유지하는지 확인한다.
3. 시간: 1시간→59분59초, 1분→59초, 1초 미만, 종료/다음 시작, 오늘 23:59:59/자정, 월말/연말/윤년, 시각/시간대 변경과 앱 복귀. 실제 계산 기준에서 검증하며 예시 데이터만으로 통과하지 않는다.
4. 상세: 직접 탭한 기간 유지, 스크롤/닫기/초점 복귀, 진행률 설정 3종, 시작 전/종료/잘못된 범위, 경과 정보의 실제 길이와 일치. 시간 이야기는 매초 변하지 않고 다른 이야기/출처 버튼·화면 회전·재진입·시작/종료 상태에 대응해야 한다.
5. 위젯: 4×2에서 기준 시각 추가 후 시작/종료 라벨이 유지되는지, 큰 글자·긴 제목·한/영에서 실제 높이와 계산이 일치하는지 확인한다. 실제 설치와 설정/생성 미리보기, 4×1 요약, Pixel/One UI, 기존 설치 업데이트를 구분한다.
6. 접근성: 현재 남은 시간을 읽고 매초 강제 낭독하지 않는지, 48dp 터치 영역과 숨김 설정이 유지되는지 확인한다.
7. 별도 위젯 카운트다운 작업: 종료 후 음수 방지, 숫자·눈금·상태 일치, 자동 다음 일정, 자정, 프로세스 종료·절전·재부팅·시각 변경·권한 변화. 이 조건을 해결하기 전 초 표시만 활성화하지 않는다.

DB 스키마·기존 일정·설정 키·출시 버전·알림 예약 동작은 변경하지 않았다. 개인 일정의 기존 펼침/편집 동선을 새 바텀시트로 교체하지 않았다.

## 후속: baseline과 글로우 경계 보완

사용자가 추가 UI의 baseline 정렬, 더 강한 글로우와 부드러운 경계를 요청했다.

- 시·분·초는 묶음의 아래쪽 끝을 맞추던 방식에서 첫 글자 baseline을 맞추는 방식으로 변경했다. 숫자·단위 내부 정렬과 큰 글자에서 단위를 아래에 두는 구조는 유지한다. 세로형 오늘/달/년 요약도 이름과 시간의 baseline을 맞춘다.
- 상세의 전체/경과 시간, 눈금 숨김 시 시작/종료 정보는 이름/값을 1:2 열로 배치한다. 16dp 간격과 첫 baseline, 값 오른쪽 정렬을 공유하며 긴 내용은 각 열 안에서 줄바꿈한다.
- 기존 글로우는 세로 중심 58%·반지름 72%라 위아래 끝에서 빛이 잘릴 수 있었다. 중심/반지름을 각 50%로 바꿔 끝에서 완전히 투명해지도록 했다. 중심 농도는 8/12%에서 18/26%로 높이고, 17개 지점에서 `(1-r²)³` 감쇠를 적용해 중심과 외곽을 부드럽게 연결한다. 빛을 자르던 별도 clip도 제거했다. 공통 함수를 쓰는 앱/위젯/설정 미리보기에 함께 적용된다.
- 눈금 높이·눈금 치수·위젯 최소 크기·시간 계산은 변경하지 않았다. 생성 미리보기 캐시는 새 표현으로 갱신하도록 버전을 올렸다.
- 코드와 로컬 Compose 1.6.1 소스의 baseline API를 검토했다. **새 빌드·Lint·테스트·APK 설치·실화면 확인은 수행하지 않았다.** 기존 갤러리의 `detail-time`, `detail-today`, `detail-last-second`와 큰 글자·한/영·밝게/어둡게·위젯 4×2에서 줄별 baseline 및 상하 경계 잘림을 최종 검수한다. 전후 실행 화면은 그때 기록한다.

## 후속: 남은 구간 전체에 글로우 채우기

사용자가 가운데만 밝아지는 문제를 지적하고, 위아래 경계는 흐리게 유지하면서 남은 구간의 시작부터 끝까지 빛을 채우도록 요청했다.

- 타원형 방사 그라데이션을 세로 방향의 선형 그라데이션으로 교체했다. 가로 방향 감쇠를 제거해 남은 구간 양 끝도 중앙과 같은 세로 밝기 분포를 갖는다.
- 세로 방향은 33개 지점에서 `(1-r²)³` 감쇠를 적용한다. 위아래 끝은 투명하고 세로 중앙의 기존 18/26% 농도는 유지한다. 남은 폭과 세로 감쇠를 분리해 짧은 구간도 같은 밝기로 채운다.
- 공통 렌더러를 통해 앱·위젯·설정 미리보기에 적용하고 생성 미리보기 캐시 버전을 갱신했다. 시간 계산·눈금 치수·최소 위젯 크기는 유지한다.
- 코드의 그라데이션 방향·채우기 범위·공통 호출부와 공백 오류를 검토했다. **빌드·Lint·단위 테스트·새 APK 설치·실화면 검수는 수행하지 않았다.** 밝게/어둡게, 320dp·큰 글자·긴 제목·빈 상태, 위젯 4×2에서 남은 비율 100/50/10/1%의 가로 채움과 상하 경계, 종료 시 빛 제거를 최종 확인한다. 실제 전후 이미지는 최종 검수 때 남긴다.


## 후속: 활동 제안을 실제 사건으로 교체

사용자 승인에 따라 ‘이 시간이면’ 활동 권유와 횟수 계산을 제거했다. `TimeStories.kt`의 실제 사건 16개와 `TimeStoriesSection`을 통해 ‘이만큼의 시간’, 실제 소요 시간, 이야기, 다른 이야기/출처를 표시한다. [기간의 정확한 의미와 출처](TIME_STORIES.md)를 함께 관리한다.

후보는 상세를 열 때 남은 길이의 0.5–2배 범위에서 가까운 순서로 선택한다. 더 긴 사건도 포함하므로 ‘비슷한 시간의 기록’이라고 밝히고 원래 기간을 명시한다. 읽는 동안과 회전 중에는 후보·선택을 유지하고 남은 길이가 없거나 처음부터 후보가 없으면 구역을 숨긴다. 브라우저 없이 출처를 누르면 안내한다. 자동 네트워크 요청, 계산·저장·알림·설치 위젯 렌더링의 변경은 없다.

한/영 문구와 소요 시간·출처의 대응, 이전 활동 리소스 참조 제거, XML 구문·중복 키·누락 참조, 공백 오류를 정적으로 검토했다. **빌드·Lint·단위 테스트·새 APK 설치·실화면 검수는 수행하지 않았다.** 실제 컴포넌트를 쓰는 `detail-story-seconds`, `detail-story-music`, `detail-story-literature`를 추가했으며 밝게/어둡게·320dp·큰 글자·긴 제목/출처명·빈 상태·버튼/회전/경계 동작과 전후 화면은 최종 검수 대기다.
