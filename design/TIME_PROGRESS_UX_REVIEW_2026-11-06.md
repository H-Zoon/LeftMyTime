# 기간별 ‘지나간 시간’ UX 검토

검토일: 2026-11-06. 사용자 요청: “각 시간 지나감 항목도 문제임. 그것도 분석”.

상태: **실제 6.8(25) APK의 오늘·달·년·주·분기 상세를 확인한 진단**. 앱 구현이나 디자인 기준 변경을 승인·완료한 기록이 아니다.

## 판단

공통 상세는 하나의 시간 상태를 남은 숫자, 눈금, 현재 위치, 경과/남은 비율, 전체 길이, 지나간 길이로 반복해서 설명한다. 여기에 탐색 안내, 계산 기준 설명, 이야기 본문과 관리 행동까지 펼쳐져 있다. 기능을 많이 담은 상태에서 중요한 숫자와 보조 정보의 우선순위가 약해졌다.

특히 ‘지나간 시간’이라는 같은 이름을 실제 경과 시간과 오늘을 포함한 날짜 개수에 함께 사용한다. 기존 계산 규칙은 문서에 명시되어 있지만, 작은 설명문을 읽어야 큰 숫자의 뜻을 정확히 알 수 있다는 UX 문제가 있다.

큰 남은 숫자와 남은 부분을 강조하는 얇은 눈금은 유지할 기반이다. 기존 A안, 내부 경과율, 날짜 계산·저장 의미를 바꾸지 않고 표현과 정보의 순서를 먼저 정리하는 것이 적절하다.

## 확인한 흐름

| 단계 | 실제로 확인한 화면·동작 | 상태와 주요 발견 |
| --- | --- | --- |
| 1 | 홈에서 오늘·이번 달·올해 선택 | 진입 가능. 각 기간 이름과 남은 길이가 함께 제공됨 |
| 2 | 오늘 상세 | 표시 정상. 실제 남은 숫자·보조 문구 중복, 현재 시각과 자정부터의 경과 길이 중복 |
| 3 | 이번 달 상세 | 표시 정상. 11월 6일 오후에도 ‘지나간 시간 6일’로 표현 |
| 4 | 올해 상세 | 표시 정상. ‘310일’은 오늘 포함 날짜 개수이며 대표 숫자 크기가 달·분기와 다름 |
| 5 | 달 눈금 가운데 선택 | 탐색 가능. 현재 24일과 선택 날짜 기준 15일이 함께 표시되고 아래 비율은 현재 기준을 유지 |
| 6 | 다른 기간 → 이번 주 | 진입 정상. 달력 기준 이름 문제 반복, 기간 규칙이 숫자보다 먼저 나옴 |
| 7 | 기간 선택 메뉴 | 주·분기 선택 가능. 현재 선택의 체크가 보임 |
| 8 | 이번 분기 | 표시 정상. 올해와 똑같은 55일인데 숫자가 더 큼 |
| 9 | 분기 상세, 폭 320dp·글자 1.5배 | 재배치 가능. 설명과 반복 문구가 숫자보다 먼저 큰 공간을 사용 |
| 10 | 같은 조건에서 경과 정보까지 스크롤 | 접근 가능. ‘지나간 시 / 간’, ‘3개 / 월’ 등 의미 단위가 갈라짐 |

캡처별 자세한 메모와 UI hierarchy는 Git 제외 폴더인 [이번 캡처 기록](qa-period-audit-2026-11-06/notes.md)에 있다. 아래 이미지는 모두 이번 실행에서 저장한 후 직접 열어 확인했다.

## 우선순위 1 — 경과 시간과 달력의 날짜 순서 구별

| 기간 | 캡처에 보이는 ‘지나간 시간’ | 실제 값의 기준 | 사용자에게 생기는 혼동 |
| --- | --- | --- | --- |
| 오늘 | 약 15시간 57분 | 자정부터 실제로 흐른 시간 | 바로 위 현재 시각과 같은 상태를 반복 |
| 이번 주 | 5일 | 월요일부터 **오늘 포함 5일째** | 금요일이 끝나기 전에도 5일이 전부 지난 것처럼 읽힘 |
| 이번 달 | 6일 | **오늘 포함 6일째** | 6일이 아직 끝나지 않았는데 완료된 기간처럼 읽힘 |
| 이번 분기 | 37일 | 10월 1일부터 **오늘 포함 37일째** | 실제 경과한 37일이라는 뜻으로 읽기 쉬움 |
| 올해 | 310일 | **오늘 포함 310일째** | 경과 시간과 달력 일차의 차이가 드러나지 않음 |

권고: 시간은 ‘지나간 시간’, 달력은 ‘이번 달 6일째’와 같이 기준을 직접 드러내는 이름을 검토한다. ‘24일 남음’의 오늘 제외 기준은 알아보기 쉬운 위치에서 짧게 안내한다. 이 분석만으로 오늘 포함 규칙을 바꾸거나 숫자를 1씩 빼면 남은 일수·눈금·비율의 관계가 달라지므로 그렇게 처리하지 않는다.

소스 근거: [기본 기간 데이터](../app/src/main/java/com/devidea/timeleft/ui/TimeDisplayFactory.kt), [주·분기 데이터](../app/src/main/java/com/devidea/timeleft/periods/CalendarPeriod.kt), [공통 경과 라벨](../app/src/main/res/values-ko/strings.xml).

## 우선순위 2 — 첫 화면에 같은 정보를 반복하지 않기

현재는 ‘현재 남은 시간 24일’ 바로 아래 큰 ‘24일 남음’을 보여 주고, 눈금의 남은 구간 다음에 다시 ‘20.0% 지남 · 80.0% 남음’, ‘전체 30일’, ‘지나간 시간 6일’을 표시한다. 각각은 유용하지만 기본 상세에서 전부 펼쳐질 필요는 재검토할 수 있다.

권고: 큰 남은 숫자 → 눈금 → 짧은 기준 정보의 순서로 첫 화면을 정리하고, 전체 길이·양쪽 비율·계산 기준은 펼쳐 볼 수 있는 보조 정보로 묶는 안을 비교한다. 경과 정보 접근은 유지한다. 오늘의 현재 시각과 경과 길이 중 어떤 값을 기본으로 둘지도 한 가지 명확한 역할로 정한다.

상단 작은 실제값은 1.2초 진입 연출 동안 실제 남은 값을 보이기 위해 마련된 장치다. 연출을 없애는 결정을 임의로 내리지 않고, 연출 이후의 상시 중복 노출을 별도로 검토한다. 주·분기의 기간 정의와 시간대 설명도 첫 숫자를 읽기 전의 필수 정보인지 검토한다.

소스 근거: [실제값 보조 문구와 진입 연출](../app/src/main/java/com/devidea/timeleft/ui/components/InteractiveRemainingTime.kt), [상세의 정보 순서](../app/src/main/java/com/devidea/timeleft/ui/components/TimeDetailContent.kt), [다른 기간 화면](../app/src/main/java/com/devidea/timeleft/periods/PeriodsActivity.kt).

## 우선순위 3 — 같은 숫자 역할에는 같은 시각적 위계 사용

올해와 이번 분기는 같은 12월 31일에 끝나며 캡처에서 둘 다 55일이 남았다. 그런데 올해는 작은 대표 숫자, 분기는 큰 대표 숫자를 쓴다.

원인: `InteractiveRemainingTime`이 진입 연출용 전체 길이를 `reserveValue`로 전달한다. `RemainingTimeText`가 예약한 숫자의 자리 수를 `widestValue`로 삼고, 세 자리 이상이면 `displayMedium`, 두 자리 이하의 한 단위이면 `displayLarge`를 고른다. 전체 길이 365와 92의 차이가 최종 남은 값 55의 크기를 바꾼다.

권고: 연출을 위한 폭 예약과 최종 대표 숫자의 서체 역할을 분리해서 검토한다. 달·년·주·분기의 같은 일수 역할은 일관되게 읽히게 하고, 좁은 폭이나 큰 글자는 자연스러운 재배치로 처리한다. 글자 배율을 무시하거나 접근성 글자를 축소하는 해결책은 사용하지 않는다.

소스 근거: [대표 숫자의 크기 선택](../app/src/main/java/com/devidea/timeleft/ui/components/RemainingTimeText.kt).

## 우선순위 4 — 현재와 미리보기를 구분하기

11월 15일을 선택하면 ‘미리보기 · 11월 15일 기준 · 15일 남음’이 뜨지만 큰 숫자는 24일이고, 경과 비율·경과 일수는 계속 11월 6일 기준이다. 기존 승인된 설계대로 실제 현재값을 유지한 동작이며 계산 오류로 분류하지 않는다.

권고: 현재의 숫자·비율 묶음과 탐색 중인 날짜의 정보를 더 명확하게 구분하는 표현을 검토한다. 탐색선에 가까운 설명으로 선택 날짜와 해당 남은 길이를 묶고, 현재 기준의 정보임을 사용자가 기억해서 추론하게 만들지 않는다. 실제 저장·정렬·알림·이야기 기준은 계속 현재값을 사용해야 한다.

소스 근거: [상세 눈금 탐색](../app/src/main/java/com/devidea/timeleft/ui/components/InteractiveTimeRuler.kt).

## 우선순위 5 — 큰 글자에서 이름과 값의 배치 조정

320dp·글자 1.5배에서 경과 정보까지 세로로 이동할 수 있었다. 정보가 사라지거나 글자를 임의로 줄인 증거는 없다. 다만 1:2 폭의 이름/값 행 때문에 ‘지나간 시간’이 ‘지나간 시 / 간’으로 갈라지고, 기간 설명과 이야기 길이도 여러 줄을 차지한다.

권고: 같은 `DetailFact`를 유지하면서 폭과 글자 배율에 따라 이름과 값을 위아래로 배치하는 방안을 검토한다. 숫자·단위·‘3개월’ 등 의미 단위의 줄바꿈도 함께 검토한다. 기본 정보 순서를 줄인 뒤 다시 확인해야 한다.

## 이야기와 행동의 위계

‘이만큼의 시간’은 기존 제품 방향이므로 제거 대상으로 단정하지 않는다. 다만 상세를 열자마자 긴 본문과 다른 이야기·저장·보관함·출처가 함께 펼쳐져 시간 확인보다 더 많은 줄을 사용한다. 첫 화면에서는 짧은 연결 문구로 소개하고 원하는 사용자가 펼치는 안, 저장·보관함 행동의 위치를 정리하는 안을 비교할 수 있다.

## 재사용할 기반과 변경 경계

- 유지할 기반: A안의 큰 남은 숫자·얇은 눈금, `TimeDetailSheet`, `TimeDetailContent`, `RemainingTimeText`, `InteractiveTimeRuler`, `TimeStoriesSection`, `TimeLeftTheme`, `Spacing`, `LayoutTokens`.
- 변경 후보: 경과 항목 이름, 중복 설명의 상시 노출, 보조 정보의 펼침 구조, 연출 예약과 숫자 서체 역할, 좁은 화면의 정보 행 배치.
- 계산·저장·DB·설정 키·반복·알림·위젯 로직을 이 진단에 묶어 변경하지 않는다. 내부 `percent`는 경과 비율 그대로 두고 표시만 파생한다.

## 확인 범위와 미검증

- 기존 `release-6.8-25/TimeLeft-6.8-25.apk`, Pixel 10 Pro XL AVD, Android API 37.2. 읽기 전용·스냅샷 미저장·소프트웨어 렌더러·창 없는 실행에서 기기 화면을 직접 캡처했다.
- 기본 1344×2992px·480dpi·글자 1.0의 한국어 상세, 분기에 한정한 320dp 폭·글자 1.5배와 경과 정보까지 스크롤을 확인했다.
- 이 APK에는 현재 소스의 일부 후속 변경이 없다. 현재 소스 전체를 실행 검증한 것으로 확대하지 않는다.
- 이번에는 글자와 물리 픽셀 크기를 함께 바꾸지 않고 밀도만 조정해 작은 폭을 확인했다. 앞선 빈 홈 검토의 검은 화면 오류를 이번 결과와 혼동하지 않는다.
- 다크 모드, 실제 기기, 개인 일정과 종료된 날짜의 ‘N일 지남’, 집중, 위젯, 긴 일정 제목, 회전·분할 화면, 월말·연말·윤년·자정, TalkBack·키보드·햅틱·모션 전 과정은 미검증이다. 스크린샷으로 접근성 준수 전체를 판정하지 않는다.
- 앱 코드·디자인 기준은 변경하지 않았다. **빌드·Lint·단위/계측 테스트는 실행하지 않았다.**
