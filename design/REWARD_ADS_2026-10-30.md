# 리워드 광고 동의·수신거부 개선 — 6.8(25)

2026-10-30. 사용자가 KISA 안내에 맞춰 앱을 수정하도록 요청했다. 후속 지시로 **기존 `reward_notifications` 토픽과 수신 선택은 유지하고 별도 대상을 만들지 않는다.** 기존 인트로 시점(신규 설치 두 번째 실행/업데이트 첫 홈)도 유지한다. 새 버전은 6.8(25)이며 후속 최종 검증 요청에 따라 서명 AAB/APK를 생성했다. 자세한 결과와 미검증 조건은 [서명 빌드 기록](RELEASE_BUILD_2026-10-30.md)을 따른다.

## 앱에서 달라지는 점

- 인트로와 설정에 ‘광고성 정보 수신 동의’를 명시하고 TimeLeft·리워드/혜택 광고·한국시간 발송 시간·무료 수신거부 방법을 같은 한/영 고지로 제공한다. 동의·거부 버튼도 구별한다.
- 리워드 알림 본문을 누르면 로그인·SDK·원격 설정 없이 `SettingsActivity`의 리워드 전용 화면을 연다. 상단 ‘수신거부’ 버튼과 기존 수신 스위치를 제공하며 ‘리워드 보기’는 별도 행동으로 둔다.
- 앱이 직접 게시하는 알림은 `(광고)` 제목·수신거부 안내와 ‘수신거부’ 액션을 제공한다. 액션은 선택을 즉시 끄고 같은 화면을 연다. 기기에서 동의값을 아직 읽는 중에도 명시적 수신거부는 가능하며, 저장값을 읽기 전에는 스위치를 꺼진 상태로 확정해 보여주지 않는다.
- 기존 불리언 선택을 그대로 읽으며 변경하지 않는다. **새로운 명시적 동의/거부/철회 때만** 선택 시각(`reward_ads_consent_changed_at`)과 고지 버전(`reward_ads_consent_notice_version=1`)을 기기에 함께 기록한다. 이전 선택에 현재 고지의 동의 시각·버전을 소급 기록하지 않는다. 서버 동의 이력이나 Analytics 속성을 추가하지 않는다.
- 수신거부와 표시가 같은 잠금을 사용해 철회 직후 앱이 새 알림을 게시하지 않게 한다. 디스크 기록 실패 시에도 토픽 해제를 시도하고 로컬 오류/재시도 상태를 유지한다. Firebase 토픽 해제 자체는 비동기다.
- 앱이 직접 게시하는 리워드는 한국시간 21:00~익일08:00에 폐기한다. 일정·집중·일반 메시지의 시간 정책은 바꾸지 않는다.

## Console과의 연결

캠페인 ID `3186944161412585896`은 **초안**이다. 기존 토픽·월수금토일 14:00 한국시간·하루 최대1회·만료1시간은 유지하고, 본문에 수신거부 안내를 추가하며 `open_target`을 `reward_settings`로 수정했다. 테스트 메시지·게시·실제 발송은 하지 않았다. 새 앱 배포와 실제 검증 전에 활성화하지 않는다.

사용자 정의 데이터는 `notification_kind=reward`, `open_target=reward_settings`만 필요하다. MainActivity가 고정 목적지로 소비하고 원격 설정/PointHome 초기화를 기다리지 않고 수신설정을 연다. 일반 메시지가 뒤에 들어오면 기존 대기를 취소하고, 회전·복원·SDK 복귀에서 소비한 요청을 반복하지 않는다. 기존 `pointhome` 경로는 수신설정의 ‘리워드 보기’에 재사용한다.

Firebase Messaging **25.1.1의 실제 캐시된 공식 소스**에서 백그라운드 notification 메시지는 `DisplayNotification`이 자동 표시함을 확인했다. Console에는 Android 액션 입력란이 없어 앱 액션을 백그라운드 자동 알림에 주입하지 않는다. 내부 `handleIntent`를 재정의하거나 SDK의 `gcm.n.*` 플래그를 변조하지 않는다. Console 알림은 **본문 탭 → 수신설정**으로 직접 연결하고, 별도 액션은 앱이 직접 게시하는 알림에서 제공한다.

따라서 앱의 야간 검사는 Console의 백그라운드 자동 표시에는 실행되지 않는다. 운영에서 14:00·대한민국 시간·1시간 TTL을 함께 제한해야 한다. 구버전은 새 `reward_settings`를 처리하지 못해 홈만 열 수 있으므로 모든 기존 사용자에게 새 동선이 적용됐다고 쓰지 않는다. 사용자 지시로 토픽을 분리하지 않은 범위와 구별한다.

## 공통 UI와 데이터 범위

`SettingsScaffold`·`TimeLeftTopAppBar`·`TimeLeftSwitchRow`·기존 상태/재시도/시스템 설정 행을 공유한다. 버튼은 기존 Material 테마·`LayoutTokens.MinTouchTarget`, 간격은 기존 `Spacing`을 사용한다. 새 팔레트·카드·링·고정 글자 크기를 추가하지 않는다. `SettingsActivity`는 기존처럼 exported=false이며 외부 데이터가 임의 Activity/URL이나 자동 철회를 지시할 수 없다. 자동 철회 플래그는 앱이 만든 immutable 액션 PendingIntent에만 들어간다.

DB·일정·집중·위젯·기존 인트로 정책·기존 수신 동의/토픽·SDK 버전/권한은 바꾸지 않는다. 새 선택 기록은 일정 백업에 포함하지 않는다. 개인정보처리방침 원본·읽기용 문서·로컬 Hosting 게시본에 기록 항목과 직접 철회 동선을 반영했다. **공개 Hosting 배포는 하지 않았다.**

## 검증 범위

정적 검토 대상: 전체 변경의 diff 공백, 한/영 리소스·포맷 인자, manifest/XML 및 JSON 구문, 기존 인트로 정책 보존, 기존 토픽/선택 키 보존, 안전한 목적지·PendingIntent 분리, 새 UI의 공통 구성요소 사용과 분기 흐름.

테스트 소스 추가: 야간 08/21시 경계, 고정 수신설정 목적지, 과거 수신 선택 보존/동의 기록 비소급, 새 선택·철회 기록과 다른 설정 보존, Intent의 1회 소비와 수신거부 액션 구별. debug 갤러리는 실제 `RewardNotificationSettingsScreen`을 `reward-notification-settings`·`-off`·`-blocked`·`-failed`·`-loading`에서 재사용하며 실제 설정/SDK를 바꾸지 않는다.

**후속 사용자 요청으로 최종 검증을 실행했다.** Debug/Release 단위 테스트 각각153개, 리워드 계측3개가 통과했고 Lint 오류는0이다. 기존과 같은 Debug 경고169/힌트10·Release 경고166/힌트7이 남는다. 서명·버전·AAB 구조·ZIP/ELF16KB 정렬·매핑 일치를 확인했다. 기존 6.7 결과를 이번 변경의 검증으로 대체하지 않았다.

Android17/API37·16KB 페이지 에뮬레이터의320dp 실제 화면에서 한/영·밝게/어둡게·글자1.5배, 수신 켜짐/꺼짐·불러오기·차단·실패 상태와 상단 수신거부 전환, 긴 내용의 하단 스크롤 접근을 확인했다. 인트로 갤러리의 예전 임시 고지는 실제 앱 리소스로 교체하고 Debug 빌드/검사를 다시 통과했다. 계측은 테스트 전용 설정을 사용했으며 실제 FCM 발송은 하지 않았다.

최종 서명 release APK도 같은 에뮬레이터에 설치해, 종료 상태에서 알림과 같은 고정 kind/target Intent를 주면 전용 수신설정이 직접 열림을 확인했다. 실제 FCM·시스템 알림 탭은 별도 확인 대기다.

실기기 확인 대기:

- 신규 설치/6.7 업데이트에서 기존 인트로 시점·선택 유지, 새 동의 고지/거부/닫기와 시스템 권한 허용/거부.
- 포그라운드/백그라운드/프로세스 종료에서 실제 토픽 수신, 본문 탭 → 수신설정, 직접 액션 철회, 로그인/원격OFF/SDK 실패에서도 철회 가능.
- 설정 읽기 전 철회, 빠른 ON/OFF, 오프라인 해제/재시도, 디스크 기록 실패, 회전·복원·연속 일반/리워드 알림.
- 서버 발송 시간·1시간 TTL·앱 야간 경계와 일반/일정/집중 알림 회귀.
- 제조사 실기기의 화면/권한·TalkBack, 신규 선택 없음의 전체 흐름, 실제6.7 대비 전후 캡처. 에뮬레이터 확인 범위가 이 조건까지 검증한 것은 아니다.
