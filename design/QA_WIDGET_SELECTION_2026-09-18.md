# 위젯 선택 UI·용도별 추가 목록 변경 기록

날짜: 2026-09-18. 사용자 승인: 위젯 선택 방식과 UI 조사 이후 **‘개선 진행’**.
상태: **코드·리소스 반영 / 정적 검토 / 빌드·Lint·단위 테스트·실행 및 런처 검수 보류**.

## 사용자에게 달라지는 점

- 위젯 추가 목록의 크기별 네 항목을 오늘·이번 달·올해·기간 요약·내 일정의 다섯 용도로 변경했다. 실제 목록 순서·배치·셀 크기는 런처가 결정한다.
- 설정 본문은 현재 선택과 미리보기를 중심으로 구성했다. 공통 상단바에 뒤로 가기를 제공하고, 선택 변경은 별도 화면에서 진행한다.
- 후보는 기간/일정으로 묶었다. 직접 선택은 같은 선택 화면의 내용을 검색 목록으로 전환하며 팝업을 쌓지 않는다. 항목 제목과 시간 구간/날짜를 함께 보여준다.
- 직접 선택 후보를 열었다 닫는 것만으로 첫 일정을 자동 선택하지 않는다. 실제 항목을 선택해야 내용이 바뀌고, 적용 전까지는 기존 위젯을 저장하지 않는다.
- ‘곧 다가오는 일정’을 ‘일정 자동 선택’으로 변경하고 진행 중인 시간 구간 우선임을 설명한다. 선택 알고리즘은 바꾸지 않았다.
- 오늘·달·년·기간 요약에서 표시 형식 옵션을 숨겼다. 개인 일정에서는 실제로 결과가 달라지는 경우에만 단위/시계·D-day 형식을 현재 값과 함께 보여준다. 시작 전처럼 결과가 같아 옵션이 숨겨져도 기존 선호값은 남는다.
- 크기 부족 안내는 실제 기간 요약 렌더러가 확대 안내를 반환할 때만 보인다. 미리보기가 화면 폭을 넘으면 가로 스크롤 안내를 추가했다. 글자를 줄이지 않는다.
- 조회 오류는 다시 시도할 수 있다. 삭제된 선택·등록 일정 없음·검색 결과 없음도 구분한다. 자동 선택은 일정이 없는 상태에서도 추가 가능하며, 직접 선택은 유효한 일정이 필요하다.
- 신규 추가는 ‘위젯 추가’, 저장값이 있는 위젯의 재설정은 ‘변경 적용’으로 표시한다. 저장 중 중복 적용을 막고, 저장 직전 선택 일정이 사라지거나 조회에 실패하면 화면에서 복구할 수 있게 했다.

## 기존 설치 호환과 신규 기본값

| provider 식별자 | 신규 진입 이름·기본값 | 목표 셀 / 최소 초기 크기 |
| --- | --- | --- |
| `AppWidget` | 오늘 / Today | 2×2 / 110×115dp |
| `MediumAppWidget` | 이번 달 / Month | 2×2 / 110×115dp |
| `WideAppWidget` | 올해 / Year | 2×2 / 110×115dp |
| `LargeAppWidget` | 기간 요약 / Overview | 4×2 / 280×150dp |
| `ScheduleAppWidget` (신규) | 내 일정 / Next | 4×2 / 245×115dp |

- 기존 네 클래스·컴포넌트 식별자를 유지했다. 내부 이름의 Small/Medium/Wide/Large 의미로 현재 콘텐츠를 추측하지 않는다.
- 새 provider 기본값은 설정을 한 번도 저장하지 않은 위젯의 구성 진입에만 사용한다. source·option·displayMode 중 저장값이 있으면 기존 값을 먼저 복원한다.
- 기존 source 키, 일정 ID, `${id}option`, `${id}displayMode`를 유지한다. 렌더러의 누락 값 처리와 기존 요약 호환 모드를 이번 UI 개편 때문에 바꾸지 않았다.
- 기존 네 provider의 최소/최대 resize 범위는 유지했다. 기존 크기를 변경하는 API를 호출하지 않는다. 초기 목표 셀 변경이 설치된 위젯에 미치는 실제 호스트 동작은 업데이트 검수 대상이다.
- 새로운 일정 provider를 전체 갱신 대상에도 등록했다. 저장·삭제·테마 변경 시 다른 provider와 같은 경로를 사용한다.
- 추가 목록에서 선택한 용도는 기본값이다. 이후 설정에서 다른 콘텐츠로 바꿀 수 있으며, 저장된 콘텐츠가 최초 진입 용도보다 우선한다.

## 공통 구성요소와 리소스

- 상단바: `TimeLeftTopAppBar`. 검색: `TimeLeftUnderlineTextField`.
- 목록 선택은 이름과 라디오 선택 상태, 최소 48dp 터치 영역을 제공한다. 색·서체·간격·표면은 `TimeLeftTheme`, `Spacing`, `LayoutTokens`를 사용한다.
- 설정과 실제 위젯은 `AppWidget.previewViews`/공통 렌더러를 사용한다. 크기 부족 여부는 반환된 기간 요약 레이아웃으로 판단하며 별도 계산을 복제하지 않는다. 현재 크기는 기존 호스트 minWidth/minHeight 경로로 해석하며 가로 화면·폴더블에서의 정확한 치수 대응은 여전히 검수 대상이다.
- 선택 화면에서 돌아올 때 변경 버튼의 키보드 초점을 복원한다. TalkBack 초점 동작은 실제 검수가 필요하다.
- `widget_picker_*` XML은 Android 12 이상 런처의 미리보기와 최초 배치에 사용한다. 값은 ‘—’이며 예시 일정·가짜 날짜를 표시하지 않는다.
- 그 이전 런처의 PNG는 같은 제목·기본 팔레트·문자 크기 역할을 사용한다. 한국어/영어와 밝게/어둡게 리소스를 제공한다. 정적 이미지이므로 실제 사용자 팔레트·현재 남은 값·시스템 글자 배율까지 표현하지 않는다.
- PNG 생성 스크립트: [generate_widget_picker_previews.py](generate_widget_picker_previews.py). Pillow로 신규 런처 안내 이미지를 생성한다. 실행 화면 캡처나 시각 검수 대체물이 아니다. 글꼴 파일은 번들에 넣지 않는다.
- 영어/한국어 문구를 함께 수정했다. 언어별 PNG는 정적 레이아웃 안내이며 그 자체가 완료된 앱 화면은 아니다.

## 이번 확인 범위

- 변경된 위젯 메타데이터·레이아웃·문구·Manifest XML 구문과 참조 리소스 존재 여부 확인.
- 영어/한국어 위젯 문구 이름 일치와 중복 이름 여부 확인.
- 신규 provider 등록·기본값 매핑·전체 갱신 경로, 저장값 우선 복원, 선택 취소 시 쓰기 없음에 대한 소스 검토.
- 한국어 밝은 기간 요약과 영어 어두운 오늘의 **런처용 정적 PNG** 확인. 실제 Android 레이아웃이나 글자 배율 검수로 취급하지 않는다.
- 문서 로컬 링크·변경 공백 점검. Kotlin 컴파일이나 동작 테스트 통과를 의미하지 않는다.

새 실행 화면의 전후 이미지는 아직 없다. 이미 설치된 앱은 이번 코드와 다르므로 이전 화면을 변경 후 증거로 사용하지 않았다. 사용자 요청에 따라 빌드·Lint·단위 테스트·새 APK 설치를 수행하지 않았다.

## 최종 검증 요청 후 확인할 조건

1. 다섯 진입의 신규 기본값, 여섯 콘텐츠 선택, 추가/재설정 저장·취소·회전. 설정 선택 페이지·검색어 복원과 뒤로 가기/키보드 동작.
2. 기존 네 provider가 서로 다른 일정·표시 모드·크기로 설치된 상태에서 업데이트. 사용자 크기·선택·표시 옵션 유지와 재설정 취소.
3. 날짜·시간 일정, 동일 제목, 긴 한/영 제목, 60개 목록, 검색 없음, 빈 목록, 조회 오류·재시도, 선택 후 삭제·저장 시 삭제.
4. 자동 선택의 진행 중/대기/빈 상태. 모든 날짜 일정이 종료된 경우 첫 일정을 반환하는 기존 동작도 기록하며 ‘다가오는 일정만 선택’으로 오인하지 않는지 확인.
5. 밝게/어둡게, 기존 사용자 팔레트, 320dp, 글자 배율 1.5배 이상. 선택 이름·상태·적용 버튼·초점·TalkBack.
6. 기간 요약의 현재 크기 부족 안내와 확대 후 복구. 미리보기와 실제 위젯 값·형식의 일치 및 가로 스크롤 안내.
7. OS·런처별 다섯 목록의 제목·미리보기·최초 크기·재설정 메뉴. 정적 PNG/previewLayout 선택과 업데이트 후 캐시 갱신.

debug 갤러리는 실제 `WidgetConfigureRoute`를 재사용한다. `widget-configure`, `widget-configure-many`, `widget-configure-empty`, `widget-configure-error`, `widget-configure-deleted`, `widget-configure-overview-small`, `widget-configure-legacy`로 진입할 수 있다. 새 fixture는 debug 소스에만 있다. 이는 검수 준비이며 실행 검수 완료가 아니다.

## 후속 범위

앱에서 `requestPinAppWidget`으로 바로 추가하는 기능, 자동 선택 알고리즘의 종료 일정 처리, 위젯 갱신 주기 변경은 이번 변경에 포함하지 않는다. 초기 크기·런처 호환·새 설정 UI의 실제 검수 결과는 최종 요청 이후 기록한다.
