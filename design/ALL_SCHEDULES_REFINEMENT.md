# 전체 일정 화면 정리와 상세 펼침 애니메이션

작성: 2026-09-18. 사용자 요청: 보기 전환·검색 사이 간격 개선, 일정 추가 화면과 같은 밑줄 검색 입력, 상세 펼침 애니메이션 가능성 조사. 후속 요청으로 애니메이션 적용을 확정했다.

상태: **간격·검색 입력·상세 펼침 애니메이션 코드 반영 / 최종 빌드·Lint·단위 테스트 및 새 화면·동작 검수는 명시적 요청까지 보류**.

## 반영한 화면 규칙

- 제목·일정 개수는 한 묶음으로 두고 보기 전환 버튼과 최소 16dp 여유를 둔다. 가용 폭이 부족하면 버튼 묶음이 다음 줄로 내려가며 줄 사이는 12dp다.
- 리스트/그리드 버튼은 각각 최소 48dp를 유지하며 둘 사이는 4dp에서 8dp로 늘린다. 선택 상태는 색과 접근성 선택 정보로 전달한다.
- 보기 전환 줄 → 검색 입력은 24dp, 검색 입력 → 정렬은 16dp, 정렬 영역 → 일정 목록은 24dp로 구분한다. 정렬이 여러 줄이면 줄 사이는 8dp다. 기존 `Spacing`을 사용한다.
- 검색 테두리 상자를 제거하고 `TimeLeftUnderlineTextField`를 일정 추가·편집의 제목 입력과 공유한다. Material `TextField`의 밑줄과 투명 배경을 공통으로 관리한다.
- 검색 돋보기는 유지하고 검색 대상 라벨은 입력 후에도 떠 있는 형태로 남긴다. 입력 즉시 필터링하며 키보드 검색 동작은 입력 초점을 해제한다.
- 일정 데이터·정렬 기준·보기 설정 저장은 유지한다. 날짜/시간 값 입력이나 추가 설정의 다른 필드는 이번 공통화 범위에 포함하지 않는다.

수정 위치: `HomeScreen.kt`, `TimeLeftUnderlineTextField.kt`, `ItemEditorScreen.kt`, `TimeLeftItemCard.kt`.

## 상세 펼침 애니메이션 적용

`TimeLeftItemCard`의 `rememberSaveable(item.id)` 펼침 상태를 유지하고, 상세를 즉시 추가·제거하던 `if (expanded)`를 `AnimatedVisibility`로 교체했다. 프로젝트의 위젯 설정 화면에서도 이미 사용하는 Compose 기능이며 새 라이브러리나 버전 변경 없이 적용했다.

### 반영한 동작

상세 블록을 `AnimatedVisibility(visible = expanded)`로 감싸고 위쪽을 기준으로 높이를 늘리면서 서서히 나타나게 한다. 접을 때는 위쪽을 기준으로 높이를 줄이며 사라지게 한다. Compose는 이런 확장·축소·페이드 전환을 제공하고 퇴장 애니메이션이 끝나면 내용을 제거한다. [Android 공식 문서](https://developer.android.com/develop/ui/compose/animation/composables-modifiers).

- 펼침 220ms, 접힘 180ms의 `tween` 전환을 적용했다. 이 상세 펼침 용도로 한정한 컴포넌트 내부 상수이며 앱 전체의 공통 모션 토큰으로 확대하지 않는다. 실제 기기에서 체감 속도는 아직 확인하지 않았다.
- 상세 설명과 편집·삭제 행동을 한 블록으로 움직인다. 설명마다 순차 지연을 넣거나 숫자·제목을 다시 등장시키지 않는다.
- 같은 상세 블록에 `animateContentSize`까지 겹치지 않는다. 높이 변화의 소유자를 하나로 두어 전환을 조정하기 쉽게 한다.
- 열린 상태에서 시간 값이 갱신되어도 펼침 애니메이션을 다시 시작하지 않도록 표시 여부만 전환 상태로 사용한다.
- 상태 문구, 제목, 기존 터치 영역을 유지한다. 접힘을 시작하면 편집·삭제 버튼을 비활성화하고 상세의 접근성 정보를 비워, 퇴장 중인 내용을 다시 실행하거나 탐색하지 않도록 한다. 실제 TalkBack 초점 이동은 최종 검수 대상이다.

### 대안과 적용 범위

전체 일정의 목록·그리드와 홈의 다음 구간은 같은 `TimeLeftItemCard`를 재사용하므로 동일한 펼침·접힘 동작을 갖는다. 제목과 남은 시간에는 등장 애니메이션을 추가하지 않았고, 강제 스크롤이나 항목별 순차 지연도 적용하지 않았다.

`animateContentSize`는 외곽 크기 변화를 부드럽게 만드는 단순한 대안이다. 이번에는 내용의 등장·퇴장까지 표현하려는 목적이므로 상세 블록의 `AnimatedVisibility`가 더 적합하다고 판단했다. 크기 애니메이션 수정자의 순서에도 주의해야 한다. [공식 크기 애니메이션 설명](https://developer.android.com/develop/ui/compose/animation/composables-modifiers#animate-composable-size-changes).

현재 목록과 그리드는 모두 `LazyVerticalGrid`를 사용하며 목록은 1열이다. 상세의 높이가 연속적으로 바뀌면 이후 행의 위치도 따라 바뀔 것으로 예상한다. 2열 그리드는 행의 가장 높은 항목에 맞춰 다음 행이 내려가므로, 옆 항목 아래에 여백이 생길 수 있다. 실제 부드러움·스크롤 위치·간격은 미검증이다. 이 조사에 맞춰 그리드 종류를 바꾸지는 않는다.

정렬·추가·삭제에 사용하는 목록 항목 이동 애니메이션은 별도 목적이다. 상세 펼침에 이를 중복 도입하거나 최신 문서의 `animateItem` 예제를 현재 의존성 확인 없이 붙이지 않는다. [공식 목록 애니메이션 문서](https://developer.android.com/develop/ui/compose/lists#item-animations).

Compose의 동작 배율이 0이면 애니메이션은 다음 프레임에서 끝나도록 정의되어 있다. 이를 강제로 덮어쓰는 별도 타이머 없이 기본 전환을 사용하고, 적용 후 기기의 애니메이션 끄기 설정에서 확인한다. [MotionDurationScale](https://developer.android.com/reference/kotlin/androidx/compose/ui/MotionDurationScale).

## 확인한 것과 남은 것

코드·리소스 사용처와 공식 문서를 읽어 구조를 확인했다. 빌드·Lint·단위 테스트를 실행하지 않았으며 현재 설치된 앱은 위 간격·밑줄 입력·애니메이션 변경을 포함하지 않는다. 수정 후 화면 캡처나 애니메이션 동작·성능 확인을 완료했다고 취급하지 않는다.

최종 검증 요청 시 확인할 범위:

- 실제 debug 갤러리의 `items`/`grid`/`editor-time`/`editor`: 밝게·어둡게, 320dp, 1.5/2배 글자, 긴 한/영 제목, 빈 목록과 검색 결과 없음.
- 보기 버튼의 선택 안내와 48dp 터치 영역, 검색 입력 중 라벨·밑줄, 검색 키로 키보드 닫기, 검색·정렬·보기 전환 후 결과 유지.
- 전체 일정의 1열/2열과 홈 다음 구간의 펼침·접힘, 빠른 연속 탭, 맨 아래 항목, 긴 상세, 검색·정렬 중 열린 항목, 편집·삭제, 애니메이션 배율 0, TalkBack 초점과 스크롤 위치.

기존 전체 일정 화면(이전 캡처)은 변경 전 참고 이미지다. 최신 코드의 화면 증거가 아니다.
