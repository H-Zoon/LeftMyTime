# 위젯 디자인·최소 크기 개편 — 구현 및 검수 기록

현재 상태: 초기 개편은 빌드·단위 테스트·Lint 및 아래 일부 에뮬레이터 검수를 마쳤다. **최신 일반 4×2·기간 요약 4×1 변경은 아직 빌드·테스트·실행 화면 검수 전이다.** 아래 초기 크기 및 캡처는 변경 전 기록이며 최신 기준은 마지막 ‘크기 축소 후속 수정’ 절을 따른다.

날짜: 2026-09-21. 사용자 승인: ‘개편 진행. 기존 작은 사이즈는 디자인 구현에 어려움이 있으므로 디자인 노출이 가능한 최소 사이즈로 변경’.

## 반영한 내용

- 설치 위젯을 단일 시간 / 세 기간 요약 두 계열로 정리했다. 제목·숫자·단위·보조 정보의 위계를 A안에 맞추고 작은 문자열 전용 16sp 축소와 눈금 자동 숨김을 제거했다.
- **초기 구현 당시** 단일 시간의 최소·최소 리사이즈 크기는 250×200dp, 기간 요약은 250×240dp, 기본 배치는 모두 4×3칸이었다. 런처의 칸 크기는 기기마다 달라 4×3칸이 항상 250×200dp라는 뜻은 아니다. 실제 가용 크기도 렌더러에서 검사한다.
- 기본 숫자 30sp/단위 14sp, 폭 340dp·높이 260dp 이상에서 숫자 56sp, 요약 숫자 22sp/단위 12sp를 사용한다. ‘1분 미만’ 같은 문장은 22sp의 별도 문구 역할이며 글자 수에 따른 축소가 아니다. 글자 배율은 유지한다.
- 각 문자열·단위 묶음의 폭과 줄 높이를 측정한다. 최소 크기 이상이어도 긴 제목·큰 글자·기존 혼합 요약까지 들어가지 않으면 글자를 줄이거나 항목을 숨기지 않고 확대 안내를 표시한다. 시간 범위 라벨만 공간이 허용될 때 추가한다. 숫자·단위·눈금은 지원 크기의 필수 정보다. 사용자의 눈금 숨김 설정은 예외다.
- 구형 작은 위젯에는 확대 안내를 표시하고 설정 진입을 연결했다. 선택 일정·표시 형식·provider ID·위젯 ID를 삭제하거나 다른 항목으로 바꾸지 않는다. 설정에서는 ‘최소 지원 크기’ 미리보기와 실제 크기를 늘리는 방법을 구분해 안내한다.
- `remainingTimeGroups`를 앱과 위젯이 공유한다. `TimeRulerTokens`로 Compose와 위젯의 눈금 간격·굵기·높이·개수를 공유하고, 실제 폭과 화면 밀도로 비트맵을 만든다.
- 요약은 오늘에 더 넓은 폭을 주되 세 기간 숫자 위계는 동일하다. 가로가 맞지 않으면 세로로 전환하며 각 기간의 탭 영역은 최소 48dp다.
- 앱의 진행 표시 설정을 설치 위젯·설정 미리보기·새 생성 미리보기에 적용하고 설정 변경 시 갱신한다.
- Android 12 이상은 런처가 주는 실제 크기 목록에 맞게 RemoteViews를 제공한다. 크기 목록이 없는 런처·이전 버전은 세로/가로 크기 쌍으로 대응한다.
- Android 12 이상은 시스템 위젯 모서리 반경, 이전 버전은 24dp를 사용한다. XML 치수는 `widget_tokens.xml`에 Spacing 및 v2 글자 역할과 대응시켰다.

## 추가 목록·상세 연결·상태

- Android 15 이상은 같은 실제 렌더러로 생성한 미리보기를 등록한다. 앱 진입·위젯 일괄 갱신 시 시도하며 provider별 성공 시각과 테마·언어·글자 배율·진행 표시 기준을 캐시한다. API 제한으로 거절되면 기존 XML/PNG로 표시한다. 미리보기를 실시간 시계라고 간주하지 않는다.
- 생성 미리보기의 기간 값은 실제 달력 값이다. 내 일정 미리보기에는 개인 제목을 노출하지 않고 선택 안내를 표시한다. 설정에서 고른 뒤에는 실제 선택 항목을 미리 보여준다.
- Android 12–14의 XML과 이전 버전의 PNG는 같은 최소 크기 비율·글자 역할·중립 눈금으로 갱신했다. PNG는 호환용 근사 이미지이며 네이티브 실행 캡처가 아니다. 실제 Android 렌더링에서 구형 PNG를 추출하는 작업은 최종 검증 이후에 가능하다.
- 단일 위젯 및 요약의 각 기간을 누르면 해당 상세 화면으로 이동한다. `TimeLeftTheme`, `TimeLeftTopAppBar`, `RemainingTimeText`, `TimeRuler`를 재사용한다. 위젯 ID·대상별 Intent를 구분하고 실행 중 화면에서도 새로운 대상을 처리한다. 자동 선택 위젯은 누를 때 다시 선정하지 않고 화면에 표시했던 일정 ID를 연다.
- 직접 선택 일정의 삭제·조회 실패를 구분하고 재선택/재시도를 연결했다. 조회 실패로 저장 ID를 지우지 않는다. 기존 혼합 표시 모드의 월 fallback은 호환용으로 유지한다.
- 자동 선택 후보가 모두 끝난 날짜 일정이면 ‘표시할 일정 없음’을 표시한다. 직접 선택한 지난 날짜의 표현과 시간 구간의 다음 시작 의미는 그대로다. 이 동작 변경에 대한 두 경계 테스트를 추가했지만 실행하지 않았다.
- 앱 복귀, 부팅, 시각·시간대·날짜 변경 방송 수신 시 위젯을 갱신한다. 방송 전달 및 백그라운드 실행은 OS 제약을 받으므로 정밀 갱신 보장은 아니다.

## 남은 기능

**30분 provider 주기 및 수동 새로고침은 유지했다.** 시스템 카운트다운의 단위 표현·0초 이후 상태 전환·눈금과의 동기화·절전 동작이 검증되지 않아 초 단위 실시간 기능을 이번 코드에 활성화하지 않았다. 정확한 알람 권한·상시 서비스·새로운 추적 이벤트는 추가하지 않았다. 정밀 갱신의 실기기 검증은 후속 범위다. pin 추가 동선은 아래 후속 작업에서 구현·검수했다.

## 최초 구현 시 확인 범위 (빌드 요청 전)

- 변경 소스·XML 구조, 리소스 참조, 한/영 새 문구, provider 식별자와 선택 저장 경로를 검토했다.
- XML 파싱·문서 링크·diff 공백 검사를 수행했다. 구형 PNG는 생성 후 대표 밝은/어두운 이미지를 확인했다. 이것을 앱·런처 화면 검수로 간주하지 않는다.
- **빌드·Lint·단위 테스트·APK 설치를 실행하지 않았다.** 사용자의 명시적 요청 전 실행 금지 지시를 유지한다. 추가한 테스트도 이 단계에서는 미실행이었다.
- 현재 설치 APK와 작업 소스의 동일성을 확인하지 않았다. 새 기준의 실제 전후 화면은 최종 검증 시 같은 데이터로 촬영하며 `design/qa-*/`에만 둔다. 대화의 구조 시안을 실행 결과로 사용하지 않는다.

## 남은 검수 조건

1. `./gradlew testDebugUnitTest assembleDebug lintDebug`. 기존 경고와 새 문제를 구분한다.
2. 실제 런처의 신규 항목 기본 단일 4×2·요약 4×1 배치, 단일 250×180·요약 250×64 공간 하한, 그보다 작은 기존 위젯의 확대 안내와 확대 후 복구. 가로 회전 및 크기 목록 미제공 런처도 포함한다.
3. 밝게/어둡게·5개 테마·한국어/영어·글자 배율 1.0/1.3/2.0·긴 제목·큰 일수·1분 미만·빈 상태·조회 실패를 확인한다. 측정치와 실제 TextView 줄 높이가 맞는지 특히 확인한다.
4. Android 15+ 생성 미리보기의 등록/거절/fallback, Android 12–14 XML, Android 11 이하 PNG, 설치 결과와 설정 미리보기의 일치. 이미지 생성은 네이티브 검수를 대체하지 않는다.
5. 여러 위젯 각각의 일정·기간 상세 진입, 자동 선택 표시 후 대상이 변경된 시점의 탭, 앱 실행 중 다른 위젯 탭, 상세 진입 후 일정 수정·삭제·반복·복귀, 오류 재시도·재선택. 상세 타이커는 보이지 않을 때 중단되는지 확인한다.
6. 기존 네 provider 업데이트, 선택·표시 형식·혼합 요약 보존, 설정 저장/취소, 크기 변경에도 선택 항목 유지. DB 및 설정 키 이행이 발생하지 않는지 확인한다.
7. 눈금 숨김 설정 즉시 반영, 접근성 읽기·명명·48dp 조작 영역, 날짜·자정·월말·연말·시간대·재부팅·절전. 이번 갱신 계기 추가가 정밀 시계 보장으로 해석되지 않도록 실제 지연도 기록한다.


## 후속 작업과 빌드 검증 (2026-09-21)

사용자가 ‘빌드 확인. 추가 작업 진행’, ‘빌드 진행되는 것 확인하였다. 추가 작업 진행’으로 검증과 후속 작업을 요청했다.

- 일정 목록의 펼친 상세와 세 기간 상세, 위젯 상세에 `PinWidgetButton`을 연결했다. 제목·숫자·눈금은 기존 렌더러, 버튼은 기존 TextButton과 최소 48dp 역할을 재사용한다.
- 요청 직전에 일정을 다시 조회하고 선택한 일정·기간을 전달한다. 자동 선택 위젯의 상세에서 추가할 때도 현재 보는 일정 ID를 고정한다. 시스템의 성공 콜백에서만 설정을 저장하고 미지원·조회 실패·삭제 상태는 안내한다.
- 성공 콜백은 요청별 고유 URI와 일회용 PendingIntent로 구분한다. 시스템이 새 위젯 ID를 넣어야 하므로 명시적 비공개 receiver에 한해 mutable을 사용한다. 반환 provider와 기존 설정 여부를 확인해 다른 위젯을 덮어쓰지 않는다. 새 선택은 기존 설정과 같은 저장 함수를 사용한다.
- 여러 갱신이 겹칠 때 오래 걸린 이전 조회가 새 선택을 덮어쓰지 않도록 렌더링을 직렬화했다. 위젯 삭제 후 들어온 갱신은 중단하고 pin 성공 방송의 수명은 실제 갱신 완료까지 유지한다.
- 최초 설치 검수에서 추가 창은 30sp, 설치 위젯은 56sp로 표시되는 차이를 발견했다. Android 12 이상 추가·생성 미리보기에 여러 크기의 RemoteViews를 제공해 큰 크기도 실제 설치와 같은 위계가 되도록 보완했다. 전후: `qa-widget-redesign/pin-confirm.png`, `qa-widget-redesign/pin-responsive-preview.png`, 설치 결과 `qa-widget-redesign/pin-installed.png`.
- 최종 코드 검증: `testDebugUnitTest assembleDebug lintDebug` 성공. **46개 테스트, 실패·오류·건너뜀 0개. Lint 오류 0개, 경고 108개, 힌트 4개.**
- 첫 검사에서 새 위젯 코드의 API 28 전용 `fallbackLineSpacing` 스타일과 줄바꿈 상수의 Lint 오류 2건을 수정했다. API별 스타일 상속을 분리하고 StaticLayout의 기본 simple 줄바꿈을 사용한다. 수정 중 생긴 API 상수 경고와 새 위젯 코드의 KTX 권고도 제거했다. 남은 경고를 이번 작업에서 모두 새로 발생한 것으로 분류하지 않는다. 이전 HEAD의 Lint를 별도 빌드한 비교는 수행하지 않았다.

### 시간 갱신 검토 결과

설치된 Android SDK 36의 `Chronometer.java`/`RemoteViews.java`를 추가 검토했다. 기본 카운트다운은 0초 이후 음수 길이를 표시하며 계속 진행한다. 시간 문자열 전체를 `%s`로 받는 형식이라 앱의 숫자·단위별 스타일을 그대로 유지할 수 없고, RemoteViews에서 앱의 tick listener를 연결해 다음 일정과 눈금을 재계산하는 경로도 없다. 이는 플랫폼 소스 검토이며 실제 절전·종료 경계 실험 완료가 아니다.

따라서 짧은 구간의 정밀 갱신은 미완료로 남긴다. 현재 30분 provider 주기, 앱 복귀·시간 변경 갱신, 수동 새로고침을 유지하며 실시간이라고 설명하지 않는다. 별도의 정확한 알람 권한이나 상시 서비스를 추가하지 않았다. [위젯 갱신 제약](https://developer.android.com/develop/ui/views/appwidgets/advanced), [시스템 pin 콜백 규칙](https://developer.android.com/reference/android/appwidget/AppWidgetManager#requestPinAppWidget(android.content.ComponentName,%20android.os.Bundle,%20android.app.PendingIntent)).


### 실제 화면·기능 검수

- Android 15/API 35, Pixel 7 임시 AVD, 기본 1080×2400/420dpi: 실제 앱에서 시간 일정 생성·저장 → 전체 일정 펼친 상세 → 위젯 추가 미리보기 → 홈 화면 설치 → 같은 일정 상세 진입을 확인했다. 위젯 ID 2의 선택 값은 일정 ID 1, focused, 남은 시간 표시였다. 이 일정은 검수용 AVD에서만 생성했다. 관련 캡처: `qa-widget-redesign/api35-expanded.png`, `api35-custom-pin.png`, `api35-installed-custom.png`, `api35-custom-detail.png`.
- Android 17/API 37, 기존 Pixel 9 Pro AVD, 1280×2856/480dpi: 오늘 상세에서 위젯 추가, 선택 저장, 설치 위젯 → 오늘 상세, 다시 추가 후 취소를 확인했다. 취소 전후 저장 값은 위젯 ID 6의 오늘/focused/남은 시간으로 동일했고 추가된 설정은 없었다. 추가 미리보기의 크기 대응 보완 전후도 이 환경에서 확인했다.
- API 37에서 이후 일정 편집으로 이동할 때 입력 응답 지연(ANR) 1건이 발생했다. 메인 스레드 기록은 `Settings.NameValueCache → DeviceConfig → AutofillManager → Activity.onResume`였다. 위젯 코드의 잠금/DB 대기 스택은 관찰되지 않았다. 시스템 초기화 경로를 가리키지만 근본 원인을 확정하거나 해결 완료로 처리하지 않는다. Android 15에서 같은 일정 추가·저장 경로와 pin 흐름은 재현되지 않았다. 기록은 `qa-widget-redesign/anr-dropbox.txt`, `last-anr.txt`에 남겼다.
- API 35 debug 갤러리에서 **실제 RemoteViews를 그린 이미지**로 다음을 확인했다. 별도 모형이나 PNG fallback 이미지를 실행 결과로 사용하지 않았다. 갤러리는 예시 ID로 실제 위젯을 추가하지 않도록 pin 행동을 비활성화한다.

## 크기 축소 후속 수정 (2026-09-21, 검증 대기)

사용자는 일반 위젯 4×2·기간 요약 4×1을 제안한 뒤 ‘수정 진행’으로 승인했다. 기본 크기에 큰 글자·세로 요약의 높이를 함께 강제하던 문제를 수정했다.

- 다섯 provider의 기본 배치: 오늘·이번 달·올해·내 일정은 4×2, 기간 요약은 4×1. 최소 및 최소 리사이즈 높이는 각각 180dp·64dp, 폭은 기존 250dp를 유지한다. 64dp는 48dp 터치 영역과 위아래 8dp 여백의 하한이며, 모든 내용·글자 배율을 보장하는 높이가 아니다. 실제 런처의 가용 크기와 내용 측정을 함께 사용한다.
- 단일 위젯은 높이 200dp 미만에서 세로 여백만 16→8dp로 줄인다. 가로 여백, 숫자·단위 크기, 48dp 새로고침, 보조 정보, 눈금은 유지한다. 큰 높이의 기존 배치는 유지한다.
- 요약은 공통 ‘남은 시간’ 제목과 그 아래 16dp 간격을 제거한다. 좌우 16dp·위아래 8dp, 열/행 사이 8dp, 이름과 값 사이 4dp를 사용한다. 기간명·숫자·단위는 12/22/12sp로 유지한다.
- 가로 열 너비는 실제 글자 폭으로 정한다. 각 열에 48dp 및 끊지 않을 숫자·단위 그룹 폭을 확보하고, 가능한 경우 기간명과 값 전체가 한 줄에 들어갈 폭을 배분한다. 부족하면 그룹 사이 줄바꿈, 높이가 충분하면 세로 배치를 시도한다. 맞지 않으면 글자를 줄이거나 기간을 숨기지 않고 확대를 안내한다. 각 기간의 직접 상세 진입은 유지한다.
- 설정 안내는 단일 4×2·요약 4×1로 구분한다. 크기 정보가 없거나 하한 미만인 경우의 예시는 단일 320×200·요약 320×96dp이며, 칸 수의 고정 환산값이 아니다. Android 12 이상 생성/추가 미리보기에는 짧고 넓은 크기도 포함한다. 미리보기 캐시 버전을 갱신하고 XML 및 한/영·밝게/어둡게 PNG 20개를 다시 생성했다.
- `WidgetTextMeasure`, `remainingTimeGroups`, `TimeRulerTokens`, 기존 위젯 팔레트·글자·간격 역할과 렌더러를 재사용한다. 저장 키·선택 항목·기존 provider 식별자·계산 및 갱신 주기는 이 후속 수정에서 변경하지 않았다.

확인 범위: 코드와 XML 구조·리소스 참조·문서 일관성을 검토하고 정적 PNG 대표 이미지를 확인했다. **빌드·Lint·단위 테스트·APK 설치를 실행하지 않았다.** 이전 46개 테스트 및 빌드 통과는 이번 수정 이전 결과다. 현재 설치된 앱은 새 코드와 다르다.

정적 추가 목록의 전후 이미지는 `qa-widget-redesign/picker-before-compact-today.png`, `picker-before-compact-overview.png` 및 `picker-after-compact-today.png`, `picker-after-compact-overview.png`에 남긴다. 이는 PNG 미리보기 비교이며 실제 위젯의 시각 검증 증거가 아니다. 실제 전후 화면은 최종 빌드 후 같은 데이터로 촬영해야 한다.

최종 검증 요청 시 추가할 조건:

1. 실제 런처 신규 추가에서 일반 4×2·요약 4×1이 선택되는지, 설치·크기 변경·설정·pin 미리보기가 같은 내용을 표시하는지 확인한다. 다른 launcher와 가로 회전은 칸 수보다 전달된 실제 크기를 기준으로 판단한다.
2. 실제 렌더러 갤러리의 `widget-today-4x2`, `widget-today-4x2-min`, `widget-overview-4x1`, `widget-overview-4x1-narrow`, `widget-overview-4x1-min`에서 대표 320×200/320×96, 좁은 250×96, 공간 하한 250×180/250×64를 확인한다. 마지막 하한 사례는 내용에 따라 확대 안내가 정상이다.
3. 한국어/영어·밝게/어둡게·글자 배율 1.0/1.3/2.0, 오늘 두 단위·올해 세 자리 일수·긴 제목·빈 상태·눈금 숨김을 확인한다. 숫자와 단위가 잘리지 않고 48dp 터치 영역 및 세 기간 상세 동선이 유지되는지 확인한다.
4. 짧은 요약에서 세로로 확대하면 세로 배치로 복구되는지, 넓고 낮은 미리보기에서 불필요한 확대 안내가 나오지 않는지 확인한다. Android 8–11 `TextView.setWidth`, Android 12–14 XML, Android 15+ 생성 미리보기는 별도 확인한다.


## Galaxy에서 4×3으로 남는 문제 보정 (2026-09-21, 적용 검증 대기)

사용자가 일반 위젯이 여전히 4×3으로 표시된다고 보고했다. 연결된 Galaxy A33의 앱·위젯 메타데이터만 읽어 조사했으며, 앱 설치·삭제·기존 위젯 변경은 수행하지 않았다.

- 설치된 앱은 버전 18/6.1, 설치 시각 2026-09-21 15:33:07이다. 설치 APK의 내 일정 provider에는 `targetCellWidth=4`, `targetCellHeight=2`, `minHeight/minResizeHeight=180dp`가 포함되어 있었다. 요약 최소 높이 리소스는 64dp다. 수정 전 APK가 남았다는 추측으로 처리하지 않는다.
- One UI Home의 실제 내 일정 위젯 두 개는 `semAppWidgetColumnSpan=4`, `semAppWidgetRowSpan=3`, 실제 제공 크기 375×323.33334dp였다. 좁은 콘텐츠 때문에 앱이 3행을 요청한 것이 아니라, 호스트가 처음부터 3행으로 배치하고 그 크기를 앱에 전달한 상태다. 원본은 `qa-widget-redesign/galaxy-widget-sizing-before.txt`에 앱 관련 부분만 보관했다.
- 표시 하한과 런처 크기 선언을 같은 값으로 쓰던 설계를 보완했다. `widget_host_min_height=110dp`, `widget_overview_host_min_height=40dp`를 추가하고 다섯 provider의 `minHeight/minResizeHeight`에 연결했다. `targetCellHeight=2/1`은 유지한다. 구형 셀 환산의 2행/1행 값이며 모든 기기의 실제 콘텐츠 높이가 110/40dp라는 뜻은 아니다.
- 실제 콘텐츠 표시 하한은 단일 250×180dp·요약 250×64dp 및 기존 내용 측정으로 유지한다. 글꼴·숫자·눈금·선택 항목은 이 보정에서 변경하지 않았다.
- 근거: [현재 Android 위젯 크기 지침](https://developer.android.com/develop/ui/views/appwidgets/layouts), [Google Android 교육 자료의 기존 셀 환산 기준](https://google-developer-training.github.io/android-developer-advanced-course-practicals/unit-1-expand-the-user-experience/lesson-2-app-widgets/2-1-p-app-widgets/2-1-p-app-widgets.html). 실제 One UI의 내부 계산 구현을 확인한 것은 아니므로, 이 보정의 최종 효과는 설치 후 검증해야 한다.

소스 XML과 참조를 확인했다. **빌드·Lint·단위 테스트·보정 APK 설치는 미실행**이다. 최종 검증 때 One UI Home의 추가 목록 및 pin 추가에서 4×2/4×1, 생성 후 실제 전달 크기와 내용 표시, 기존 4×3 위젯의 수동 리사이즈를 확인한다. 기존 위젯의 크기는 호스트가 보관하므로 기본 크기 설정 변경만으로 자동 축소된다고 안내하지 않는다.


## 시간·상태 한 행 및 시작·종료 라벨 (2026-09-21, 검증 대기)

사용자의 ‘시간과 남음을 한 행에 배치하고 시작·종료 시각 노출’ 분석 요청 이후 ‘진행’ 승인을 반영했다.

- 실제 단일 RemoteViews의 숫자와 상태를 한 TextView의 span으로 구성한다. 기존 숫자 30/56sp·단위 14sp, 상태 12sp·보조색을 유지하고 글자 밑선을 공유한다. 지역화된 `^1` 템플릿으로 한국어 ‘시작까지 42분’과 영어 ‘42 min until start’ 어순을 구분한다. 문자열을 비교해서 상태를 추측하지 않는다.
- 진행 중/남은 기간은 ‘남음’, 시작 전 시간 구간은 ‘시작까지’를 적용한다. 지난 날짜와 D-day/D+ 표시에는 ‘남음’을 붙이지 않는다. 빈 상태는 안내만 표시한다. 날짜·반복·남은 시간 계산과 설정 저장은 변경하지 않았다.
- 별도 보조 행은 범위가 표시될 때 제거한다. 눈금 숨김이나 범위가 없는 항목에는 기존 종료 문구를 유지한다. 시간→눈금 간격 16→8dp, 눈금→범위 간격 8→4dp다. 유효한 범위는 먼저 전체 높이에 포함해 들어가는지 계산하며, 라벨만 선택적으로 숨기지 않는다.
- 개인 날짜 일정의 이미 계산된 시작·종료 날짜를 AdapterItem의 원시 범위 라벨에 전달한다. 번역된 시작/종료 설명을 파싱하지 않는다. 왼쪽 시작·오른쪽 종료 라벨은 12sp이며 접근성 이름에 시작/종료 역할을 제공한다.
- 실제 단일 콘텐츠 하한은 250×160dp로 낮췄다. 모든 내용이 160dp에 들어간다는 뜻은 아니며 글자 배율·줄바꿈·라벨을 포함한 실제 높이 계산으로 표시 여부를 결정한다. 런처 선언 250×110dp 및 4×2는 유지한다. 요약 위젯의 레이아웃은 이번 변경 대상이 아니다.
- 공통 WidgetTextMeasure, 숫자·단위 span, 팔레트, TimeRulerTokens와 기존 XML 글자·간격 역할을 재사용했다. 실제 미리보기는 같은 렌더러를 사용하며 생성 미리보기 캐시를 갱신했다. 정적 단일 미리보기 XML 4개와 한/영·밝게/어둡게 PNG도 갱신했다. 값과 범위는 실제 데이터처럼 보이는 예시 대신 ‘—’로 표시한다.

코드·XML 및 리소스 참조를 검토하고 한/영·밝게/어둡게의 대표 PNG를 확인했다. 전후 정적 미리보기는 `qa-widget-redesign/picker-before-inline-today.png`, `picker-after-inline-today.png` 및 schedule 파일에 보관했다. 정적 미리보기는 네이티브 화면 검수가 아니다. **빌드·Lint·단위 테스트·설치·실제 화면 검수는 수행하지 않았다.**

최종 요청 시 실제 렌더러 갤러리와 런처에서 확인할 항목:

1. `widget-today-4x2`, `widget-schedule-4x2`, `widget-schedule-4x2-min`: 숫자+남음의 밑선, 시작·종료 라벨, 좁은 화면 및 실제 높이 160/180/200dp. 최소값에서 내용이 맞지 않으면 확대 안내가 정상이다.
