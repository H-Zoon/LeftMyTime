# 메인 화면 정보·행동 위계 보완

2026-11-09 후속: 새 Debug APK의 예시/실제 빈 홈·일정이 있는 홈, 320dp·큰 글자, 로딩/오류 표시를 확인했다. 실제 SDK의 스크롤 가림은 공개 표시/숨김 API로 수정하고 홈·전체 일정의 노출/숨김·Activity 복귀·같은 위치 복원을 재확인했다. 아래 모든 조건을 일괄 완료한 것은 아니며 [최종 검수 범위](QA_FINAL_2026-11-09.md)가 최신이다.

날짜: 2026-11-06. 사용자 지시: “메인 화면도 작업해야지”.

상태: **기존 Android 홈 소스 반영. 새 빌드·실행·시각 검수 대기.** 이미 선택한 A의 간결한 기본 화면과 [상세 보완](QA_TIME_DETAIL_REFINEMENT_2026-11-06.md)을 홈에도 확장했다. 새로운 디자인 방향을 다시 선택하는 작업으로 되돌리지 않았다.

## 해결할 문제

이전 실제 빈 홈에는 다른 기간·집중·시간 범위·날짜·일정 추가가 비슷한 주황 텍스트 행동으로 흩어져 있었다. 추가의 첫 행동이 분명하지 않았으며, 빈 상태의 제목은 시간 구간만 가리켰지만 날짜도 추가할 수 있었다. 일정이 있는 홈에서는 대표 숫자·눈금과 보조 행동 사이의 간격·묶음을 정돈할 필요가 있었다.

## 반영 내용

| 영역 | 최종 코드의 표현·동작 |
| --- | --- |
| 기간 요약 | 오늘·이번 달·올해를 같은 기존 숫자 역할로 유지. ‘다른 기간’을 제목 줄의 중립색 보조 행동으로 이동하고 정적 상세 안내는 값 아래 표시 |
| 빈 홈 | ‘일정을 추가해 보세요’ 제목, 설명, 채운 일정 추가 버튼 한 곳으로 통합. 별도의 시간/날짜 직접 버튼과 중복 추가 버튼 제거 |
| 추가 메뉴 | 기존 `ScheduleAddButton`을 기능 패키지 파일로 공유해 시간·날짜·저장한 일정·캘린더 진입을 그대로 연결. 메뉴와 버튼의 48dp·펼침 상태 이름 제공 |
| 전체 일정의 빈 상태 | 본문에 같은 추가 버튼 사용. 빈 상태에서는 상단의 중복 추가 아이콘 생략. 데이터가 있거나 로딩/실패일 때의 상단 추가 접근은 유지 |
| 일정이 있는 홈 | 대표 숫자·눈금 아래의 상세 보기와 집중 진입을 같은 감싸기 행에 묶음. 길거나 큰 글자는 다음 줄로 흐름 |
| 집중 진입 | 새 집중은 중립색, 기존 진행/일시정지 집중으로 돌아가기는 강조색. 빈 홈에서는 일정 추가 그룹 아래에 표시 |
| 상단 도구 | 전체 일정은 보조 색으로 표시하고, 폭 360dp 미만 **또는** 글자 배율 1.2배 초과이면 이름 있는 아이콘 사용 |
| 로딩·조회 실패 | 데이터 확인 전 ‘더 예정된 일정이 없습니다’ 문구를 표시하지 않음. 기존 상태·재시도는 유지 |

재사용한 기반은 `HeaderSection`, `RemainingTimeText`, `NextCountdownHero`, `TimeHeadline`, `TimeRuler`, `TimeLeftItemCard`, `QuickFocusSection`, `EmptyItemState`, 기존 추가 메뉴와 테마·간격·모서리다. `TimeLeftInlineButton`에 테마의 `ButtonColors`를 전달할 수 있게 했으며 기본값은 기존과 같다. 새 팔레트·글꼴·카드·링·그림자·장식 애니메이션을 추가하지 않았다.

진행 중 구간·고정·날짜 대표의 선택, 시작까지/종료까지 표기, 시간/날짜 각 최대 3개 목록과 대표 중복 제외, 전체 일정 검색·정렬·격자 설정, 계산·반복·알림·저장 형식은 그대로다. 현재 집중의 기존 RUNNING 우선·PAUSED 차순 선택을 화면 두 위치에서 공유하도록 같은 조건을 재사용했다. `MainActivity`의 기존 알림·PointHome 수정은 이 작업에서 수정하지 않았다.

PointHome 캐릭터는 SDK가 따로 올리는 UI다. 생성 시안과 debug 갤러리에는 SDK 오버레이를 그리지 않으며 실제 메인에서의 위치·메뉴/목록 겹침은 새 앱 검수에 포함한다. SDK 캐릭터의 스킨이나 제공 기능을 제거한 것으로 해석하지 않는다.

## 코드·문서 검토

- 빈 홈과 빈 전체 일정에서 `EmptyItemState`가 동일한 추가 메뉴를 사용하고, 선택한 항목의 기존 콜백으로 연결되는 구조를 검토했다.
- `QuickFocusSection`은 대표 안, 대표가 없는 비어 있지 않은 홈, 빈 홈 아래 중 한 곳에만 표시되도록 조건을 확인했다. 현재 세션·busy·error·열기 콜백을 모두 전달한다.
- `FlowRow`·자연 높이·기존 최소 터치 영역을 사용하며, 큰 글자에 맞추기 위해 숫자나 단위를 줄이거나 자르지 않았다.
- 한/영 빈 제목 리소스를 같은 의미로 수정했다. 새 데이터나 사용자 문구를 production 코드에 하드코딩하지 않았다.
- `DesignGallery.kt`의 실제 `HomeScreen`을 재사용하는 `home-review`, `home-review-empty`, `home-review-all-empty`, `home-review-loading`, `home-review-failed`, `home-review-progress-hidden`, `home-review-focus-busy`, `home-review-focus-error`를 추가했다. 고정 시각·2026-11-06 기간·예시 일정은 debug에만 둔다.
- XML 파싱·중복 키와 변경 경로의 공백 검사는 아래 실행 결과에 한정한다. Kotlin 컴파일이나 Android Lint 통과로 확대하지 않는다.

실행 결과: 한/영 `strings.xml` 파싱 성공·중복 키 없음, 빈 제목 양 언어 값 확인, 변경 경로 `git diff --check` 오류 없음, 보고서의 로컬 참조 5개 누락 없음. `ScheduleAddButton` 정의가 하나이며 호출이 공유되는 경로를 검색으로 확인했다.

## 최종 검증 요청 시 확인할 범위

사용자가 명시적으로 요청하면 `./gradlew testDebugUnitTest assembleDebug lintDebug`로 앞선 상세 변경과 현재 작업 전체를 검증한다. 기존 경고와 새 문제를 구분하고, 새 APK에서 다음을 확인한다.

1. 빈 상태·기간만 있는 상태·진행 중 구간·여러 구간·날짜만 있음·긴 제목·종료/잘못된 일정·숨김 설정, 시간 보드와 기본 A.
2. 한/영·밝게/어둡게·320dp/기본 폭·글자 1.0/1.5/2.0. 기간 세 항목과 초·단위 보존, 큰 글자의 상단 아이콘·행 감싸기·가로 넘침·스크롤.
3. 일정 추가 메뉴의 시간·날짜·저장한 일정·캘린더 각각 진입, 선택 취소·다시 열기, 전체 일정 빈 상태의 단일 진입과 데이터 생성 후 상단 아이콘 복원.
4. 집중 없음·진행·일시정지·busy·error에서 중복 없이 올바른 진입, 대표 일정 선택·고정과 상세/수정 동선 유지.
5. 오늘·달·년 상세 열기/닫기, 주·분기 진입, 원래 스크롤·키보드 포커스 복귀, TalkBack 이름·펼침 상태·48dp.
6. 로딩·조회 실패에는 거짓 빈 안내가 없는지, 재시도·작업 오류·불완전 항목 안내·전체 일정 접근, 검색·정렬·보기 설정.
7. 실제 MainActivity의 PointHome 플로팅과 메뉴·추가 버튼·집중·아래 일정 목록의 겹침.

**빌드·Lint·단위/계측 테스트·새 APK 설치·실행·위 조건의 시각 검수는 미실행이다.** 현재 설치할 수 있는 기존 6.8 APK는 이번 홈·앞선 상세 변경 전 상태다. 이미지나 debug 데이터 추가를 새 화면 검수로 취급하지 않는다.
