# 위젯 선택 방식과 설정 UI 개선 조사

작성: 2026-09-18. 대상: `8986d02` 이후 표시 항목 분리 작업이 반영된 현재 작업 트리.
상태: **후속 ‘개선 진행’ 승인에 따라 설정 UI·일정 검색·문구·용도별 런처 목록을 코드에 반영했다. 빌드·실행 검수 대기.** 아래는 조사 당시의 발견과 제안이며, 최종 적용 범위는 [구현 기록](QA_WIDGET_SELECTION_2026-09-18.md)을 따른다. 앱에서 바로 추가하는 pin 기능은 후속 범위로 남긴다.

기존 승인 범위와 구분: 오늘·이번 달·올해·기간 요약의 독립 선택, 기존 표시 보존, 재설정 복원, 실제 렌더러 공유 미리보기는 코드에 반영되어 있다. [구현 기록](QA_WIDGET_CONTENT_2026-09-18.md)을 참고한다. 이번에는 그 위에서 선택 과정과 UI를 조사했다.

조사 방법은 현재 소스와 Android 공식 문서 대조다. 실제 사용자 관찰·런처별 실행·새 화면 캡처는 하지 않았다. 아래 사용자 불편은 코드에서 확인한 구조를 바탕으로 한 평가이며, 사용성 측정 결과가 아니다. 빌드·Lint·단위 테스트는 사용자 지시에 따라 실행하지 않았다.

## 추천 방향

사용자 문제: **홈 화면에서 보고 싶은 내용을 고르려는데, 크기를 먼저 고르고 긴 설정 목록에서 내용을 다시 찾아야 한다.**

목표는 **내용 선택 → 결과 확인 → 적용**이다. 런처의 목록과 앱의 설정 화면은 별도로 개선한다.

- 런처 목록의 목표안: **오늘 / 이번 달 / 올해 / 기간 요약 / 내 일정**의 다섯 용도. 크기는 각 위젯 안에서 조절한다. 사용자들이 세 기간을 자주 확인한다는 피드백에 맞춰 각각 직접 찾을 수 있게 한다.
- 앱 설정의 우선 개선: 선택한 내용 요약, 해당 내용의 미리보기, 필요한 옵션만 표시한다. 전체 후보와 긴 일정 목록은 선택할 때 연다.
- 적용 순서: **설정 화면 정리 → 런처 이름·미리보기·기본 선택을 함께 변경 → 앱에서 위젯 추가 동선 검토**. 기존 설치 위젯을 없애면서 목록을 정리하지 않는다.

## 현재 코드에서 확인한 문제

| 확인한 구조·동작 | 예상되는 불편 | 개선 제안 |
| --- | --- | --- |
| 런처에 소형·중형·와이드·대형 네 항목. 모두 같은 여섯 콘텐츠를 설정 가능 | 내용 차이를 알기 전에 크기부터 판단해야 함 | 용도별 목록과 적절한 초기 크기·미리보기를 함께 제공 |
| 설정 순서가 큰 미리보기 → 여섯 선택 행 → 개인 일정 전체 목록 → 옵션 | 선택을 바꿀 때 미리보기가 화면 위로 벗어날 수 있음 | 선택 요약을 위에 두고 미리보기를 인접 배치. 후보 목록은 별도로 열기 |
| 직접 선택 목록은 제목만 표시하며 검색 없음 | 같은 제목을 구별하기 어렵고 일정이 많을수록 스크롤 증가 | 검색 + 제목 + 시간 구간/날짜를 표시. 선택한 일정만 설정 본문에 요약 |
| 오늘·이번 달·올해에도 ‘남은 시간으로 보기’ 스위치 노출 | 현재 표현에서는 켜고 꺼도 결과가 같음 | 세 기간과 기간 요약에는 숨김. 의미가 다른 개인 일정 표현에만 명시적 형식 선택 제공 |
| ‘곧 다가오는 일정’은 진행 중인 시간 일정을 먼저 선택 | 이름과 실제 선택 규칙이 다름 | ‘일정 자동 선택’으로 이름 변경하고 진행 중 우선임을 설명 |
| 기간 요약은 공간 부족 시 확대 안내만 나오지만 저장 가능 | 적용 후에도 남은 시간을 볼 수 없는 위젯이 생길 수 있음 | 저장 전에 크기 부족을 명확히 알리고 적용 후 조절 경로 안내 |
| 개인 일정 조회 실패·저장된 일정 삭제에 같은 문구 사용. 빈 목록 안내도 함께 나올 수 있음 | 사용자가 다시 선택해야 하는지, 재시도해야 하는지 불명확 | 로딩·빈 목록·삭제·조회 오류를 별도 상태로 표현 |
| 화면 제목은 ‘위젯’, 동작은 모두 ‘저장’. 화면 내 뒤로 가기 없음 | 새로 추가하는지 기존 위젯을 수정하는지 불명확 | 공통 상단바 ‘위젯 설정’, 새 추가는 ‘위젯 추가’, 재설정은 ‘변경 적용’ |
| 설정 미리보기는 실제 렌더러를 공유하지만 런처 PNG/미리보기 XML은 별도 | 추가 목록에서 본 이미지와 선택 결과가 달라질 수 있음 | 런처 미리보기도 새 기본 콘텐츠·A안·초기 크기에 맞춰 갱신 |

## 런처 선택 방식 비교

| 방안 | 장점 | 제약 | 판단 |
| --- | --- | --- | --- |
| 기존 네 크기 유지, 설정만 정리 | 기존 추가 경로 변경이 작음 | 사용자가 처음 보는 선택 기준은 여전히 크기 | 먼저 적용할 수 있는 단계 |
| 단일 시간 / 기간 요약, 두 종류로 통합 | 목록이 가장 짧음 | 오늘·달·년을 찾으려면 설정을 한 번 더 열어야 함. 기존 네 등록 항목 이행 필요 | 대안 |
| 오늘 / 이번 달 / 올해 / 기간 요약 / 내 일정 | 자주 찾는 기간을 추가 목록에서 바로 선택 | 기본값·초기 크기·미리보기·기존 설치 호환을 함께 다뤄야 함 | **목표안 추천** |
| 여섯 콘텐츠 × 네 크기를 모두 등록 | 모든 조합을 직접 선택 | 같은 목적의 항목이 24개가 되어 비교가 어려움 | 적용하지 않음 |

‘내 일정’ 안에서 자동 선택과 직접 선택을 제공한다. 자동·직접은 별도 외형이 아니라 표시할 일정을 정하는 방식이다. 기간 요약의 보조 설명은 ‘오늘·이번 달·올해를 함께’로 제안한다. 종류별 색상·카드·장식 아이콘을 새로 만들지 않는다.

Android는 런처에 주요 용도와 유용한 변형만 노출하고, 모든 조합을 나열하지 않도록 권장한다. 다섯 항목이라는 수와 구성은 이 앱의 이용 목적에 따른 제안이며 플랫폼 의무가 아니다. [공식 설정 디자인 안내](https://developer.android.com/design/ui/mobile/guides/widgets/configuration).

### 기존 위젯을 보존하는 이행 조건

- 기존 네 provider 컴포넌트는 삭제하거나 이름을 바꾸지 않는다. 사용자 화면의 명칭과 내부 컴포넌트 식별자는 구별한다.
- 기존 컴포넌트를 용도별 새 추가 진입으로 재사용하고 부족한 항목만 추가하는 방안을 우선 검토한다. 기존 네 항목에 새 다섯 항목을 단순히 추가하면 목록이 아홉 개가 되므로 목표와 맞지 않는다.
- 새로 생성된 위젯에는 진입한 용도의 기본값을 적용한다. 기존 위젯의 저장된 source·일정 ID·표시 옵션·기존 요약 모드는 항상 우선한다. 기존에 값이 누락된 경우의 종전 처리도 검토 없이 바꾸지 않는다.
- 최초 크기와 최소 크기는 콘텐츠에 맞춰 정하되, 이미 설치된 위젯의 사용자가 정한 크기를 일괄 변경하지 않는다. 새 이름·미리보기만 바꾸고 모든 신규 위젯을 계속 ‘오늘’로 시작시키면 안 된다.
- 실제 항목 순서·배치·재설정 메뉴는 런처가 제어한다. 앱이 모든 런처에서 같은 순서와 화면을 보장할 수는 없다.
- 네 기존 provider가 모두 설치된 상태에서 업데이트하는 검수가 필요하다. 이행 구현과 검수 전에는 호환 완료로 기록하지 않는다.

## 설정 화면 추천 구성

큰 실제 미리보기와 전체 후보를 항상 한 화면에 나열하기보다, **현재 선택과 그 결과**를 본문에 둔다. 후보를 펼치는 데 한 번의 조작이 더 필요하지만 미리보기와 일정·표시 옵션의 관계를 읽기 쉬워진다.

| 위에서 아래 순서 | 표시 내용·행동 |
| --- | --- |
| 공통 상단바 | 뒤로 가기, ‘위젯 설정’. 뒤로 가기는 이번 변경을 적용하지 않고 종료 |
| 표시할 내용 | ‘오늘’ 등 현재 선택 + ‘변경’ 텍스트 동작. 반복 화살표 없음 |
| 선택한 일정 | 직접 선택일 때만 제목·시간/날짜 + ‘변경’. 자동 선택이면 선택 규칙 설명 |
| 미리보기 | 실제 선택·현재 크기·글자 배율로 렌더링. ‘현재 크기’와 크기 부족 상태를 바로 설명 |
| 표시 형식 | 결과가 달라지는 일정에만 노출. 서로 다른 결과를 예시로 비교 |
| 기존 표시 옵션 | 기존 요약 모드를 가진 위젯에만 관련 설정을 점진적으로 노출 |
| 하단 주 행동 | 추가/변경 적용. 작은 화면·큰 글자에서도 본문은 스크롤되고 행동은 접근 가능 |

‘변경’을 누르면 하나의 선택 패널에서 **기간**(오늘·이번 달·올해·기간 요약), **일정**(일정 자동 선택·일정 직접 선택)으로 묶는다. 탭 없이 소제목과 간격을 쓰고 전체에서 하나를 선택한다. 일반 항목은 선택 즉시 패널을 닫고 새 미리보기를 보여준다. 이 선택만으로 실제 위젯에 저장하지는 않는다.

직접 선택은 같은 선택 흐름 안에서 검색 가능한 일정 목록으로 이동한다. 하단 패널을 겹쳐 열지 않는다. 기존에 고른 일정이 있으면 복원하고, 제목 외 시간 구간/날짜로 동명이항목을 구별한다. 선택을 취소하면 이전 선택을 유지한다. 일정이 많을 때만 의미 없는 빈 검색 UI를 숨기는 식의 임의 기준을 만들지 않고, 검색 위치와 동작을 일관되게 유지한다.

신규 위젯의 기본 선택과 초기 미리보기는 제공한다. 런처 목적별 개편 전에는 현재 신규 기본값인 오늘을 유지하고, 개편 후에는 진입한 항목의 기본값을 사용한다. 재설정은 기존 선택을 먼저 복원한다.

Android 공식 안내도 설정 경로를 짧게 유지하고, 명확한 완료 행동과 외형 변경의 미리보기를 제공하도록 권장한다. 위 구성은 이를 현재 A안에 맞춘 제안이다. [공식 설정 디자인 안내](https://developer.android.com/design/ui/mobile/guides/widgets/configuration).

### 크기 안내와 미리보기

공간 부족 시 ‘크기를 늘려 주세요’만 보여주는 것은 현재 코드의 안전한 대체 표시지만, 시간 확인이라는 위젯의 목적을 충족한 상태는 아니다.

- 크기에 맞으면 일반 미리보기만 표시한다. 기간 요약의 긴 크기 설명을 항상 반복하지 않는다.
- 부족하면 **‘현재 크기에는 세 기간이 모두 들어가지 않아요. 적용 후 홈 화면에서 위젯을 길게 눌러 크기를 늘려 주세요.’**를 제안한다. 실제 크기 조절 동작은 런처별로 검수해 문구를 확정한다.
- 설정 화면에서 저장만 막으면 사용자가 여기서 크기를 바꿀 수 없어 막힐 수 있다. 크기 조정 필요를 설명한 상태에서 적용하거나 다른 내용을 선택할 수 있게 한다. 단일 기간으로 자동 변경하지 않는다.
- 적합성 판단은 `WidgetOverview`와 공유한다. 별도 고정 숫자로 가로/세로 가능 여부를 다시 계산하지 않는다. 모든 기기에서 ‘4×2면 충분’하다고 단정하지 않는다.
- 넓은 미리보기는 실제 글자 크기를 유지한다. 가로 스크롤이 필요한 경우에만 ‘좌우로 밀어 전체 보기’ 안내를 제공한다. 휴대폰 화면에 맞추려고 접근성 글자를 줄이지 않는다.
- 설정에서 가상 크기 예시를 추가한다면 ‘크기 예시’로 표시하고, 실제 홈 화면 크기를 바꾸는 기능과 구분한다. 1차 범위에서는 크기 슬라이더를 추가하지 않는다.

런처 이미지도 실제 최초 콘텐츠와 크기에 맞춰야 한다. 현재 설정의 공유 렌더러가 런처의 정적 미리보기까지 자동으로 갱신해 주지는 않는다. [공식 발견·미리보기 안내](https://developer.android.com/design/ui/mobile/guides/widgets/discovery-promotion).

### 표현과 상태

- ‘곧 다가오는 일정’ → **‘일정 자동 선택’**. ‘진행 중인 일정을 우선 표시해요’로 설명한다. 현재 선택기는 모든 날짜 일정이 지난 경우 첫 일정을 반환하는 경로도 있으므로 ‘항상 다가오는 일정만 표시’라고 안내하지 않는다. 종료 일정만 남았을 때의 정책 변경은 별도 동작 변경으로 다룬다.
- ‘내 일정’의 선택 방식 → **‘일정 직접 선택’**. 런처의 ‘내 일정’ 이름과 구분한다.
- 오늘·이번 달·올해·기간 요약은 표시 형식 선택을 숨긴다. 저장된 기존 옵션은 삭제하지 않는다.
- 개인 일정은 **‘표시 형식’** 아래 단위 표현과 시계/D-day 표현을 실제 결과 예시로 구별한다. 예: `42분`과 `00:42`, `12일`과 `D-12`. 예시는 설명용이며 실제 미리보기에는 선택 일정의 값을 쓴다. 자동 선택은 시간·날짜 일정 모두 선택될 수 있음을 고려한다.
- 시작 전 시간 구간은 현재 두 옵션의 출력이 같다. 옵션을 보여줄 때 적용되는 시점을 설명하거나 이 상태에서 숨기되, 저장된 선호를 초기화하지 않는다.
- 직접 선택의 빈 목록은 ‘등록된 일정이 없어요’와 다른 표시 내용 선택 경로, 삭제된 일정은 ‘선택한 일정이 삭제됐어요’와 다시 선택, 조회 오류는 ‘일정을 불러오지 못했어요’와 재시도를 제공한다. 서로 다른 안내를 겹쳐 표시하지 않는다.
- 자동 선택에서 빈 목록은 앞으로 일정이 생기면 자동 표시할 수 있는 상태다. 직접 선택에 필요한 일정 ID가 없는 상태와 저장 가능 여부를 구분한다.

## 재사용과 작업 단위

| 순서 | 작업 | 재사용·변경 경계 |
| --- | --- | --- |
| 1 | 설정 본문·선택 패널·일정 검색·문구·크기 안내 | `TimeLeftTopAppBar`, `TimeLeftUnderlineTextField`, `TimeLeftTheme`, `Spacing`, `LayoutTokens`. 미리보기는 `AppWidget.previewViews`, 크기 적합성은 `WidgetOverview` 공유 |
| 2 | 런처 목적별 목록·기본 콘텐츠·정적 미리보기 | 기존 provider 식별자와 설정 키 보존. 신규 진입 기본값만 명시적으로 구분. 새 미리보기 리소스는 디자인 규칙과 함께 검수 |
| 3 | 앱 안에서 ‘홈 화면에 위젯 추가’ | 공통 선택 UI를 재사용하는 별도 기능. 자동 선택 알고리즘·갱신 주기 변경과 묶지 않음 |

카드·링·그라데이션을 추가하지 않는다. 선택 패널은 기존 표면 역할을 사용하고 목록은 라디오 선택 상태·텍스트·간격으로 구별한다. 터치 영역은 최소 48dp, 긴 제목과 큰 글자는 줄바꿈한다. 사용자 문구는 한국어/영어 리소스에 함께 관리한다.

## 앱에서 바로 추가하는 후속 기능

설정의 ‘위젯’ 또는 일정 상세에서 추가 동선을 제공하면, 앱 안에서 내용을 고른 뒤 홈 화면에 배치할 수 있다. 홈의 시간 확인을 가리는 상시 홍보 배너보다 사용자가 관련 행동을 할 때 찾을 수 있는 진입이 적합하다. [공식 발견 안내](https://developer.android.com/design/ui/mobile/guides/widgets/discovery-promotion).

Android 8.0 이상과 지원 런처에서는 `requestPinAppWidget`을 사용할 수 있다. 현재 앱에는 이 경로가 없다. 지원 여부를 확인하고 기존 런처 추가 경로도 유지한다. [공식 구현 안내](https://developer.android.com/develop/ui/views/appwidgets/discoverability).

이 API는 기존 설정 Activity를 자동으로 열어 주지 않는다. 앱에서 먼저 선택을 받고, 성공 콜백의 실제 위젯 ID에 연결해야 한다. 호출 결과 `true`는 배치 완료가 아니며 사용자 거절 시 콜백도 오지 않는다. 여러 추가 요청의 설정이 섞이지 않도록 요청별 선택을 보존해야 한다. 따라서 버튼 하나를 붙이는 작업과 구분한다. [AppWidgetManager API](https://developer.android.com/reference/android/appwidget/AppWidgetManager#requestPinAppWidget(android.content.ComponentName,android.os.Bundle,android.app.PendingIntent)).

## 구현 후 확인할 조건

- 여섯 콘텐츠 선택, 선택 취소, 추가/재설정 완료, 기존 선택 복원, 회전·재생성 중 선택 보존.
- 일정 없음·조회 실패·삭제된 일정·동일 제목·긴 제목·많은 일정·검색 결과 없음. 검색 입력 후 뒤로 가기와 키보드 동작.
- 밝게/어둡게, 기존 팔레트, 한국어/영어, 320dp·큰 글자 1.5배 이상, TalkBack 이름·선택 상태·초점 복귀.
- 선택 결과와 실제 위젯의 같은 내용·형식. 요약 크기 부족·확대 후 복구. 화면 폭을 넘는 미리보기 접근.
- 네 기존 provider의 서로 다른 크기·콘텐츠·옵션이 설치된 상태에서 업데이트. 신규 용도별 추가 및 기존 위젯 재설정·취소 후 값 유지.
- 지원 OS와 실제 런처에서 추가 목록의 이름·초기 크기·미리보기·재설정 메뉴 확인. 이전 검수 화면을 이번 변경 검수로 대체하지 않음.

이번 조사에서는 문서와 로컬 링크만 점검한다. 위 조건의 실행 확인 및 빌드·Lint·단위 테스트는 명시적 최종 검증 요청 이후 수행한다.
