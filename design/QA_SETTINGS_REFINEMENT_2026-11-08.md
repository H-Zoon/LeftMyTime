# 설정 화면 정보와 조작 정리

2026-11-09 후속: 새 Debug APK의 실제 설정·메뉴와 BAR_ONLY 표시 예시, 리워드 상세 상단/시스템 뒤로가기·회전·스크롤 복원·동의 메타데이터 불변을 확인했다. 테마 오류 설명 누락을 수정 후 같은 조건으로 재확인했다. 실제 수신·모든 저장값/접근성 조건까지 완료한 것은 아니며 [최종 검수 범위](QA_FINAL_2026-11-09.md)가 최신이다.

날짜: 2026-11-08. 사용자 요청: “설정 화면의 AI 스러움도 개선 진행”. 승인된 A ‘시간 중심’과 실제 설정 코드를 이어서 정리했다.

상태: **소스 반영 완료. 변경 전 6.8 APK의 가상머신 화면은 확인했다. 새 코드의 빌드·Lint·단위/계측 테스트·설치·시각/조작 검수는 미실행.**

## 실제 화면에서 확인한 문제

읽기 전용 `Pixel_10_Pro_XL`, Android 17/API 37.2, 소프트웨어 렌더러에서 기존 `TimeLeft-6.8-25.apk`를 새로 설치했다. 영어·밝게·글자 1.0배, 1344×2992px·480dpi(폭 448dp) 조건이다. 실제 홈의 설정 버튼으로 들어가 본문을 스크롤했다. 새 Gradle 작업은 실행하지 않았다.

| 단계 | 관찰한 화면 | 문제와 적용 방향 |
| --- | --- | --- |
| 1. 설정 진입 | [상단 캡처](qa-settings-refinement-2026-11-08/01-before-top.png) | 테마 진입에 디자인 이름·모드/색상·오늘 숫자·눈금·강조 문구·화살표가 겹친다. 실제 테마 비교는 이미 전용 화면에 있으므로 현재값 중심의 한 행으로 정리한다. |
| 2. 알림 구간 | [알림 캡처](qa-settings-refinement-2026-11-08/02-before-lower.png) | 새 일정에 적용한다는 설명이 두 번 반복되고, 반씩 배정한 열 때문에 짧은 값 옆의 영어 항목명이 두 줄이 된다. 리마인더 설정 바로 뒤에는 종류 구분 없이 긴 광고 동의 고지가 이어진다. 공통 설명은 한 번, 짧은 값은 자연 너비, 리워드는 현재 상태와 전용 상세로 나눈다. |
| 3. 데이터·개인정보 | [하단 캡처](qa-settings-refinement-2026-11-08/03-before-bottom.png) | 같은 화면의 분류가 길게 이어지고 개인정보 안내와 버전이 별도 섹션이다. 일정 데이터와 앱 정보로 정리하며 수집 안내 본문은 계속 표시한다. |

기존 화면도 공통 서체·바탕·최소 터치 영역·구분선을 사용하고 있었다. 문제는 새 팔레트나 장식 부족보다 중복된 표현과 정보 배치다. 스크린샷만으로 TalkBack·키보드·큰 글자·상태 복원이나 접근성 준수를 판정하지 않았다. 하단의 이야기 보관함은 이전 작업에서 이미 소스에서 제거했으나 이 6.8 APK에는 남아 있다.

## 소스 반영

- 화면 → 일정 목록 → 알림 → 일정 데이터 → 앱 정보의 다섯 묶음. 테마와 진행 표시를 함께 두고, 기본 정렬과 지난 일정은 목록에 둔다.
- `ThemePreviewEntry`는 기존 `SettingsNavigationRow`를 공유해 테마 이름·현재 디자인/색상/화면 모드·화살표만 제공한다. 실제 앱/위젯 테마 비교·적용·취소는 기존 `ThemePreviewScreen`을 유지한다.
- 새 일정 기본 알림은 짧은 날짜/시간 이름과 선택값을 표시한다. 적용 범위 설명은 두 행 아래 한 번만 제공한다. 기존 일정 알림을 변경하지 않는다는 점을 명시했다.
- `SettingsDropdownRow`의 값은 자연 너비로 측정한다. 긴 값의 상한은 행 폭 45%이며 이 비율은 이 행의 열 배분에만 쓴다. 기존 300dp 미만 또는 글자 배율 1.2배 초과의 세로 배치를 유지하고 축소·말줄임을 추가하지 않는다. 같은 행을 쓰는 테마 옵션도 최종 검수에 포함한다.
- 메인의 리워드 행은 기존 저장 선택·전송 반영·시스템 허용 상태의 같은 분기를 공유한다. 누르면 `RewardPreferencesScreen`에서 기존 `RewardNotificationPreferences`의 고지·스위치·상태·재시도·시스템 설정을 제공한다. 스위치 앞 고지와 동의·권한·구독 콜백은 유지했다. 기존 알림 액션의 직접 수신설정·철회·리워드 열기 화면도 유지한다.
- `rememberSaveableStateHolder`로 메인 설정의 스크롤을 상세 전환 중 보관한다. 리워드 상세의 상단 뒤로가기·시스템 뒤로가기는 메인으로 돌아온다. 새 영구 설정 키는 만들지 않는다.
- 탐색 행은 이름 있는 버튼 역할, 섹션 제목은 heading 의미를 제공한다. 기존 `SettingsScaffold`, `TimeLeftSection`, `TimeLeftSwitchRow`, `TimeLeftTopAppBar`, `TimeLeftTheme`, `Spacing`·`LayoutTokens`를 재사용한다. 새 카드·그림·색·글꼴을 추가하지 않았다.
- 한/영 문구를 함께 수정했다. 개인정보 수집 안내·동의 고지의 발신자/내용/시간과 선택 정책은 유지하고 수신거부 안내 경로만 새 상세까지 명시했다. 로컬 방침 원본·Hosting 소스·발송 안내 예시를 함께 맞췄으며 공개 배포나 Console 메시지 변경은 하지 않았다. 그 외 일정·DB·설정값·알림 예약/수신 정책·계측·위젯 로직을 변경하지 않는다.

## 정적 확인과 실행 검수 대기

한/영 XML 파싱·중복 키 없음·포맷 인자 일치·추가 3개 키 존재·설정/갤러리 문자열 참조 해소·제거한 매개변수 잔여 호출 없음·`git diff --check`를 확인했다. 기존 설정 선택·동의·알림 관련 함수 9개는 HEAD와 본문이 같다. 기존 직접 수신설정의 본문과 콜백도 유지했다. 이는 빌드·실행 통과가 아니다.

명시적 최종 검증 요청 시 전체 변경의 `./gradlew testDebugUnitTest assembleDebug lintDebug`와 함께 다음을 확인한다.

1. 한/영·밝게/어둡게·320dp·큰 글자 1.5배·긴 버전/디자인 이름, 빈 일정·일정이 있는 상태. 제목·현재값·고지의 잘림/겹침과 모든 터치 영역을 확인한다.
2. 기본 정렬·지난 일정·진행 표시·날짜/시간 기본 알림·날짜 알림 시각의 실제 저장/복원. 기존 일정의 기본 알림과 반복/알림 예약이 외관 변경으로 바뀌지 않아야 한다. 알 수 없는 기존 선택값·막대만 표시도 확인한다.
3. 테마 진입·앱/위젯 비교·적용·취소, 데이터 조회 로딩/실패/빈 상태, 모드 선택 메뉴의 긴 값과 줄바꿈. 메인에 실시간 견본이 없고 현재 디자인/색/모드는 정확해야 한다.
4. 리워드 상세의 동의 켜짐/꺼짐·읽기 중/읽기 실패·반영 중·철회 중·확인 실패·재시도·시스템 차단. 단순 진입과 복귀로 선택·시각·고지 버전·권한이 바뀌지 않아야 한다. 실제 동의와 철회, 시스템 설정 복귀 및 기존 알림 액션의 직접 수신설정도 확인한다.
5. 메인 스크롤 → 리워드 상세 → 상단/시스템 뒤로가기, 회전/프로세스 복원, 테마 취소/적용 후 복귀. `DesignGallery`의 실제 화면을 쓰는 `settings-rewards-*`, `settings-reward-detail-*`를 보조로 사용한다. 갤러리는 로컬 상태만 바꾸며 실수신/저장 증거가 아니다.
6. 저장한 일정·백업·개인정보처리방침 진입과 버전 표시. TalkBack의 행 이름·현재값·선택·펼침·heading·스위치 및 읽기 순서를 확인한다.

변경 후 캡처는 새 APK 검수 때 같은 조건으로 `design/qa-settings-refinement-2026-11-08/`에 추가한다. 현재 세 캡처는 모두 **변경 전**이다. 최신 구현을 실행하거나 새 UI를 시각 검수했다고 보고하지 않는다.
