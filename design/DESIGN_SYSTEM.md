# LeftMyTime 디자인 기준 v2 — A안 · 시간 중심

확정일: 2026-09-18. 사용자가 A/B/C 시안을 비교한 뒤 **“A안으로 확정”**이라고 선택했다.
상태: **A안 앱 구현 완료 / 에뮬레이터 검수 기록 별도 관리**. 이후 UI 작업은 이 문서를 기준으로 한다.

기존 구현과 검수 환경은 [v1 기록](DESIGN_SYSTEM_V1.md), 비교 과정은 [개편안과 결정 기록](REDESIGN_PROPOSAL.md)에 보관한다.
v1의 둥근 글꼴·카드·진행 링 유지 규칙보다 이 문서가 우선한다. 1차 구현은 [v2 검수 기록](QA_V2_2026-09-18.md), 상단 기간 요약은 [후속 검수 기록](QA_FLOW_2026-09-18.md), 현재 상세 진입 방식은 [안내 보완 기록](QA_PERIOD_HINT_2026-09-18.md)에서 실제 확인 범위를 관리한다.

## 제품의 중심

**지금 하는 일과 하루·달·년에 얼마나 남았는지, 열자마자 읽을 수 있는 조용한 시간 도구.**

사용자가 확인한 주요 용도는 업무·공부 등 짧은 시간 구간과 하루·한 달·1년의 남은 시간이다.
두 용도를 모두 홈에 둔다. 짧은 구간만 강조해 하루·달·년을 설정 속으로 옮기지 않는다.
기존 시작/종료 시각 모델과 날짜 일정 기능을 유지한다.

## 확정한 시각 언어

- **큰 남은 시간 숫자 + 얇은 시간 눈금**을 대표 형태로 쓴다.
- 중립적인 산세리프 글꼴, 따뜻한 회백색 바탕, 짙은 먹색 글자, 절제한 주황 강조색을 기본으로 한다.
- 대표 숫자는 한 화면에 하나만 가장 크게 둔다. 제목·종료 시각·단위는 이를 보조한다.
- 목록은 간격과 구분선으로 묶는다. 모든 내용을 둥근 카드로 감싸거나 각 행에 진행 링을 반복하지 않는다.
- 색은 현재 위치·남은 눈금·선택을 구별할 때 쓴다. 주요 숫자와 제목은 기본 글자색으로 읽히게 한다.
- 장식용 그라데이션·그림자·배지·진입 시 0부터 채워지는 애니메이션은 추가하지 않는다. 2026-09-21 승인한 남은 눈금 뒤 글로우만 시간의 남은 범위를 보조하는 한정된 예외로 둔다.
- 2026-09-23 승인한 상세의 숫자 진입·직접 조작 반응은 아래 ‘상세 인터랙션’ 범위에서만 사용한다. 홈·목록 전체의 자동 반복 움직임으로 확장하지 않는다.

B의 세리프 숫자와 C의 계기판 서체를 화면별 취향에 따라 혼합하지 않는다. 새로운 디자인 결정은 이 문서에 먼저 반영한다.

## 홈의 정보 순서

1. 앱 이름과 설정 진입.
2. 상단의 남은 시간 요약: 오늘 / 이번 달 / 올해를 작은 숫자로 함께 표시. 같은 화면 바탕과 얇은 구분선을 사용한다.
3. 대표 일정: 진행 중인 시간 구간을 우선한다. 없으면 종료일이 가장 가까운 유효한 날짜 일정을 표시한다. 상태·종료 시각/날짜 → 제목 → 큰 남은 시간/일수 → 시작/현재/종료 눈금 순서다.
4. 다음 일정: **시간 구간 / 날짜 일정**을 작은 제목으로 구분하고 기존 목록 행을 공유한다. 시간은 **시작까지**, 날짜는 **종료일까지**의 남은 길이다. 각 종류 최대 3개를 독립적으로 표시하고 대표 일정은 반복하지 않는다. ‘일정 추가’에서 시간 범위와 날짜를 모두 선택한다.
5. 전체 일정 관리: 모든 일정, 검색, 정렬, 기존 보기 방식에 접근할 수 있는 보조 동선.

대표 구간을 바로 아래 목록에서 같은 강조도로 반복하지 않는다. 전체 일정 관리에서는 해당 일정을 계속 찾고 수정할 수 있어야 한다.
검색·정렬을 보조 동선으로 옮기더라도 기존 기능과 사용자 설정을 없애지 않는다. 전체 일정은 홈 상단에서만 연다. 다음 구간 아래의 ‘전체 일정 N개 보기’는 중복 진입이므로 표시하지 않는다. 일정 개수는 기존 전체 일정 화면에서 확인한다. 좁은 화면·큰 글자는 상단 진입을 이름 있는 아이콘으로 바꾼다.

2026-09-18 후속 승인: 상단 요약은 개인 일정과 시각적 위계를 분리하기 위한 변경이다. 최상위 탭·회색 카드·고정 헤더를 추가하지 않는다. 공통 ‘자세히’ 버튼을 두지 않고 **‘각 기간을 누르면 자세히 볼 수 있어요’**라는 정적인 안내를 표시한다. 기간마다 반복되는 화살표는 산만하다는 사용자 피드백에 따라 표시하지 않는다. 이름과 숫자를 포함한 항목 전체를 누르면 **그 기간**의 큰 숫자와 눈금이 하단 상세로 열린다. 안내문은 별도 버튼이 아니다. 상세를 닫으면 홈의 스크롤 위치를 유지한다.

마지막으로 본 기간은 저장하거나 복원하지 않는다. 기존 `home_header_index` 값은 마이그레이션·삭제 없이 남겨 두지만 읽거나 쓰지 않는다. 화면 회전 중 열려 있는 상세를 유지하는 임시 UI 상태와 마지막 기간 설정은 구별한다.

세 기간의 주 숫자는 같은 `titleLarge`(22sp)·중립색을 사용하며, 요약에서는 제목 ‘남은 시간’이 공통 의미를 전달하므로 값마다 ‘남음’을 반복하지 않는다. 접근성 이름은 기간과 남은 길이를 함께 제공한다. 오늘은 시·분에 보조 크기의 초를 붙이며 가로 폭을 더 배분한다. 시·분과 다른 기간의 주 숫자 위계는 동일하다. 가용 폭 300dp 미만 또는 글자 배율 1.2배 초과에서는 세로 행으로 배치한다. 글자나 기간을 숨기지 않는다.

상세는 `TimeDetailContent` 안에서 `RemainingTimeText`와 `TimeRuler`를 재사용한다. 남은 시간·눈금·경과/남은 비율·전체/지나간 길이·‘이만큼의 시간’ 순서로 표시한다. 전체/막대만/숨김 설정에 따라 비율과 눈금을 조절한다. 일수는 기존 계산대로 오늘을 제외한 날짜 수임을 설명한다. 달·년의 경과율은 오늘을 포함한 날짜 기준임을 명시한다. 하루 경계는 기존 00:00–23:59:59, 달·년은 실제 시작일/마지막 날을 유지한다.

2026-09-23 후속 승인: 날짜 일정이 전체 일정 안에만 숨는 문제를 해결하기 위해 홈에 직접 노출한다. 진행 중인 시간 구간 선택은 유지하며, 날짜 대표는 남은 일수→ID 순으로 정한다. 시작 전 날짜도 종료일까지의 일수를 보여주되 ‘시작 전’과 시작/종료일을 함께 표시한다. 오늘까지인 날짜는 `0일 남음` 대신 **‘오늘까지’**, 양수는 **‘12일 남음’**, 지난 날짜는 전체 일정에서 **‘3일 지남’**으로 읽는다. 날짜 목록이 반복 시간 구간에 밀려 사라지지 않게 각 종류의 수를 따로 제한한다. 종료·잘못된 범위·날짜 정보가 없는 일정은 대표/홈 날짜 목록에 넣지 않고 전체 일정의 기존 표시/맨 아래/숨김 설정과 수정 동선을 유지한다. 상단 요약, 공통 숫자·눈금·상세 시트를 재사용하며 탭·추가 카드·하단 전체 일정 링크를 만들지 않는다. 검수 조건과 전후 캡처 대기는 [홈 날짜 일정 기록](QA_HOME_DATES_2026-09-23.md)을 따른다.

## 시간 표현

- 큰 숫자와 단위는 **남은 시간**이다. ‘42분 남음’, ‘15:00까지’, ‘시작까지’처럼 뜻을 직접 쓴다.
- 눈금의 지나간 부분은 중립색, 남은 부분은 강조색으로 표시한다. 시작·현재·종료 라벨로 색 이외의 단서를 준다.
- 내부의 기존 `percent`는 경과 비율로 유지한다. 남은 표현은 `1 - 경과 비율`로 파생하며 저장값의 의미를 뒤집지 않는다.
- 눈금 수는 화면 폭에 맞게 조정한다. 모든 구간에 눈금 1개가 1분이라는 의미를 부여하지 않는다.
- 현재 위치가 시작/종료 라벨과 겹치면 현재 시각을 별도 줄로 옮긴다. 의미 있는 숫자를 겹쳐 놓지 않는다.
- 대표 시간의 단위는 길이에 맞게 표시하고 숫자가 줄마다 흔들리지 않게 한다. 홈 대표 구간·오늘 요약·오늘/시간 구간 상세는 1초 단위로 표시하며 1분 미만도 실제 초를 보여준다. 초를 숨기는 목록·위젯의 기존 ‘1분 미만’ 표현은 유지한다.
- 초는 두 자리와 같은 숫자 폭을 사용한다. 시·분과 함께 표시할 때 보조 숫자로 두고 초만 남으면 주 숫자가 된다. 매초 등장/이동 애니메이션이나 강제 음성 낭독을 추가하지 않는다. 기존 1초 계산 흐름을 재사용한다.
- 같은 줄의 시·분·초 묶음은 숫자의 첫 baseline으로 정렬한다. 묶음 안의 숫자와 단위도 같은 기준선을 사용한다. 큰 글자에서 단위를 아래로 옮겨도 숫자의 기준선을 유지한다. 세로형 기간 요약의 이름·시간, 상세 정보의 이름·값도 첫 baseline을 맞춘다. 상세 정보는 이름/값 1:2 열과 16dp 간격, 값 오른쪽 정렬을 사용하고 긴 내용은 줄바꿈한다.
- 상세 경과율은 소수점 한 자리로 표시하고, 눈금과 글로우는 반올림 전 비율을 사용한다. 완료 직전 활성 구간은 99.9%를 상한으로 표시하고 실제 종료 상태에서 완료로 전환한다. 달·년의 날짜 기준 100% 의미는 유지한다.
- 하루·달·년은 실제 달력 경계와 기기 시간대를 기준으로 계산한다. 월을 30일, 연을 365일로 고정하지 않는다.
- 시안의 14:18·42분·예시 일정은 검수 데이터다. 실제 화면에 기본 일정이나 계산값으로 하드코딩하지 않는다.

## 상세 인터랙션 (2026-09-23)

사용자가 조사안과 추천 반응 전체의 구현을 승인했다. `TimeDetailSheet`·`TimeDetailContent`를 오늘/달/년과 개인 일정, 위젯에서 연 앱 상세가 공유한다. 개인 일정은 대표 구간 하단과 펼친 목록의 **‘시간 자세히 보기’**로 연다. 제목의 기존 수정 동선과 목록의 펼침 동작은 유지한다.

- 상세 바텀시트 전체 높이는 현재 앱 창 높이의 최대 80%로 제한한다(`LayoutTokens.DetailSheetMaxHeightFraction`). `TimeDetailSheet`의 표면에 상한을 적용해 드래그 핸들도 포함하고, 긴 내용·큰 글자는 기존 내부 세로 스크롤로 확인한다. 내용이 짧으면 자연 높이를 사용한다. 오늘/달/년·대표 구간·목록의 개인 일정에 공통 적용하며 회전·분할 화면에서는 현재 창 크기로 다시 계산한다.
- 명시적으로 상세를 열면 활성 상태의 대표 숫자를 전체 길이에서 현재 남은 길이로 `Motion.DetailEntranceMs`(1200ms) 동안 한 번 전환한다. 실제 월/년 길이를 사용한다. 연출값은 저장·정렬·알림·이야기 선택·실제 눈금에 전달하지 않으며, 실제값은 보조 문구와 접근성에 계속 제공한다.
- 2026-09-23 후속 보정: `RemainingTimeEntrance`가 시작/목표 차이에 맞춰 감속한다. 날짜는 앞 40%에 목표+6까지 접근하고 마지막 60%에 최대 6개 정수를 하나씩 내린다. 마지막 구간은 제곱 감속과 올림으로 숫자 사이 간격을 점점 늘리고, 최종값은 종료 시 도달한다. 차이가 6 이하라면 전체 시간을 그 단계들에 배분한다. 최대 6단계와 시간 배분은 `Motion`에서 관리하며, 접근 구간의 곡선은 기존 `DetailEntranceEasing`을 쓴다.
- 오늘/시간 구간은 같은 타임라인에서 시·분·초의 표시 단계에 위 보정을 적용한 뒤 하나의 유효한 총 초로 합쳐 `RemainingTimeText`에 전달한다. 분·초의 빠른 반복 순환을 줄이고 각 단위가 목표로 감소하게 한다. 필요한 경우 첫 15% 안에서 `1:00:00 → 0:59:59`처럼 원래 최대값 이하로 단위를 빌린다. 모든 중간 조합은 목표 이상·최대 이하이며 24시간 59분 같은 범위 밖 숫자를 만들지 않는다. 계획은 초 틱마다 다시 만들지 않고 최신 실제값의 차이만 반영해 종료 후 실제 카운트다운으로 연결한다.
- 상세의 시간 단위는 전체 구간의 가장 큰 단위를 유지한다. 예를 들어 1시간 구간은 `1시간 0분 00초 → 0시간 42분 00초`다. 단위 경계를 지나도 줄 구성이 튀지 않게 0인 상위 단위와 최대값의 숫자 자리 폭을 유지한다. 날짜 상세의 세 자리→두 자리도 같은 글자 역할을 유지한다. 홈·목록·위젯의 기존 단위 생략 규칙은 그대로 쓴다.
- 초 틱·일반 재구성·회전·복귀는 최대값 연출을 다시 시작하지 않는다. 실제 원본 기간/대상이 바뀌면 별도 상세 상태로 취급한다. 시작 전·종료·0·유효하지 않은 범위에서는 연출하지 않는다. 시스템 애니메이션 배율 0이면 곧바로 실제값을 표시한다.
- 활성 상세의 눈금은 48dp 터치 영역 안에 기존 28dp 도형을 둔다. 탭·가로 드래그·가로 휠로 선택한 시각/날짜를 탐색선과 **‘미리보기’**로 표시한다. 실제 큰 숫자·경과율·남은 색·글로우는 현재 기준으로 유지한다. 세로 스크롤은 시트/페이지에 전달한다. 손을 떼도 선택을 유지하고 **‘현재로 돌아가기’**로 해제한다.
- 탐색의 기본 간격은 시간 1분, 1분 미만 구간 1초, 날짜 1일이다. 끝이 분 경계가 아니어도 마지막 초에 도달한다. 달/년의 첫날 포함 경과율과 오늘 제외 남은 일수, 오늘의 23:59:59 끝, 날짜 일정의 날짜 차이 기준을 유지한다. 원본 `TimeDetailRange`를 전달하며 번역된 날짜/시간 문자열을 역파싱하지 않는다.
- 현재 위치의 자석 반응은 `TimeRulerTokens`의 6dp 이내·전체 폭 2% 이내다. 조작 중 주변 28dp 눈금이 최대 4dp 솟았다가 돌아온다. 햅틱은 날짜 1일·길이에 따른 1/5/15분 등의 구간과 현재 위치에서만, 최소 120ms 간격으로 제공하며 시스템 설정을 따른다. 탭/버튼에도 짧은 같은 피드백을 재사용한다. 상시 진동/눈금 반복 움직임은 없다.
- 키보드 좌우·Home/End·Escape와 접근성의 이전/다음/현재 복귀·진행 조절 동작을 제공한다. 시간 숫자의 **‘초로 보기’**는 같은 값을 총 초로 표시하며 **‘시·분·초로 보기’**로 돌아온다. 일수를 자유시간으로 환산하지 않는다.
- 이야기의 버튼 전환과 본문 가로 스와이프에 `Motion.StoryChangeMs`(180ms)와 `Spacing.s`(8dp) 이동/페이드를 사용한다. 본문을 48dp 이상 넘기면 이전/다음 이야기로 순환한다. 후보·선택은 초 틱/회전에서 유지하며 출처와 접근성 설명은 선택된 이야기 하나를 따른다. 시스템 애니메이션 비활성화 시 즉시 전환한다.
- 설치 위젯은 기존 탭으로 앱 상세를 연다. 런처 위젯 자체에 가로 탐색·매 프레임 애니메이션·새 백그라운드 갱신을 추가하지 않는다.

코드 적용 상태이며 실제 동작·시각·촉각 검수 전이다. [상세 검수 대기](QA_INTERACTIONS_2026-09-23.md)를 따른다.

## 시간 피드백 후속 기준 (2026-09-21)

- 글로우는 남은 눈금 뒤의 기존 28dp 영역에만 표시한다. 세로 중앙 농도는 현재 `TimeRulerTokens`의 밝게 10%·어둡게 20%를 따른다(초기 18%·26% 기록 이후 조정된 기존 코드값이며 이번 인터랙션 변경에서 강도를 바꾸지 않았다). **남은 구간의 시작부터 끝까지 가로 밝기를 일정하게 채운다.** 남은 폭이 짧아져도 양 끝의 빛을 줄이거나 중앙만 밝히지 않는다. 위아래 방향에만 완만한 곡선 감쇠를 적용해 상하 경계에서 완전히 투명해지도록 한다. 숫자·화면 전체로 확장하거나 별도 카드 그림자로 쓰지 않는다. 앱과 위젯은 같은 Canvas 그리기 함수와 `TimeRulerTokens`를 사용한다.
- 시작 전·종료·잘못된 범위에는 활성 글로우를 표시하지 않는다. 진행 숨김이면 빛도 숨긴다. 깜빡임이나 호흡 효과는 없다. 최종 농도는 실화면 검수 전이다.
- ‘이만큼의 시간’은 출처가 확인된 과거 사건을 한 번에 하나 보여준다. 활동 권유·성과 약속·반복 횟수 환산은 사용하지 않는다. 제목 → 비슷한 길이임을 알리는 소요 시간 → 한두 문장 이야기 → ‘다른 이야기 보기’와 기관명이 있는 ‘출처 보기’ 순서이며 별도 카드나 그림을 추가하지 않는다. 버튼은 48dp 터치 영역과 baseline을 유지하고 좁은 폭·큰 글자에서는 다음 줄로 넘긴다.
- `TimeStoriesSection`과 로컬 한/영 문구·검증된 출처를 공통 상세에서 공유한다. 상세를 열 때 남은 길이의 0.5–2배 안에 있는 사건을 상대적으로 가까운 순서로 연결한다. 실제 사건의 길이를 명시하며 남은 시간과 정확히 같다고 표현하지 않는다. 후보·선택은 읽는 동안과 화면 회전 시 유지하고 버튼 또는 2026-09-23 승인한 본문 가로 스와이프로 넘긴다. 시작 대기는 시작까지의 길이에 연결하고, 남은 길이가 없거나 비슷한 사례가 없으면 구역을 숨긴다. 상태·기간이 바뀌거나 상세를 다시 열면 다시 선택한다. 자동 외부 요청은 없고 ‘출처 보기’를 누르면 해당 자료를 외부 앱으로 연다. [사례·출처·편집 기준](TIME_STORIES.md)을 따른다.
- 일수는 과거 사건의 길이를 비교하는 데만 사용하며 자유시간 N×24시간이나 가능한 작업량으로 바꾸지 않는다. 경과 시간은 반올림된 퍼센트에서 역산하지 않는다.
- 단일 오늘/시간 위젯은 제목 아래에 날짜·시간 기준을 표시하고 새로고침의 접근성 설명에도 제공한다. 기존 48dp 헤더 높이 안에서 우선 배치하되 실제 글자 높이 측정에 포함한다. 단일 4×2·요약 4×1 및 시작/종료 라벨 기준을 유지한다. 기간 요약에 새 줄을 추가하지 않는다.
- 위젯 숫자·눈금·글로우는 갱신 시점의 값이다. 시스템 초 카운트다운은 종료 후 음수 진행·눈금 동기화 검증 전이므로 활성화하지 않는다. 상시 서비스·정확한 알람 권한을 추가하지 않는다.

[적용 내용과 검증 대기 조건](QA_TIME_DETAIL_2026-09-21.md). 사용자 요청에 따라 새 빌드·Lint·테스트·실화면 검수는 아직 실행하지 않았다.

## 화면별 적용

- **홈:** 기간 요약, 대표 시간, 다음 구간을 위 기준으로 구성한다. 검색·정렬·추가 기능에 접근하는 경로를 함께 완성한다.
- **전체 일정:** 제목·개수/보기 전환 → 검색 → 정렬 → 일정 목록 순서를 유지한다. 보기 전환 줄과 검색은 24dp, 검색과 정렬은 16dp, 정렬과 목록은 24dp로 띄운다. 보기 전환 버튼 사이는 8dp이며 좁은 폭에서는 버튼 묶음을 다음 줄로 옮긴다. 검색과 일정 제목 입력은 `TimeLeftUnderlineTextField`의 투명 배경·밑줄 표현을 공유한다. 공유 일정 행의 상세는 위쪽을 기준으로 펼침 220ms·접힘 180ms의 높이와 투투명도 전환을 사용한다. 제목·남은 시간은 그대로 두며 시스템 애니메이션 배율을 따른다. 홈 다음 구간에도 같은 규칙을 적용한다. [적용 기록과 미검증 조건](ALL_SCHEDULES_REFINEMENT.md).
- **입력:** 이름과 시작/종료 값을 먼저 보여준다. 색·아이콘·알림·반복은 접을 수 있는 보조 영역에 모은다. 시간과 날짜 일정의 실제 필드를 보존한다.
- **설정:** 홈과 같은 서체·여백·구분선을 사용한다. 설정별 카드와 색상 배지를 반복하지 않는다. 2026-09-23 사용자 승인으로 기본 정렬·만료 항목·날짜/시간 기본 알림은 현재값을 보여주는 드롭다운 행으로 통일한다. 정렬은 ‘홈 동작’에 함께 둔다. 항목명과 현재값은 첫 baseline을 맞추며, 행 전체(최소 48dp)를 누르면 같은 폭의 메뉴가 열리고 현재 선택은 체크와 접근성 선택 상태로 구별한다. 닫힘/열림을 안내하고 선택 시 닫는다. 가용 폭 300dp 미만 또는 글자 배율 1.2배 초과에서는 현재값을 이름 아래에 배치하고 문구를 자르거나 축소하지 않는다. 진행률 표시는 행 전체가 하나의 스위치 동작이다. 화면 모드 드롭다운과 색상 견본은 아래 테마 미리보기 화면에서 제공한다. 기존 옵션·저장 키·알림 동선을 보존하고 메뉴를 여닫는 것만으로 저장하지 않는다. [변경 기록과 검수 대기](QA_SETTINGS_2026-09-23.md)를 따른다.
- **테마 미리보기:** 설정의 화면 섹션에 디자인 이름·현재 모드/색상·실제 오늘의 남은 시간과 눈금 견본·‘미리보기 및 변경’을 표시한다. 전용 화면에서는 시스템/밝게/어둡게와 기존 6개 색상을 비교하고 앱/위젯 보기를 전환한다. 선택은 미리보기 영역에만 반영하며 하단 적용으로 모드·색상을 함께 저장하고 실제 위젯을 갱신한다. 취소·뒤로는 저장하지 않는다. 비교 중 시간은 진입 시점의 실제 데이터로 고정하고 이를 안내한다. 홈의 기간 요약·대표 시간·일정 행·빈 상태와 위젯의 실제 렌더러를 재사용하며 상세·편집·추가·삭제·새로고침 동작은 제공하지 않는다. 전체 화면을 축소하지 않고 가용 폭과 기기 글자 배율로 표시한다. 위젯은 기존 대표 크기 단일 320×200dp·요약 320×96dp를 사용하고 좁은 폭에는 가로 스크롤을 안내한다. `ThemeDefinition`과 공통 해석기가 A의 색상·서체·모양을 묶으며 현재 선택 가능한 디자인은 A ‘시간 중심’ 하나다. 계절별 배경·서체·눈금·다른 레이아웃과 위젯 대응 표현은 실제 시안에 맞춰 후속 확장한다. [적용 범위와 검수 대기](QA_THEME_PREVIEW_2026-09-23.md)를 따른다.
- **위젯:** 단일 시간과 세 기간 요약 두 계열을 사용한다. 다섯 목적별 진입과 기존 provider·선택 설정은 유지한다. 단일 시간은 숫자와 상태 문구를 같은 텍스트 행에 배치한다. 숫자 30sp·단위 14sp·상태 문구 12sp를 사용하며, 폭 340dp·높이 260dp 이상에서는 숫자 56sp, 세 기간 요약은 숫자 22sp·단위 12sp다. 앱과 숫자·단위 그룹 및 눈금 치수 규칙을 공유한다. 2026-09-21 크기 축소 후속 승인에 따라 기본 배치는 **단일 시간 4×2칸·기간 요약 4×1칸**이다. 런처의 기본·최소 리사이즈 선언은 **단일 시간 250×110dp·기간 요약 250×40dp**다. 실제 콘텐츠 표시 하한 **단일 250×160dp·요약 250×64dp**와 분리한다. 180dp를 런처에도 선언하면 2행 지시에도 3행으로 잡힐 수 있으므로 실제 화면 하한을 셀 배치 힌트에 재사용하지 않는다. 이 값은 기본적인 공간 하한이며 모든 문구가 들어가는 보장은 아니다. 내용 측정으로 실제 표시 가능 여부를 추가 판단한다. 높이 200dp 미만 단일 위젯은 위아래 여백만 8dp로 줄이고 제목·숫자·보조 정보·눈금을 유지한다. 칸 크기는 런처에 따라 달라 실제 크기도 확인한다. 시간 행과 눈금 사이는 8dp, 눈금과 시작·종료 라벨 사이는 4dp다. 유효한 시작·종료 시각/날짜는 기본 배치에 포함해 높이를 계산하며 남는 공간에만 선택적으로 표시하지 않는다. 진행 중에는 ‘42분 남음’, 시작 전에는 ‘시작까지 42분’을 사용하고, D-day/D+ 형식에는 ‘남음’을 덧붙이지 않는다. 종료 정보가 범위 라벨에 있으면 별도 종료 문구를 생략하되, 눈금 숨김이나 라벨 부재 시에는 기존 종료 정보를 유지한다. 문자 길이에 따라 숫자를 줄이거나 눈금을 숨기지 않는다. 큰 글자·긴 제목·기존 혼합 요약이 들어가지 않으면 확대를 안내한다. 사용자의 눈금 숨김 설정은 따른다. 크기를 늘려도 단일 항목에 다른 기간을 자동 추가하지 않는다. 기간 요약은 중복 제목을 제거하고 세 항목을 가로로 표시한다. 숫자·단위와 기간명의 실제 폭에 따라 열을 배분하고 한 줄에 맞지 않을 때는 단위 그룹 사이에서 줄바꿈한다. 가로 배치가 들어가지 않고 높이가 충분하면 세로 행으로 전환한다. 기존 혼합 표시 설정은 보존하되 공간이 부족하면 확대를 안내한다. 누른 일정·기간의 상세로 직접 연결한다. [최신 구현·검증 대기 기록](QA_WIDGET_REDESIGN_2026-09-21.md).
- **위젯 설정:** 공통 상단바 → 선택 내용 요약 → 선택 일정/설명 → 실제 크기 미리보기(공간 하한 미만인 위젯은 권장 크기 예시와 확대 안내) → 필요한 표시 옵션 → 추가/변경 적용 순서다. ‘변경’으로 후보를 열고, 기간·일정 소제목을 사용한다. 직접 선택은 검색 가능한 전체 화면 목록에서 제목과 시간/날짜를 함께 보여준다. 큰 글자와 긴 목록을 위해 선택 화면 하나의 내용을 전환하며 팝업을 겹쳐 열지 않는다. 후보를 고르다 취소하면 원래 선택을 유지하고 실제 위젯은 적용 시에만 저장한다. 오늘·달·년·기간 요약에는 효과 없는 형식 옵션을 표시하지 않는다. 개인 일정은 실제 결과가 달라질 때 단위/시계·D-day 표현을 예시로 비교한다. 숨긴 옵션의 저장값은 유지한다. 크기 부족·조회 실패·삭제·빈 목록은 별도 상태로 안내한다.

### 아이콘과 앱 시작 (2026-09-21)

아이콘의 기존 흰색 심볼을 유지하고 배경을 고정 Clay 강조색 `#B5482D`로 쓴다. 적응형 아이콘·호환 이미지·스토어용 로컬 파일에 같은 브랜드 색을 적용한다. 아이콘 색을 앱의 사용자별 팔레트 설정과 연동하지 않는다.

스플래시는 앱의 밝게/어둡게 배경과 Clay 로고를 사용한다. 기존 브랜드 심볼의 정렬·투명도 전환은 360ms 이내 한 번으로 제한하고, 채워지는 진행률·반복 회전·과한 반동은 사용하지 않는다. 첫 앱 프레임이 준비되면 `Motion.MediumMs`의 200ms 전환으로 진입하며 로고만 8dp 이동한다. 전환 중 탭하면 즉시 진입하고 애니메이션 비활성화·화면 종료 시에는 바로 정리한다. 애니메이션 완료를 위해 앱을 기다리게 하지 않는다. XML 색상과 모션 값은 시스템 시작 화면이 Compose보다 먼저 표시되는 플랫폼 예외이며 기본 Clay 팔레트·Spacing·Motion 역할에 대응한다. [구현 및 검수 대기](QA_BRAND_LAUNCH_2026-09-21.md).

### 위젯의 플랫폼 예외와 공유 범위

`remainingTimeGroups`와 `TimeRulerTokens`를 앱·위젯에서 공유한다. XML/RemoteViews의 치수·서체 역할은 `res/values/widget_tokens.xml`에 Spacing 및 v2 값과 대응시킨다. 값은 sp로 시스템 글자 배율을 따르고, 1분 미만 같은 문장은 22sp 역할을 사용한다. 실제 값에 따른 임의 축소는 하지 않는다. 앱 Canvas와 위젯 비트맵은 모두 폭에 따른 20–60개 눈금, 2dp 굵기, 24/12dp 높이를 사용한다.

런처 배경은 Android 12 이상에서 시스템 위젯 모서리 반경, 이전 버전에서는 24dp를 사용한다. Android 15 이상 생성 미리보기는 실제 렌더러를 공유한다. Android 12–14 XML 및 이전 버전 PNG는 호환용이며 개인 일정 예시를 제품 데이터로 넣지 않는다. 크기를 받지 못한 경우와 정적 PNG의 대표 미리보기는 단일 320×200dp·요약 320×96dp이며 칸 수의 고정 환산값이 아니다. 최소 크기, 짧고 넓은 크기, 큰 크기를 생성 미리보기에 함께 제공한다. PNG는 네이티브 실행 화면과 구분한다. 설정 미리보기·설치 결과·런처 미리보기의 실제 일치는 최종 검수 대상이다.

일정 목록의 펼친 상세, 오늘·이번 달·올해 상세, 설치 위젯의 상세 화면에는 같은 ‘홈 화면에 위젯 추가’ 텍스트 버튼을 사용한다. 대표 숫자 옆에 상시 추가 행동을 반복하지 않는다. 새 위젯은 현재 보는 대상을 남은 시간 형식으로 고정하며, 자동 선택 위젯에서 들어온 상세도 보던 일정 ID를 고정한다. 런처 확인에서 추가가 완료된 후에만 설정을 저장한다. 추가 미지원 시 홈 화면에서 직접 고르는 방법을 안내한다. Android 12 이상 추가·생성 미리보기에는 여러 크기의 실제 렌더링을 전달해 설치 후 글자 위계가 갑자기 바뀌는 것을 줄인다.

기간 상세 시트와 위젯 상세에서 단독 행으로 놓인 ‘홈 화면에 위젯 추가’는 가로 내부 여백을 없애 본문과 같은 시작선에 글자를 맞춘다. 세로 내부 여백은 `Spacing.s`, 최소 터치 높이는 `LayoutTokens.MinTouchTarget`을 사용한다. 일정 목록의 여러 행동을 함께 둔 행은 기존 버튼 내부 여백을 유지한다.

숫자 정밀 갱신과 상태 전환의 검증 전까지 수동 새로고침을 유지한다. 시간대·시각 변경 등의 갱신 계기를 제공하되 실시간 시계 동작으로 표시하거나 설명하지 않는다.

## 검수와 AI 작업 기준

1. 작업 전에 이 문서를 읽고 변경할 사용자 경험과 재사용할 역할을 한 문장씩 적는다.
2. 실제 화면을 재사용하는 debug 갤러리에서 같은 데이터로 전후를 비교한다.
3. 밝게/어둡게, 기본/기존 5개 팔레트, 320dp, 글자 1.5배 이상, 긴 한/영 제목을 확인한다.

5. 단위·눈금·TalkBack 설명이 같은 시간 의미를 전달하는지 확인한다. 위젯은 크기별로 따로 확인한다.
6. UI 변경에는 시각 검수와 기존 동선을 확인한다. 빌드·Lint·단위 테스트는 수정사항 반영 후 사용자가 명시적으로 요청한 최종 검증에서만 실행한다. 계산·선택 로직이 달라진 부분의 검증 범위는 기록해 둔다.
7. 검수한 환경·전후 이미지·미검증 조건을 기록한다. 새 규칙은 이 문서와 공통 구현을 함께 바꾼다.

## Android 적용에서 정한 세부 규칙

- 새 기본 팔레트 키는 `clay`다. 기존에 저장된 5개 팔레트 선택은 그대로 읽는다.
- 320dp 또는 큰 글자에서는 격자를 한 열로 표시하되 저장된 보기 선택을 덮어쓰지 않는다.
- 글자 1.5배 초과에서는 큰 숫자의 단위를 아래로 배치한다. 상단 기간 요약은 세로 행으로 전환하고 값의 단위별 그룹을 줄바꿈한다.
- 달력 선택은 UTC 날짜를 기준으로 변환한다. 360dp 미만 또는 글자 1.3배 초과에서는 년·월·일 직접 입력을 사용한다. 시간 입력은 기기의 12/24시간 형식을 따르고 큰 글자에서는 시·분 필드를 세로로 배치한다.
- 위젯은 앱 테마와 팔레트를 공유한다. 단일 항목의 눈금·갱신 버튼은 높이와 글자 배율에 맞춰 조정한다. 크기에 따른 보조 기간 생략은 기존 표시 방식을 유지한 위젯에만 적용한다. 신규 기간 요약은 세 기간을 하나의 표시 항목으로 취급한다.
- 위젯의 기존 표시 옵션은 유지한다. 신규 위젯은 남은 시간 표현을 기본값으로 한다.
- 런처의 초기 용도는 새 위젯 설정에만 적용한다. 기존 네 provider 식별자와 저장 키는 유지하며 저장된 내용·옵션이 런처 이름보다 우선한다. 신규 ‘내 일정’ provider도 공통 갱신 경로를 사용한다. 런처 표시 순서와 실제 셀 크기는 호스트가 결정한다.
- 런처용 `widget_picker_*` XML과 구형 런처용 한국어/영어·밝게/어둡게 PNG는 A안의 기본 표면·서체 역할을 사용한다. 정적 그림에 실제 값처럼 보이는 예시 일정을 넣지 않고 값은 ‘—’로 둔다. 실제 값과 사용자 팔레트는 설정의 공유 RemoteViews 미리보기에서 확인한다. PNG 생성물은 런처 안내용이며 실행 화면 검수 증거가 아니다.
- 기간 요약 XML은 좌우 16dp·위아래 8dp 여백, 기간명 12sp·값 22sp·단위 12sp를 사용하며 공통 제목은 두지 않는다. 열/행 사이 8dp, 이름과 값 사이 4dp는 v2 간격을 RemoteViews에 옮긴 값이다. 가로 열은 숫자·단위 묶음을 보존하는 최소 폭과 한 줄 표시 폭을 측정해 배분하며 각 항목의 터치 영역은 가로·세로 최소 48dp다. 내용 측정 코드도 이 치수를 사용하며 함께 수정한다. 런처가 제공한 크기·현재 글자 배율·문구의 실제 측정 높이로 표시 가능성을 판단한다. 위젯 종류별로 색·글꼴을 따로 만들지 않는다.
- 시작 시각부터 종료 직전까지 진행 중이다. 같은 날 구간 종료 후에는 다음 날 시작까지 남은 시간을 표시한다. 자정을 넘는 새 구간 기능은 추가하지 않는다.
