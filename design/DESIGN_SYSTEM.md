# LeftMyTime 디자인 기준 v2 — A안 · 시간 중심

확정일: 2026-09-18. 사용자가 A/B/C 시안을 비교한 뒤 **“A안으로 확정”**이라고 선택했다.
상태: **A안 앱 구현 완료 / 에뮬레이터 검수 기록 별도 관리**. 이후 UI 작업은 이 문서를 기준으로 한다.

기존 구현과 검수 환경은 [v1 기록](DESIGN_SYSTEM_V1.md), 비교 과정은 [개편안과 결정 기록](REDESIGN_PROPOSAL.md)에 보관한다.
v1의 둥근 글꼴·카드·진행 링 유지 규칙보다 이 문서가 우선한다. 1차 구현은 [v2 검수 기록](QA_V2_2026-09-18.md), 상단 기간 요약은 [후속 검수 기록](QA_FLOW_2026-09-18.md), 현재 상세 진입 방식은 [안내 보완 기록](QA_PERIOD_HINT_2026-09-18.md)에서 실제 확인 범위를 관리한다.

## 제품의 중심

**지금 하는 일과 하루·달·년에 얼마나 남았는지, 열자마자 읽을 수 있는 조용한 시간 도구.**

사용자가 확인한 주요 용도는 업무·공부 등 짧은 시간 구간과 하루·한 달·1년의 남은 시간이다.
두 용도를 모두 홈에 둔다. 짧은 구간만 강조해 하루·달·년을 설정 속으로 옮기지 않는다.
기존 시작/종료 시각 모델과 날짜 일정 기능을 유지한다.

## 확정한 시각 언어

- **큰 남은 시간 숫자 + 얇은 시간 눈금**을 대표 형태로 쓴다.
- 중립적인 산세리프 글꼴, 따뜻한 회백색 바탕, 짙은 먹색 글자, 절제한 주황 강조색을 기본으로 한다.
- 대표 숫자는 한 화면에 하나만 가장 크게 둔다. 제목·종료 시각·단위는 이를 보조한다.
- 목록은 간격과 구분선으로 묶는다. 모든 내용을 둥근 카드로 감싸거나 각 행에 진행 링을 반복하지 않는다.
- 색은 현재 위치·남은 눈금·선택을 구별할 때 쓴다. 주요 숫자와 제목은 기본 글자색으로 읽히게 한다.
- 장식용 그라데이션·그림자·배지·진입 시 0부터 채워지는 애니메이션은 추가하지 않는다.

B의 세리프 숫자와 C의 계기판 서체를 화면별 취향에 따라 혼합하지 않는다. 새로운 디자인 결정은 이 문서에 먼저 반영한다.

## 홈의 정보 순서

1. 앱 이름과 설정 진입.
2. 상단의 남은 시간 요약: 오늘 / 이번 달 / 올해를 작은 숫자로 함께 표시. 같은 화면 바탕과 얇은 구분선을 사용한다.
3. 진행 중인 구간: 상태·종료 시각 → 일정 제목 → 큰 남은 시간 → 시작/현재/종료 눈금.
4. 다음 구간: 제목, 시작/종료 시각, **시작까지** 남은 시간. 구간 추가 행동을 같은 영역에 둔다.
5. 전체 일정 관리: 날짜 일정, 검색, 정렬, 기존 보기 방식에 접근할 수 있는 보조 동선.

대표 구간을 바로 아래 목록에서 같은 강조도로 반복하지 않는다. 전체 일정 관리에서는 해당 일정을 계속 찾고 수정할 수 있어야 한다.
검색·정렬을 보조 동선으로 옮기더라도 기존 기능과 사용자 설정을 없애지 않는다. 전체 일정은 홈 상단에서만 연다. 다음 구간 아래의 ‘전체 일정 N개 보기’는 중복 진입이므로 표시하지 않는다. 일정 개수는 기존 전체 일정 화면에서 확인한다. 좁은 화면·큰 글자는 상단 진입을 이름 있는 아이콘으로 바꾼다.

2026-09-18 후속 승인: 상단 요약은 개인 일정과 시각적 위계를 분리하기 위한 변경이다. 최상위 탭·회색 카드·고정 헤더를 추가하지 않는다. 공통 ‘자세히’ 버튼을 두지 않고 **‘각 기간을 누르면 자세히 볼 수 있어요’**라는 정적인 안내를 표시한다. 기간마다 반복되는 화살표는 산만하다는 사용자 피드백에 따라 표시하지 않는다. 이름과 숫자를 포함한 항목 전체를 누르면 **그 기간**의 큰 숫자와 눈금이 하단 상세로 열린다. 안내문은 별도 버튼이 아니다. 상세를 닫으면 홈의 스크롤 위치를 유지한다.

마지막으로 본 기간은 저장하거나 복원하지 않는다. 기존 `home_header_index` 값은 마이그레이션·삭제 없이 남겨 두지만 읽거나 쓰지 않는다. 화면 회전 중 열려 있는 상세를 유지하는 임시 UI 상태와 마지막 기간 설정은 구별한다.

세 기간의 숫자는 같은 `titleLarge`(22sp)·중립색을 사용하며, 요약에서는 제목 ‘남은 시간’이 공통 의미를 전달하므로 값마다 ‘남음’을 반복하지 않는다. 접근성 이름은 기간과 남은 길이를 함께 제공한다. 오늘은 두 단위가 필요해 가로 폭만 더 배분하며 숫자 크기·색의 우선순위는 동일하다. 가용 폭 300dp 미만 또는 글자 배율 1.2배 초과에서는 세로 행으로 배치한다. 글자나 기간을 숨기지 않는다.

상세는 `RemainingTimeText`와 `TimeRuler`를 재사용하며 진행 표시 숨김 설정을 따른다. 일수는 기존 계산대로 오늘을 제외한 날짜 수임을 설명한다. 하루 경계는 기존 계산의 00:00–23:59:59, 달·년은 실제 시작일/마지막 날을 표시하며 계산 로직은 변경하지 않는다. 다음 일정 시간 표기 축약과 날짜 일정의 홈 직접 노출은 이번 승인 범위에서 제외한다.

## 상태별 화면 기준

아래는 A안으로 구현할 때의 기본 설계다. 사용자 선택은 디자인 방향에 대한 것이며, 세부 동작은 실제 데이터·접근성 검증을 거친다.

| 상태 | 대표 영역 | 나머지 정보와 동작 |
| --- | --- | --- |
| 진행 중인 구간 1개 | 제목, 종료까지 남은 시간, 시간 눈금 | 하루·달·년과 다음 구간을 이어서 표시 |
| 진행 중인 구간 여러 개 | 종료가 가장 가까운 구간을 기본 표시. 동률이면 안정적인 ID 순서 | ‘진행 중 N개’로 다른 구간을 선택할 수 있게 하고 사용자 선택을 진행 중에는 유지 |
| 진행 중인 구간 없음 | 상단 세 기간 요약 크기 유지 | 다음 구간은 시작까지 남은 시간으로 구분 |
| 등록 일정 없음 | 오늘/이번 달/올해를 정상 표시 | 짧은 안내와 시간 구간 추가·날짜 일정 추가 행동 제공 |
| 날짜 일정만 있음 | 상단 세 기간 요약 크기 유지 | 날짜 일정은 내 일정에서 기존 남은 날짜·반복 정보를 유지 |
| 구간 종료 | 종료된 구간을 계속 진행 중으로 표시하지 않음 | 남은 진행 구간을 표시하거나 대표 구간을 제거. 상단 요약은 확대하지 않음. 종료 일정 표시 설정 유지 |
| 긴 제목·큰 글자 | 제목과 단위를 줄바꿈하고 영역 높이를 늘림 | 숫자·단위를 생략하거나 글꼴 배율을 무시해 맞추지 않음 |

`AdapterItem`에 일정 유형·진행 상태·남은 초/일·시작까지 초·시각 라벨을 명시적으로 전달한다.
표시 문자열, `percent == 0`, `remainingSortKey`만으로 시작 전/종료/진행 중을 추측하지 않는다.
대표 구간 선택 규칙은 외관 변경에 딸린 실제 동작 변경이므로 해당 분기 검증을 포함한다.

## 시간 표현

- 큰 숫자와 단위는 **남은 시간**이다. ‘42분 남음’, ‘15:00까지’, ‘시작까지’처럼 뜻을 직접 쓴다.
- 눈금의 지나간 부분은 중립색, 남은 부분은 강조색으로 표시한다. 시작·현재·종료 라벨로 색 이외의 단서를 준다.
- 내부의 기존 `percent`는 경과 비율로 유지한다. 남은 표현은 `1 - 경과 비율`로 파생하며 저장값의 의미를 뒤집지 않는다.
- 눈금 수는 화면 폭에 맞게 조정한다. 모든 구간에 눈금 1개가 1분이라는 의미를 부여하지 않는다.
- 현재 위치가 시작/종료 라벨과 겹치면 현재 시각을 별도 줄로 옮긴다. 의미 있는 숫자를 겹쳐 놓지 않는다.
- 대표 시간의 단위는 길이에 맞게 표시하고 숫자가 줄마다 흔들리지 않게 한다. 1분 미만의 진행 구간은 ‘1분 미만’으로 표시하고 완료와 구별한다.
- 초 표시는 모든 영역에 강제하지 않는다. 기존 표시 정밀도 옵션이 적용되는 영역은 호환성을 확인한다.
- 하루·달·년은 실제 달력 경계와 기기 시간대를 기준으로 계산한다. 월을 30일, 연을 365일로 고정하지 않는다.
- 시안의 14:18·42분·예시 일정은 검수 데이터다. 실제 화면에 기본 일정이나 계산값으로 하드코딩하지 않는다.

기존 사용자가 선택한 5개 테마와 일정별 색상은 유지한다. 새로운 기본 팔레트와 기존 설정 키의 이행 방식을 분리한다.
기존 팔레트도 동일한 배경·글자 위계·컴포넌트 구조를 공유하고 강조색 역할을 중심으로 매핑한다. 기존 사용자의 선택을 임의로 새 기본색으로 덮어쓰지 않는다.
오류·삭제 색은 강조색과 별도 역할로 정의한다. 선택·오류·종료 의미를 색으로만 전달하지 않는다.

## 글자·간격·형태

Android 구현은 `FontFamily.SansSerif`로 시작한다. 별도 폰트 다운로드 없이 한국어·영문·숫자의 균형을 실기기에서 검수한다.
나눔스퀘어라운드는 이전 구현 기준이며 v2 화면의 기본 서체로 혼합하지 않는다.

크기 값은 승인된 시각 방향을 Android로 옮기기 위한 시작값이다. 실제 글자 배율·한/영 표시·기기 폭에서 검수하며 조정하고 변경 근거를 남긴다.
숫자가 길어지면 단위별 그룹을 다음 줄로 배치한다. 홈 전체를 고정 높이로 만들지 않는다.
대화상자·입력 요소·홈 위젯의 모서리는 기능상 유지할 수 있다. ‘카드 없음’을 모든 표면의 직각화로 해석하지 않는다.

## 화면별 적용

- **홈:** 기간 요약, 대표 시간, 다음 구간을 위 기준으로 구성한다. 검색·정렬·추가 기능에 접근하는 경로를 함께 완성한다.
- **전체 일정:** 제목·개수/보기 전환 → 검색 → 정렬 → 일정 목록 순서를 유지한다. 보기 전환 줄과 검색은 24dp, 검색과 정렬은 16dp, 정렬과 목록은 24dp로 띄운다. 보기 전환 버튼 사이는 8dp이며 좁은 폭에서는 버튼 묶음을 다음 줄로 옮긴다. 검색과 일정 제목 입력은 `TimeLeftUnderlineTextField`의 투명 배경·밑줄 표현을 공유한다. 공유 일정 행의 상세는 위쪽을 기준으로 펼침 220ms·접힘 180ms의 높이와 투명도 전환을 사용한다. 제목·남은 시간은 그대로 두며 시스템 애니메이션 배율을 따른다. 홈 다음 구간에도 같은 규칙을 적용한다. [적용 기록과 미검증 조건](ALL_SCHEDULES_REFINEMENT.md).
- **입력:** 이름과 시작/종료 값을 먼저 보여준다. 색·아이콘·알림·반복은 접을 수 있는 보조 영역에 모은다. 시간과 날짜 일정의 실제 필드를 보존한다.
- **설정:** 홈과 같은 서체·여백·구분선을 사용한다. 설정별 카드와 색상 배지를 반복하지 않는다.
- **위젯:** 남은 숫자, 제목, 종료 시각을 우선한다. 작은 크기에서는 보조 눈금을 생략할 수 있다. 앱과 계산 의미·색 역할을 맞춘다.

## 공통 구현 위치와 이행 순서

아래 공통 구현을 사용한다. 새 화면에서도 같은 역할은 재사용하고 중복 구현을 만들지 않는다.

| 단계 | 대상 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 1 | `TimeLeftTheme.kt`, `LayoutTokens.kt`, `RemainingTimeText`, `TimeRuler` | A의 색·서체·숫자·눈금을 한 곳에 정의, 기준 화면으로 확인 | 구현 · 검수 기록 참조 |
| 2 | `HomeScreen.kt`, `HeaderSection.kt`, `NextCountdownHero.kt`, `TimeLeftItemCard.kt` | 상단 기간 요약·기간 상세·대표 영역·목록 통합. 진행 없음/겹침/긴 제목/기존 관리 동선 확인 | 구현 · 검수 기록 참조 |
| 3 | `ItemEditorScreen.kt`, `TimeLeftTopAppBar`, `SettingsScreen.kt` | 입력·설정도 같은 위계 사용. 기존 저장·알림·반복 설정 유지 | 구현 · 검수 기록 참조 |
| 4 | `AppWidget.kt`, 위젯 XML·설정 | 기존 설치 위젯 설정과 크기별 읽기 유지, 앱과 의미 일치 | 구현 · 검수 기록 참조 |

`TimeLeftCard`가 있다는 이유로 새 목록을 카드로 감싸지 않는다. 필요한 공통 텍스트·눈금·행을 먼저 만든다.
하나의 화면 안에서는 A의 대표 영역과 이전 스타일의 링·카드 목록을 혼합한 상태를 완료로 취급하지 않는다.
DB 스키마·기존 일정·반복·알림·위젯 ID·설정 키·출시 버전은 디자인 개편만을 이유로 변경하지 않는다.

## 검수와 AI 작업 기준

1. 작업 전에 이 문서를 읽고 변경할 사용자 경험과 재사용할 역할을 한 문장씩 적는다.
2. 실제 화면을 재사용하는 debug 갤러리에서 같은 데이터로 전후를 비교한다.
3. 밝게/어둡게, 기본/기존 5개 팔레트, 320dp, 글자 1.5배 이상, 긴 한/영 제목을 확인한다.
4. 진행 중/없음/겹침/빈 목록/날짜 일정/종료 상태와 기간 선택·추가·수정·설정 동선을 확인한다.
5. 단위·눈금·TalkBack 설명이 같은 시간 의미를 전달하는지 확인한다. 위젯은 크기별로 따로 확인한다.
6. UI 변경에는 시각 검수와 기존 동선을 확인한다. 빌드·Lint·단위 테스트는 수정사항 반영 후 사용자가 명시적으로 요청한 최종 검증에서만 실행한다. 계산·선택 로직이 달라진 부분의 검증 범위는 기록해 둔다.
7. 검수한 환경·전후 이미지·미검증 조건을 기록한다. 새 규칙은 이 문서와 공통 구현을 함께 바꾼다.

명시적으로 요청된 최종 코드 검증의 기본 명령은 `./gradlew testDebugUnitTest assembleDebug lintDebug`다. 요청 전 자동 실행하지 않으며, 문서만 바꾸는 작업에도 앱 빌드를 반복하지 않는다.
[기존 검수 기록](QA_2026-09-18.md)은 v1 결과다. A안은 [v2 검수 기록](QA_V2_2026-09-18.md)을 사용한다.

## Android 적용에서 정한 세부 규칙

- 새 기본 팔레트 키는 `clay`다. 기존에 저장된 5개 팔레트 선택은 그대로 읽는다.
- 320dp 또는 큰 글자에서는 격자를 한 열로 표시하되 저장된 보기 선택을 덮어쓰지 않는다.
- 글자 1.5배 초과에서는 큰 숫자의 단위를 아래로 배치한다. 상단 기간 요약은 세로 행으로 전환하고 값의 단위별 그룹을 줄바꿈한다.
- 달력 선택은 UTC 날짜를 기준으로 변환한다. 360dp 미만 또는 글자 1.3배 초과에서는 년·월·일 직접 입력을 사용한다. 시간 입력은 기기의 12/24시간 형식을 따르고 큰 글자에서는 시·분 필드를 세로로 배치한다.
- 위젯은 앱 테마와 팔레트를 공유한다. 실제 높이와 글자 배율에 맞춰 눈금·갱신 버튼·보조 기간을 생략하고 주요 시간부터 표시한다.
- 위젯의 기존 표시 옵션은 유지한다. 신규 위젯은 남은 시간 표현을 기본값으로 한다.
- 시작 시각부터 종료 직전까지 진행 중이다. 같은 날 구간 종료 후에는 다음 날 시작까지 남은 시간을 표시한다. 자정을 넘는 새 구간 기능은 추가하지 않는다.
