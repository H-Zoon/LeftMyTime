# 위젯 디자인·기능 개편 전략

작성일: 2026-09-21. 조사 기준: `0a6905f`의 소스와 Android 공식 문서.

상태: **후속 사용자 승인에 따라 디자인·최소 크기·상세 진입·상태 처리·앱에서 위젯 추가를 구현했다. 빌드·단위 테스트·Lint 통과 및 일부 에뮬레이터 검수를 완료했다. 정밀 갱신과 미검증 환경은 후속 범위다.** [적용 내용 및 남은 기능](QA_WIDGET_REDESIGN_2026-09-21.md)을 현재 상태로 따른다. 아래 비교와 전략은 조사 당시의 근거를 보존한다. 사용자가 불일치를 느끼는 범위는 홈 화면에 설치한 위젯과 위젯 추가 목록·미리보기 모두다. 기준은 [디자인 시스템 v2](DESIGN_SYSTEM.md)의 A안 ‘시간 중심’이다.

## 1. 제안의 중심

**위젯을 앱의 ‘남은 시간 표현’을 홈 화면으로 가져오는 작은 창으로 만든다.** 새 디자인 테마를 추가하기보다 앱·설치 위젯·설정 미리보기·런처 추가 목록에 같은 숫자 위계와 시간 눈금 규칙을 적용한다.

사용자가 고르는 오늘 / 이번 달 / 올해 / 기간 요약 / 내 일정은 유지한다. 구현·표현은 **단일 시간**과 **세 기간 요약** 두 계열로 정리한다. 크기는 정보의 배치를 바꾸며 선택한 기간이나 일정을 바꾸지 않는다.

## 2. 현재 불일치의 근거

아래는 코드에서 확인한 사실이다. 설치된 APK의 버전과 실제 화면은 이번 조사에서 확인하지 않았으므로 현재 기기의 모습과 같다고 단정하지 않는다.

| 영역 | 현재 코드 | 사용자에게 미치는 영향 | 개편 방향 |
| --- | --- | --- | --- |
| 숫자와 단위 | 앱 `RemainingTimeText`는 숫자·단위를 분리한다. 위젯 `renderBase`는 문자열 전체를 같은 크기로 표시한다. | 숫자가 주인공인 앱과 문장을 읽는 위젯의 인상이 다르다. | 동일한 숫자·단위 위계를 RemoteViews에 적용한다. |
| 작은 크기 | Compact 값이 7자 이상이면 22sp에서 16sp로 작아진다. | 남은 시간이나 언어에 따라 핵심 숫자의 크기가 바뀐다. | 글자 수에 따른 축소를 제거하고 단위 묶음 줄바꿈·배치 전환·최소 크기로 해결한다. |
| 크기별 배치 | 일반 위젯 숫자가 22/32/28/36sp로 나뉘며 넓은 형식은 숫자와 보조 문구가 가로 공간을 나눠 쓴다. | 크기별 디자인 규칙이 제각각이고 긴 값이 불리하다. | 작은형·기본형·가로형의 공통 정보 순서와 글자 역할을 정의한다. |
| 시간 눈금 | 앱은 폭·밀도에 맞는 Canvas, 위젯은 600×48 픽셀·60개 눈금을 늘려 표시한다. 높이에 따라 눈금을 숨긴다. | 눈금 간격·굵기가 달라지고 작은 설치 크기에서 A안의 특징이 사라진다. | 같은 눈금 치수 규칙을 사용해 실제 폭으로 생성한다. 표준 크기에는 눈금을 위한 공간을 우선 확보한다. |
| 색상·서체 | 글자·강조·트랙은 이미 `ThemePalette`를 참조하고 기본 산세리프를 사용한다. 배경 XML은 같은 색을 별도 선언한다. | 색상 전체가 다른 문제라기보다 타이포그래피·배치의 차이가 크다. | 현재 팔레트를 유지하고 중복된 배경 역할만 관리한다. |
| 추가 목록 | 별도 `widget_picker_*` XML·PNG가 ‘—’ 중심의 미리보기를 제공한다. 설정 안에서는 실제 위젯 렌더러를 쓴다. | 선택할 때 본 표현과 실제 배치 결과가 이어지지 않는다. | 지원 버전에서는 실제 렌더러로 생성하고 구형 미리보기도 같은 규칙으로 만든다. |
| 탭 동작 | 위젯의 공통 앱 실행 Intent에 표시 항목 정보가 없다. | 보고 있던 일정·기간의 상세로 바로 연결되지 않는다. | 위젯·기간·일정 식별자를 전달하여 해당 상세를 연다. |
| 설정 반영 | 위젯은 진행 표시 숨김 설정을 읽지 않고, 그 설정 변경도 위젯 갱신을 요청하지 않는다. | 앱에서 숨긴 눈금이 위젯에는 남을 수 있다. | 공통 표시 설정과 변경 후 갱신을 함께 적용한다. |

## 3. 디자인 개편안

후속 승인으로 작은형 지원 제안을 변경했다. 이후 크기 축소 승인으로 기본 배치는 단일 4×2·요약 4×1, 공간 하한은 단일 250×180dp·요약 250×64dp로 변경했다. 기존 250×200dp·250×240dp 및 공통 4×3은 초기 구현 이력이다. 하한 미만이거나 실제 내용이 들어가지 않으면 확대 안내를 표시한다. 아래 작은형 행은 검토 이력으로만 남긴다.

### 단일 시간 계열: 오늘·이번 달·올해·내 일정

정보 순서는 **대상 → 남은 숫자와 단위 → 상태·기준 시각 → 시간 눈금**으로 통일한다. 진행 중에는 ‘남음’, 시작 전에는 ‘시작까지’를 명시하고, 상태를 색이나 0%만으로 구별하지 않는다. 날짜 일정의 D-day 표시 선택도 유지한다.

| 배치 | 필수 정보 | 여유 공간에 추가할 정보 |
| --- | --- | --- |
| 작은형 | 대상, 읽을 수 있는 숫자·단위, 시작 전 등 필요한 상태 | 짧은 눈금. 시간 범위 라벨은 생략 가능 |
| 기본형 | 대상, 큰 숫자·작은 단위, 상태, 얇은 눈금 | 종료 시각·날짜, 시작/종료 라벨 |
| 가로형 | 대상과 남은 시간의 명확한 두 영역, 상태 | 아래쪽의 짧은 눈금과 기준 시각. 긴 문구는 다음 줄로 이동 |
| 큰형 | 기본형과 동일한 대상·위계 | 해당 일정의 시간 범위·반복 등 관련 맥락만 추가 |

- 숫자는 중립색·regular·고정폭 숫자, 단위와 보조 문구는 muted 역할을 사용한다. 기존 22/30/56sp 역할을 출발점으로 실측하며, 56sp나 앱의 96sp를 모든 위젯에 강제하지 않는다.
- 숫자와 단위는 묶음으로 줄바꿈한다. 큰 글자에서는 줄 수와 배치를 먼저 바꾸고, 물리적 공간이 부족하면 크기 안내를 제공한다. 잘림·임의 축소로 해결하지 않는다.
- 눈금은 지난 부분 중립색·남은 부분 강조색을 유지한다. 폭에 따른 눈금 수·dp 기준 굵기·큰/작은 눈금 비율을 앱과 공유한다. 짧은 구간만 초 단위로 촘촘해 보이는 등 의미를 바꾸지 않는다.
- 위젯 바깥의 둥근 표면은 런처 위에 읽히기 위해 유지한다. Android 12 이상에서는 시스템 위젯 모서리 규칙을 따르고 하위 버전 예외를 기록한다. 내부에 카드·그림자·배지·화살표를 반복하지 않는다. [Android의 위젯 모서리 지침](https://developer.android.com/develop/ui/compose/glance/create-app-widget#rounded-corners)
- 새로고침 버튼은 숫자보다 강조하지 않는다. **갱신 개선을 확인하기 전 제거하지 않는다.** 갱신 개선 후에는 정상 상태에서 제외하고 오류 상태의 ‘다시 시도’와 설정에서 수동 갱신을 제공하는 안을 권장한다.

### 세 기간 요약 계열

앱 상단과 같은 ‘오늘 / 이번 달 / 올해’ 및 같은 숫자·단위 위계를 사용한다. 세 항목은 같은 강조도이며 각 영역을 누르면 그 기간 상세로 이동한다. 반복 화살표와 공통 상세 버튼은 추가하지 않는다.

가로 공간이 충분하면 세 열, 부족하면 세 행으로 바꾼다. 이미 구현한 ‘세 항목 유지 → 세로 배치 → 확대 안내’ 원칙을 이어간다. 새 기본 배치 크기는 세 항목이 읽히는 크기로 검증하며, 기존 설치 크기를 강제로 변경하지 않는다. 요약에 큰 눈금 세 개를 추가해 복잡하게 만들지 않는다.

### 추가 목록·설정 미리보기

- 다섯 목적 이름은 유지하고, 같은 형태 안에서 제목과 표시 내용의 차이로 구별한다. 크기명 중심의 선택 방식으로 되돌리지 않는다.
- 설정의 실제 렌더러 공유 구조를 유지한다. 선택 결과와 크기·큰 글자 조건을 미리보기에서 확인할 수 있게 한다.
- Android 15 이상: 실제 렌더러로 생성한 RemoteViews 미리보기 적용을 우선한다. Android 12–14: `previewLayout`, 그 이전 및 fallback: `previewImage`에 같은 표현 규칙을 적용한다. 미리보기 생성 API에는 호출 제한이 있으므로 매초 갱신하지 않는다. [Android 미리보기 지침](https://developer.android.com/develop/ui/views/appwidgets/previews)
- 오늘·달·년은 실제 달력 값을 사용할 수 있다. 개인 일정이 없는 상태는 ‘일정을 선택하세요’로 표현한다. 가짜 일정을 제품 기본값으로 넣지 않는다. 비교용 고정 예시는 debug에만 둔다.
- PNG를 별도 취향으로 다시 그리는 경로를 줄이고 실제 Android 렌더링에서 파생하는 생성 방식으로 정리한다. 언어·테마별 자원은 호환에 필요한 만큼 유지한다.
- 런처 자체의 목록 간격·카드 모양은 앱이 통제할 수 없으므로 제공하는 이름·설명·미리보기·기본 크기를 개편 범위로 삼는다.

## 4. 기능 개편 우선순위

### P0 — 남은 시간의 신뢰성

모든 provider의 `updatePeriodMillis`는 현재 1,800,000ms다. 일정 수정·설정·크기 변경 등의 갱신은 있지만, 이것만으로 업무·공부 구간의 시계가 계속 움직이지는 않는다. Android의 provider 주기 갱신은 30분보다 짧게 설정할 수 없으며, 실제 실행 시각도 보장하지 않는다. [Android 갱신 최적화](https://developer.android.com/develop/ui/views/appwidgets/advanced)

먼저 **시계 표시의 진행**과 **데이터·상태 재계산**을 분리해 설계한다.

1. 짧은 구간은 시스템 `Chronometer` 카운트다운 적용 가능성을 작은 기술 검증으로 확인한다. RemoteViews는 API 24부터 카운트다운 설정을 지원한다. 다만 기본 시계 형식과 현재 숫자·단위 형식의 일치, 0초 이후 표시, 시작 전/진행 중 전환은 별도 해결이 필요하다. 실시간 갱신 완료를 미리 약속하지 않는다. [RemoteViews API](https://developer.android.com/reference/android/widget/RemoteViews#setChronometerCountDown(int,%20boolean))
2. 일정 변경, 날짜 경계, 재부팅, 시간·시간대 변경, 반복 일정 전환을 갱신 계기로 검토한다. OS별 수신·실행 제약과 앱이 실행 중이지 않은 경우까지 확인한다.
3. 달·년의 일수와 오늘의 시·분 등 표시 정밀도에 맞게 갱신 정책을 나눈다. 상시 초 단위 백그라운드 작업이나 정확한 알람 권한을 외관 개선 때문에 추가하지 않는다. WorkManager도 분 단위 정밀 시계의 대체재로 취급하지 않는다.
4. 숫자가 호스트에서 움직여도 눈금·상태는 마지막 계산값일 수 있다. 이 불일치를 어떻게 제한하거나 표현할지 기술 검증의 통과 조건에 포함한다. 검증되지 않은 형식은 실시간으로 오해하게 제공하지 않는다.

### P1 — 누른 내용으로 이동

- 단일 기간 → 해당 기간 상세.
- 직접 선택 일정 → 해당 일정 상세.
- 자동 선택 → **화면에 표시했던 일정** 상세. 탭 시점에 새로 고른 다른 일정으로 바뀌지 않게 한다.
- 기간 요약 → 누른 기간 상세.
- 선택 일정 삭제 → 재선택 안내. 조회 실패 → 다시 시도. 일정 없음 → 일정 선택/추가 경로.

기존 앱 실행과 실행 중 앱의 `onNewIntent`를 함께 처리한다. 위젯 인스턴스·기간·일정별 PendingIntent가 서로 덮어쓰지 않게 구분하고, 오래된 식별자는 안전한 안내로 처리한다. 각 탭 영역은 최소 48dp와 명확한 접근성 이름을 확보한다.

### P1 — 상태·설정 일관성

- 앱의 테마·진행 표시 설정을 위젯에도 적용하고 변경 즉시 갱신한다. 위젯별 스타일 선택은 먼저 늘리지 않는다.
- 정상 / 시작 전 / 일정 없음 / 선택 일정 삭제 / 조회 실패를 구분한다. 오류를 정상적인 ‘0분’으로 표현하지 않는다.
- 자동 선택은 현재 진행 구간 우선 규칙을 유지한다. 모든 후보가 끝난 날짜 일정일 때 첫 일정을 반환하는 fallback은 ‘표시할 예정 일정 없음’으로 바꾸는 안을 제안한다. **이 부분은 디자인 수정과 구분되는 동작 변경**으로 별도 반영·검증한다. 사용자가 직접 선택한 지난 날짜의 D-day 표시와 일일 시간 구간의 다음 시작 의미는 유지한다.
- 앱 홈에서 임시로 고른 대표 일정과 위젯의 자동/직접 선택은 서로 다른 사용자 의도이므로 강제 동기화하지 않는다.

### P2 — 추가 동선 단축

상세 화면에서 ‘이 일정 위젯 추가’를 제공하는 pin 기능은 다음 단계다. 먼저 설치 결과·갱신·미리보기의 일치를 확보한다. 일시정지/재개 버튼은 현재의 시작·종료 시각 기반 모델과 다르므로 이번 개편에 섞지 않는다.

## 5. 장기 운영을 위한 구현 경계

- `TimeLeftTheme`/`ThemePalette`, `Spacing`/`LayoutTokens`, `RemainingTimeText`의 숫자·단위 규칙, `TimeRuler`의 눈금 규칙을 공통 기준으로 사용한다. RemoteViews에 Compose 함수를 직접 재사용하기보다 **표시 데이터·역할·치수 규칙**을 공유한다.
- `WidgetDisplayData`를 완성된 문장만 넘기는 구조에서 숫자·단위 묶음, 상태, 기준 시각, 표시 대상 식별자를 전달하는 구조로 확장하는 안을 검토한다. 계산 원본의 시간 의미와 경과 비율은 유지한다.
- Android 12 이상은 제공된 실제 크기 목록 또는 소수의 반응형 레이아웃을 사용하고, 구형/크기 목록 미제공 런처에는 fallback을 둔다. 최소 폭·최소 높이 조합만 실제 크기라고 가정하지 않는다. [Android 반응형 위젯 지침](https://developer.android.com/develop/ui/views/appwidgets/layouts)
- 설치 위젯·설정 미리보기·debug 갤러리의 공통 렌더러를 유지한다. 추가 목록도 가능한 플랫폼에서 같은 경로에 연결한다.
- Glance 전면 전환을 선행 조건으로 삼지 않는다. 현재 RemoteViews에서도 우선 문제를 해결할 수 있으며, 프레임워크 교체만으로 디자인이나 갱신 제약이 사라지지 않는다.
- 기존 provider 이름, 위젯 ID, 선택 일정, 설정 키, DB를 보존한다. 기존 `legacySummary`의 개인 일정+기간 혼합 표시는 호환용으로 유지하고 재설정에서 단일 시간/기간 요약으로 명시적으로 전환한다. 외관 변경만으로 기존 내용을 없애지 않는다.
- 승인 후 새 규칙은 디자인 문서와 실제 사용처를 함께 수정한다. 새 예외가 필요하면 이유·적용 범위·검증 조건을 기록한다.

## 6. 권장 작업 순서와 완료 기준

| 순서 | 작업 묶음 | 완료 기준 |
| --- | --- | --- |
| 1 | 두 계열의 숫자·단위·간격·눈금과 설정 반영 | 같은 일정·기간을 앱과 위젯에서 보면 같은 위계로 읽히고, 작은 크기에서 문자열 길이 때문에 숫자가 작아지지 않음 |
| 2 | 시간 갱신 기술 검증 및 상태 설계 | 짧은 구간의 진행·시작·종료·절전 중 동작을 확인하고, 지원 가능한 정밀도와 지연 한계를 문서화 |
| 3 | 항목별 상세 진입, 오류·자동 선택 경계 | 여러 위젯을 설치해도 누른 항목이 열리고 삭제·오류·후보 없음에서 복구 동선이 분명함 |
| 4 | 추가 목록·미리보기 일치, 기본 크기 조정 | 지원 Android 버전별 미리보기와 설치 결과의 서체·위계·배치가 같고 요약 기본 크기에서 세 항목이 읽힘 |
| 5 | 명시적으로 요청된 최종 검증 후 기준 확정 | 실제 화면과 기능 검증 결과를 기록한 뒤 v2 위젯 기준을 갱신 |

1과 4를 첫 시각 개편 범위로 묶고, 2는 초기에 가능성을 확인하되 기능 변경으로 별도 관리한다. 새로고침 제거는 2의 결과에 종속된다. 구현 중 빌드·Lint·단위 테스트를 자동 실행하지 않는다.

최종 검증 요청 시 포함할 조건:

- 밝게/어둡게, 기존 테마, 한국어/영어, 최소 크기·가로형·큰형, 글자 배율 1.0/1.3/2.0, 긴 제목·긴 값.
- 실제 홈 화면과 추가 목록, 설정 미리보기의 같은 표시 규칙. Android 11 이하 / 12–14 / 15 이상과 서로 다른 런처의 여백·크기·미리보기 지원.
- 오늘·월·년 경계, 시간대·시각 변경, 재부팅·절전, 구간 시작/종료·자정 넘김·반복, 설치 후 앱 미실행 상태.
- 여러 위젯의 독립 선택·탭 동작, 기존 네 provider 업데이트, `legacySummary` 보존, 저장/취소, 일정 삭제·조회 실패·후보 없음.
- 눈금 숨김 설정·접근성 읽기 순서·상태 의미·48dp 탭 영역. 움직이는 숫자와 눈금이 서로 다른 시점을 가리키는지 확인.
- 요청 후 `./gradlew testDebugUnitTest assembleDebug lintDebug`를 실행하고 기존 경고와 새 문제를 구분. 변경한 계산·상태·내비게이션 경계에 필요한 검증을 포함.

전략 수립 시에는 소스·리소스·공식 API 문서만 검토했다. 후속 구현 상태는 [최신 기록](QA_WIDGET_REDESIGN_2026-09-21.md)에 구분한다. 대화의 구조 시안은 실제 APK 화면이나 시각 QA 증거가 아니다. 새 빌드·Lint·단위 테스트·설치·런처 실행 검수는 수행하지 않았다.

2026-09-21 Galaxy 크기 보정: 연결된 기기의 설치 APK에도 `targetCellHeight=2`가 들어 있었지만 One UI Home은 내 일정 위젯을 4×3(375×323dp)으로 배치했다. 런처에 180dp를 선언한 설정을 보완해 배치용 높이는 단일 110dp·요약 40dp로 분리했다. 실제 콘텐츠 하한 180dp·64dp와 내용 측정은 유지한다. 최신 보정 APK의 빌드·설치·재배치 확인은 아직 수행하지 않았다. 기존 설치 위젯의 크기는 호스트가 보관하므로 새로 추가하거나 수동 리사이즈하여 확인한다.
