# 디데이 영상 앨범 구현 가이드

날짜 일정의 준비 과정과 당일 장면을 친구와 함께 모은다. 일정 상세의 **영상 앨범** 행에서 앨범을 만들거나 해당 일정의 앨범을 바로 연다. 초대받은 친구는 **전체 일정 → 영상 앨범 → 초대 코드로 참여**에서 코드를 입력한다. 참여한 앨범도 같은 목록에서 다시 연다.

## 화면과 동작

- 날짜 일정 상세의 앨범 행은 기존 남은 시간과 기간 정보 아래에 표시한다. 앨범 생성 전에는 D-day, 제목, 날짜와 친구에게 공유될 정보를 먼저 보여준다.
- 앨범은 **D-day와 일정 → 영상 추가·친구 초대 → 날짜별 타임라인** 순서다. 타임라인에는 썸네일, 내가 올렸는지 여부, 업로드 시각과 재생 동작을 표시한다. 내 영상의 옵션 메뉴에서 삭제할 수 있다.
- 초대 및 코드 입력, 영상 선택 후 미리보기와 업로드 확인은 각각 별도 하단 시트에서 진행한다. 초대 시트에서 코드를 발급한 뒤 시스템 공유 창을 열 수 있다.
- `TimeLeftTheme`, `TimeLeftTopAppBar`, `TimeLeftInlineButton`, `TimeLeftUnderlineTextField`와 현재 간격 토큰을 사용한다. 앨범 내용은 한 표면에서 읽고 날짜 경계만 얇은 선으로 표현한다.

## 첫 버전에서 선택한 범위

- **초대 코드**는 한 번 사용할 수 있고 24시간 후 만료된다. 소유자가 새 코드를 만들면 이전 코드가 대체된다. 전달받은 코드의 소지자가 먼저 사용할 수 있으므로 지인에게 직접 전달하는 파일럿을 기준으로 한다.
- **일정 연결**은 같은 기기의 일정 ID와 목표일을 조합한다. 같은 회차는 같은 앨범을 다시 열고, 목표일이 바뀌면 앱에서 새 앨범을 열 수 있다. 앨범이 생성된 때의 제목과 목표일은 스냅샷이다. 전체 일정의 앨범 목록에서 이전 앨범도 찾을 수 있다.
- **영상 선택**은 Android 사진 선택기를 사용한다. MP4, 최대 15초, 최대 6 MiB다. 길이는 기기에서 검사하고 형식의 MIME 및 용량 한도는 스토리지에서도 적용한다. 촬영은 기기의 카메라 앱에서 한다. 영상 타임라인의 D-day 표시는 업로드 시각을 보는 기기의 날짜로 변환해 계산한다.
- **시청**은 참여자 앱에서 Media3 ExoPlayer로 한다. 개별 영상과 연속 재생을 지원한다. 앱이 백그라운드로 가면 재생을 멈춘다. 재생 오류가 발생하면 앨범 새로고침으로 세션과 목록을 다시 받을 수 있다.
- **파일럿 배포**는 Debug 빌드에서만 설정할 수 있다. 익명 로그인 계정은 설치에 묶여 있으므로 앱 데이터 삭제·재설치 후에는 기존 회원 권한이 복구되지 않는다. 공개 출시 시에는 계정 복구, 앨범 탈퇴·멤버 제거·전체 삭제, 보관 정책, 트래픽 한도 및 개인정보처리방침을 먼저 정리한다.

## 구성

| 영역 | 사용 방식 |
| --- | --- |
| Android | 날짜 일정 상세 진입 행, 전체 일정의 앨범 목록, Android 사진 선택기, 날짜별 타임라인, Media3 MP4 재생목록 |
| Supabase Auth | 공유 앨범 화면 진입 시 익명 세션을 만들고 기기 내부에 세션 갱신 토큰 저장 |
| Postgres | 앨범·멤버십·초대 코드. 앨범 생성, 초대 발급, 일회용 코드 소비는 RPC에서 처리 |
| Storage | 비공개 `countdown-clips` 버킷. `앨범 UUID/업로더 UUID/영상 UUID.mp4` 경로와 RLS로 멤버의 조회·업로드, 업로더의 삭제를 허용 |
| 재생·파일 일관성 | 영상 목록은 스토리지 객체에서 조회한다. 별도 메타데이터 쓰기 없이 업로드 직후 목록에 반영할 수 있다. 플레이어는 복사 가능한 공개 주소 대신 멤버 세션 헤더로 인증된 Storage URL을 읽는다. |

## 파일럿 설정

1. Supabase 테스트 프로젝트의 SQL Editor 또는 해당 프로젝트에 연결한 CLI에서 [마이그레이션](../supabase/migrations/202611260001_shared_countdown_clips.sql)을 1회 적용한다.
2. Supabase Authentication에서 Anonymous Sign-Ins를 켠다. 이 설정은 테스트 프로젝트에 적용한다. 공개 운영에서는 CAPTCHA 등 가입 남용 방지를 설정한다.
3. Debug 빌드에 테스트 프로젝트의 URL과 **publishable key**를 넘긴다. 프로젝트 루트의 Git 제외 `local.properties`에 넣는다. `-P` 옵션 또는 사용자 Gradle 설정을 사용하면 해당 값이 우선한다.

   ```properties
   sharedClipsUrl=https://YOUR_PROJECT.supabase.co
   sharedClipsPublishableKey=sb_publishable_REPLACE_ME
   ```

4. 두 Android 기기에 같은 프로젝트 설정의 Debug 빌드를 설치한다. 첫 기기에서 **날짜 일정 상세 → 영상 앨범 → 앨범 만들기 → 친구 초대 → 초대 코드 발급**을 선택한다. 두 번째 기기는 **전체 일정 → 영상 앨범 → 초대 코드로 참여**에서 코드나 받은 메시지를 붙여넣는다. 기존 Firebase 설정은 앱의 다른 기능에 계속 쓰인다.

Supabase 무료 플랜은 현재 파일 저장 1GB를 포함한다. 비활성 프로젝트 일시 정지 조건과 전송량 한도를 파일럿 전에 확인한다. [Supabase 가격](https://supabase.com/pricing) · [익명 로그인](https://supabase.com/docs/guides/auth/auth-anonymous) · [Storage 접근 제어](https://supabase.com/docs/guides/storage/security/access-control)

## 검수 절차

1. 서로 다른 기기 A와 B에서 각각 2~5초 MP4를 올린다. 상대 기기에서 새로고침 후 두 영상을 개별 재생하고 이어 본다.
2. 초대 재사용, 만료, 코드 재발급을 확인한다. 미가입 기기 C의 앨범 조회·파일 조회·업로드를 시도해 차단을 확인한다. B가 A의 영상을 지울 수 없는지도 확인한다.
3. 크기·길이 초과 영상, 사진 선택 취소, 업로드 중 네트워크 단절 및 같은 영상의 재시도, 삭제 후 목록 갱신을 확인한다. 저장된 영상이 새 활동에 중복 등록되는지도 확인한다.
4. 앱 백그라운드 전환, 회전, 작은 화면, 큰 글자, 밝은/어두운 테마, 긴 일정 제목과 빈 앨범에서 확인한다. 같은 일정과 목표일로 다시 열 때 기존 앨범을 사용하는지 확인한다.

로컬 PostgreSQL(PGlite)에서 Supabase의 Auth·Storage 스키마를 모사해 마이그레이션 적용, 앨범 생성 재시도, 코드 재발급·재사용 제한, 미가입자의 조회·업로드 차단과 작성자만 삭제할 수 있는지 확인했다. Android와 실제 Supabase 검증 범위는 아래에 기록한다.


### 기준 브랜치와 화면 검수

`feature/shared-countdown-clips`의 기준인 `d316743`에 원래 작업 폴더의 6.9 변경 79개 경로를 기록했다. 홈·상세·설정·위젯을 이 기준으로 유지하며 앨범 변경은 그 위에 적용한다. SQL 마이그레이션은 이번 UI 변경에서 추가하지 않았다.

Debug 디자인 갤러리는 실제 앨범 화면을 사용한다. `album-directory-empty`, `album-create`, `album-empty`, `album-timeline`, `album-timeline-large`, `album-error`에서 다른 상태를 확인할 수 있다. 화면 캡처는 Git에서 제외되는 `design/qa-shared-countdown-clips/`에 저장한다.

- Android 16의 Galaxy A33에 Debug 6.9(26)를 덮어 설치했다. Android 에뮬레이터에서 기존 홈과 전체 일정, 날짜 상세, 앨범 생성/빈 상태, 초대 시트, 영상 선택 시트, 타임라인과 세로 영상 재생 화면을 확인했다. 어두운 모드, 320dp 폭, 1.5배 글자와 긴 제목을 함께 확인했다.
- 실제 Supabase 파일럿 프로젝트에서 에뮬레이터로 앨범을 생성하고 1개 QA MP4를 올려 Media3로 재생했다. 별도 익명 세션은 초대 전 앨범·클립 목록이 비었고 초대 후 MP4를 읽을 수 있었다. 코드 재사용은 HTTP 400으로 차단됐다. QA 클립은 앱에서 삭제했고 QA 앨범은 테스트 계정에 남아 있다.
- 화면 캡처에는 QA 데이터만 사용했다. 두 실제 기기에서 각자 업로드하는 상호 공유, Lint 및 Gradle 단위 테스트는 이번 확인 범위에 포함하지 않았다.
